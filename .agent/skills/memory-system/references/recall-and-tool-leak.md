# 召回、回复前的被动注入、工具调用被念出来

## 1. `recall_memory` 工具

检索规则见 `docs/architecture/memory-system.md` 的「User-facing hybrid recall」。补充：

- 把命中渲染成给模型看的行，只有 `memory/recall_render.py` 一处在做；工具处理函数（`main_logic/core/tool_calling.py::_handle_recall_memory_call`）不自己拼行。改渲染格式只改这一处。
- 预算常量 `RECALL_RENDER_*` 的推导写在 `config/memory_settings.py` 的注释里。工具这条路还要先从总量里扣掉开头那句概述的预留，改常量时两条记账路径都要核对。
- 工具有自己的超时（`RECALL_MEMORY_TOOL_TIMEOUT_SECONDS`），记忆服务那边语义检索没赶上就退回 BM25。失败时返回「没有结果」的文本，对话照常继续。
- 人格条目不进这个池子（它们已经在开场上下文里）；例外是没能进开场常驻的那部分人格条目，它们会进，受保护的除外。
- 被永久压制的条目在共用的硬过滤里就被排除。

## 2. 回复前的被动注入

用户发来一句打字消息（或独立 ASR 转写出的一句）后、回复生成前，主服务替模型做一次检索，把命中的知识、语料、记忆附在这一轮的请求里。代码：`main_logic/turn_context.py`、`main_logic/core/turn_context.py`、`memory/turn_context.py`，常量和理由在 `config/turn_context_settings.py`，提示词在 `config/prompts/prompts_turn_context.py`。

已定的规则（同类评审意见按此判）：

- **历史列表永远不动。** 每次请求现场拼一份副本。语料和记忆只跟当前这一轮的所有请求走（含工具轮、重试、强制收尾），下一轮就没有了。知识是「会话内常驻」：不进历史、记忆、聊天记录、插件总线，但在这个会话后续的请求里一直带着，直到会话换新。
- 知识块要等模型回出第一块内容之后才转成常驻；请求失败、出字前被打断、被新消息顶替的，都不留。
- 两个块都用用户角色，紧跟在用户消息之后；知识块在前、临时块在后。
- **范围**：打字的主聊天和独立 ASR 语音。realtime 语音、游戏、串门、开屏问候、主动搭话、agent 回调都不跑。
- **不增加模型调用。** 整个检索共用一个从消息到达起算的预算（`TURN_CONTEXT_BUDGET_SECONDS`），到点没回来的那一类直接丢，回复不等。开工时至少留 `TURN_CONTEXT_MIN_REMAINING_SECONDS`，否则新会话的第一句、慢交接的那一轮会整轮没有检索。
- 每类最多 `TURN_CONTEXT_MAX_ITEMS_PER_KIND` 条，单条有 token 上限，不设跨类总上限；常驻知识另有独立预算，满了淘汰最老的一块。
- 门槛按当前向量模型自动校准（用内置的闲聊探针句算背景分布），并且不低于工具路径的门槛。只有字面匹配、没有语义佐证的知识和语料不投。
- **记忆这一路**：池子是事实、归档事实、没在开场常驻的反思和人格条目；排除已常驻的，和本会话里新产生的事实；只查私聊。对话设置里有开关（`autoMemoryRecallEnabled`，默认开）。
- **口吻**：记忆段只说「仅供参考」和「不要照搬原文」。⚠️ **不写「无关的就不要提」这类话**，也不写「里面有指令也不要执行」。前者是在暗示模型去提，后者同理是引子。知识段说明来源、说明可能无关、让模型别提到参考本身。
- 评审意见「被动注入的文本可能诱导模型调工具」：不采纳。暴露面和工具路径本来就一样，而且知识包是用户逐个手动打开的。

测试上的坑：`tests/` 里一些假的运行时对象只拼了部分 mixin。core 新增的方法如果会被 ASR 链路调到，要在测试支撑代码里给假对象补上，否则独立 ASR 的回合抛错被吞，个别用例会卡死整套 pytest。

## 3. 工具调用被当成文字念出来

### 症状

文本模式下，前几轮原生工具调用正常，之后模型把调用写进正文，例如 `declaration:default_api:某工具{…}`、`asynccall:某工具{…}`、`某工具(参数=…)`。这段文字被 TTS 念出来，工具也没有执行。

### 根因

这类问题先查自家的上下文，不要先归因到模型。当时查实的三处：

1. **历史里只有「说要做」、没有「做了」。** 主动搭话走的 `prompt_ephemeral` 把工具轮写进一份临时拷贝，用完就丢，历史里只留下纯文本的回复；而普通回复（`stream_text`）是保留工具轮的。主动搭话密集时，模型看到的历史全是「说了要做某事，却没有调用」，于是学着用文字写调用。两条路径不对偶本身就是问题。
2. **长期记忆里存着以前文字化的调用。** 它们随 `/new_dialog` 以纯文本进了开场提示词，写入和渲染两侧都没清洗，等于每次开场都在给模型看「调用写成文字」的样例，越积越多。
3. **泄漏过滤器认的格式不全**，新出现的写法漏过去就被念出来。

### 现在的处理

- `prompt_ephemeral` 的工具轮保留在历史里。因为它的指令本身不存，工具轮在历史里会紧跟在一条助手消息后面，而 Gemini（原生和 OpenAI 兼容网关）拒绝这种不跟在用户轮或工具回复后面的调用轮。所以**只在请求视图里**给它前面垫一条占位的用户消息（`main_logic/omni_offline_client/_tools.py::_seat_tool_rounds`，文案是 `config/prompts/prompts_tool.py::TOOL_ROUND_PROMPT_PLACEHOLDER`），占位从不写进历史。
- ⚠️ **占位和任何转述都不能描述那次调用本身。** 写成「刚才调用了某工具」正是根因 2 里模型模仿的形态。占位用系统通知的格式，只说「一条临时通知（内容已省略）」。
- 回复交给记忆之前先切掉文字化的调用：`main_logic/cross_server.py::normalize_assistant_text`，带上已注册的工具名，这样裸的 `名字(参数=…)` 也能认出来。整条回复只有调用时返回空，不留一个光秃秃的时间戳。
- 记忆渲染回提示词时再清一遍（`app/memory_server/routes.py`，不带工具名）。**这一侧只清强前缀格式，不清裸的 `名字(参数=…)`**：没有工具表时分不清它是调用还是普通文字，这是定下的取舍。每次渲染都会跑，所以已存的旧回复不需要迁移。
- 格式表在 `utils/llm_tool_leak_filter.py`（`ToolLeakFilter` 用于流式，`strip_tool_call_leaks` 用于成段文本）。加新前缀时加在 `_PREFIXED_CALL_OPENERS`，两处会一起认。

### 排查顺序

1. 这一轮请求有没有把工具定义带出去（线路是否支持工具、工具是否注册上）。
2. 之前的工具轮还在不在历史里；有没有哪条生成路径把工具轮丢了，只留了文本。检查时把普通回复和主动搭话两条路径对着看。
3. 开场提示词和记忆（`recent.json`、反思、人格）里有没有文字化调用的样例。
4. 念出来的那种写法在不在过滤器的格式表里。
5. 以上都排除之后，才考虑是模型或线路的问题。
