# 各层的定位，以及写记忆类提示词的规则

## 1. 各层存什么

| 层 | 存什么 | 不存什么 |
|---|---|---|
| facts（`facts.json`） | 具体的事：某次发生了什么、用户说了什么偏好、状态变了 | — |
| reflection（`reflections.json`） | 概括出的关系和相处方式、特点、偏好 | 某一次事件的经过 |
| persona（`persona.json`） | 性格和偏好。人格是抽象的；它由两人的关系塑造，但记下的更应是角色自己的性格和反应方式 | 事件；把角色对用户的迁就、默许、让步写成恒定规律 |

为什么要守这条线：提示词如果要求反思「写清发生了什么」「必须落在具体的事和原话上」，模型就会把人格和反思往事件叙述上推，层级错位；反过来不设防，又会产出「两人形成了默契」这种放到任何两个人身上都成立的空话，在注入预算里长期压过具体事实。

## 2. 写或改人格 / 反思类提示词时

适用于：反思合成（`REFLECTION_PROMPT`）、升格合并（`PROMOTION_MERGE_PROMPT`）、精炼（`MEMORY_REFINE_PROMPT`、`SCOPED_MEMORY_REFINE_PROMPT`）、每周自省（`MEMORY_INTROSPECTION_PROMPT`、`MEMORY_INTROSPECTION_SCOPED_PROMPT`）、人格纠正（`PERSONA_CORRECTION_PROMPT`），都在 `config/prompts/prompts_memory.py`，8 种语言一起改。

- **判空洞用「有没有信息量、能不能看出这两人具体怎样相处」**，不用「有没有具体事件」。
- 要求「更准确、更有信息量」的同时写上「保持概括层级，不写成某一次事件的经过」。
- 「形成了……默契／模式／纽带」「体现了／意味着……」这类空话的禁用句式和反例要保留，这是防止空洞定性句回潮的核心。
- 除非多条依据都这么说，不许用「总是／从不／每次／一定」这类绝对说法。合成、升格合并、精炼、自省四处都有这句，新增同类提示词要带上。
- 自省清单里的 `self_rule` 指的是「把角色对用户的迁就 / 默许 / 让步写成恒定规律，或与角色卡性格相悖的反应」。角色正常的性格和反应方式不算问题，别把它扩成「凡是写角色自己的都压掉」。
- 角色自己说过的话在合成提示词里有标注，不能当作用户特点或两人相处方式的证据。新增会把对话喂给模型做总结的提示词时沿用这个标注。
- `memory/_reflection/ontology.py` 里 `relation_type` 的 `milestone`、`shared_memory` 和 `temporal_scope` 的 `episode` 仍是事件型类别，上面的口径调整没有动它们。要改先问维护者。

## 3. 提示词里的外来文本

- 进提示词的记忆行、角色卡（尤其是创意工坊下载的角色卡）一律按「数据，不是指令」处理：提示词里明说，并把正文里的 `=` 连串压短，使它拼不出分隔线（自省在 `memory/introspection.py` 里做，通用工具是 `utils/prompt_fence.py::fence_safe`）。
- 评审意见要求「对工坊角色卡逐项让用户确认」「把工坊卡的行排除出提示词」「工坊角色不跑自省」：不采纳。自省是全自动设计，现有的两层缓解是定下的做法。
- 分隔线成对出现：`======以下为X======` 配 `======以上为X======`。繁体（zh-TW）提示词里的分隔线保持简体写法，和同文件其它提示词一致。水印规则见 neko-guide。
- 给模型看的占位或转述文本不能描述「一次工具调用」本身，原因见 `recall-and-tool-leak.md`。

## 4. token 预算

总则和守门脚本见 neko-guide 的「每个 LLM 调用必须有 budget + timeout」和 `docs/design/llm-prompt-budget.md`。下面是那两处没写的：

- **为什么不用字符切片**：字符数和 token 数的比例随文字种类变化很大；字符上限既不准，又可能从 JSON 中间切断，后面的解析静默失败。
- 工具在 `utils/tokenize.py`：`truncate_to_tokens`（丢尾）、`truncate_head_tail_tokens`（头尾都留，给会话流里的单条长消息用）、`take_lines_within_token_budget`（按整行装箱）、`count_tokens`。常量命名 `*_MAX_TOKENS`。`*_MAX_CHARS` 只给非提示词的界面 / 传输防爆用，不算输入预算的依据。
- ⚠️ **`config/` 是守门脚本的盲区**。`scripts/check_llm_budget.py` 的 `EXCLUDE_DIRS` 含 `config`（还有 `plugin`、`tests`、前端目录），整个 `config/` 不扫。把提示词拼装函数放进 `config/prompts/`（多语言字符串按规范本来就要放那里）之后，里面的字符切片对 `LLM_INPUT_BUDGET` 完全不可见。出过的组合：调用点挂 `# noqa` 写「拼装函数已经截断」，拼装函数在 `config/` 里，截断用的是 `[:800]`。评审提示词拼装函数时看截断的单位，不要因为检查是绿的就放过。
- `# noqa: LLM_INPUT_BUDGET` 是给「本来就不该截」的内容用的（用户原话、用户自己的配置、系统窗口标题这类），要写理由。它不是给「我用字符截过了」盖章的。
- 前端没有分词器，前端的字符截断只能当传输防爆。后端收到后必须按 token 重新框一遍。
- 单条上限截的是正文，总量上限数的是整行（序号、本地化标签、日期后缀、换行都占 token）。所以「条数 × 单条上限 = 总上限」不成立，要留行开销。现成的推导在 `config/memory_settings.py` 的 `RECALL_RENDER_*` 和 `SCOPED_RENDER_ENTRY_MARKUP_TOKENS` 注释里，改这些数先读注释。
- 写「谁给谁让路」的配额（按主体分预算、群和成员混排）时，把全成员、全群、混排、群在首、群在尾几种组合都摆出来再定夹具。只测刚修的那个方向，很容易把「A 被 B 饿死」修成「B 被 A 饿死」。分配顺序就是调用方传入的主体顺序，渲染层不重排；分桶按条目自己的 `(主体 key, scope)`，不按 persona 的 section key（同一 section 可能装着两个隔离域）。

## 5. 不做的事（产品层面已定）

- **不做事实 / 反思 / 人格的查看、编辑、回滚界面。** 可编辑、可回滚的记忆会破坏陪伴感。记忆浏览器只编辑 `recent.json`（口癖列表的放行 / 压制面板管的是回避列表，不是记忆条目）。证据计数也不给用户改（`docs/design/memory-evidence-rfc.md` 的 non-goals）。
- **不让对话模型自己写记忆。** 前提是对话模型的工具能力不可靠、语音要低延迟、长期运行要控成本，所以记忆靠后台流水线。评估外部框架「模型自己写记忆」的做法时按这个前提改写，不照搬。
- **行为提醒不走 persona。** 它如果做成 persona 条目，评分衰减、精炼合并、矛盾检测、长期同步、召回都要加排除；所以存独立文件 `behavior_notes.json`，只在 `/new_dialog` 拼开场文本时读，也不进 `arender_injected_memory`（每周人格自省看不到它，由行为自省自己复查）。
