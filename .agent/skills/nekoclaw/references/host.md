# 宿主（`nekoclaw/host/`、`app/agent_server/`）里不显然的规矩

机制在设计稿 `docs/design/nekoclaw-rewrite.md` 第 5、6、10、12 节，落地出入在 6.9、6.10、12.5 节。下面是那里没有的，或者定过之后容易被改回去的。

## 主服务这一侧：每种轮次结束都要交代「这一轮经工具办过事没有」

主服务在一轮结束时告诉 agent 进程这一轮她有没有经工具办过事（`acted_through_tools`），办过的轮次不旁听。轮次结束的路径不止一条（正常结束、回调轮、镜像输出、记忆服务冷却、主动搭话、被打断），分散在 `main_logic/core/turn.py`、`streaming.py`、`proactive.py`。

- 新加一种轮次结束路径时：带上这个标记，并清掉这一轮记下的工具状态。
- 漏带的后果：她已经派发的事被旁听当成「答应了却没派」，再派一遍。漏清的后果：工具状态带进下一轮，下一轮该旁听的不旁听。
- `tests/unit/test_task_tools_main.py` 里有一条读源码的测试守着「每个放进队列的轮次结束都清状态」，新路径要能过它。

## 调插件

- `PluginRunner.run_entry` 这个方法不要改名叫 `invoke`。`scripts/check_llm_budget.py` 把任何 `.invoke(` / `.ainvoke(` 都当成模型调用来查预算，插件调用叫这个名字会被它拦。
- `plugin_runs.py` 的 `_reraise_swallowed_cancellation` 不是多余代码。任务取消有时被下层吞成普通异常、甚至完全吸收掉（测试里用进程内 ASGI 传输加中间件搭的假插件服务就会这样）。不重新抛出的话，轮询会继续盯着一个调用方已经不在的 Run，这个 Run 也永远不会被取消。
- 任务大脑直达插件入口和 task agent 经网关调插件，走的是同一段 `/runs` 代码（`run_entry`）。两条路的差别只在结果怎么处理（设计稿 6.2 节），不要为其中一条另写一套调用。

## task agent 启动失败时用户的话

`TaskAgentManager._keep_unsent`：这次启动要发、还没进会话记录的用户的话（之前保留的、这次的那句、准备期间补充的），只要失败发生在进记录之前（额度不够、启动抛异常、运行时报启动失败），就按先后放回，下一次启动排在最前面；已经发出 prompt 之后才出错的清掉，免得下次重复；被叫停、正在关的会话不放回。

「进程恰好在读到 prompt 和写进记录之间退出会丢话」是已知的窄窗口，不单独为它改协议（设计稿第 15 节「使魔额度的扣法要重构」下面）。这条路上再来的评审意见：改坏既有行为的、时序竞争的照常修；其余可选的只记进设计稿，不改代码。

## 查询和旁听里定过的评审意见

- 「让查询也等一次小模型粗筛」：不做。查询任何情况下都不调模型。本地没找到候选、task agent 又不可用时，查询回「没找到现成的能力，真要办可以派发试试」，不下「办不了」的结论（6.3 节）。
- 「她查完进度后说办好了，旁听对不上记录」：不按词面重合度收紧。试过，撤回了：门槛只能照个别真实样本定，换个说法就掉线，任务列得多时无关的声称又能碰巧过线。现行做法是软提醒随用户下一句带上（第 15 节「查过任务之后说办好了的处理」）。
- 精选答了不存在的插件或入口：不追问，直接交给 task agent（6.2 节）。追问拦不住「入口存在但选错了」这种真会出事的错。

## 使魔空间

布局和全部细节在设计稿 12.1、12.5 节。

**写保护加在宿主的权限回调上**（`TaskAgentManager._cb_permission`）：

- `write`、`edit` 往使魔空间里写一律拒绝，不管权限怎么设、工作目录在哪。
- 跑命令：命令里出现目录名 `task_agent_space`，或者命令的运行目录在使魔空间里，整条拒绝。命令自己把名字拼出来的（变量、通配符）认不出，这是写明了的边界，没有沙箱。
- ⚠️ 这层保护只管得到走这个回调的工具。以后接别的运行时，它自带的文件工具如果不走这个回调，要在它自己的权限配置里再做一遍。
- 清旧过程只认内置运行时的落盘（会话目录里的 `transcript.jsonl` 和 `outputs/`）。别的运行时落盘的名字不一样时，要在 `space_keeper.py` 里另加。

**看着像 bug、其实是有意的**（同类评审意见再来先对照，理由在 12.5 节）：

- 每件委托最多复盘一次，失败也不重试；「没办成」的先等 24 小时，其间被接着办完就在办完时复盘。
- 手写的条目（开头没有 `texts` 行）不补摘要：手写正文里哪几段各是一条经验说不清，只补一部分会让没补到的段落以后被重复加。同一条界线：手写的条目也不写依据、次数、状态（`evidence`、`seen`、`status`），它算生效、不会过期。
- 还没生效的经验（猜的只被一件委托交过、看到过却没有存在的依据）是「待定」条目：一个文件，开头标 `status: pending` 和一句怎样确认的话，不进任何索引。状态四种：生效、待定、过期、被用户删掉不再收（owner 2026-11-18 定的，原来三种）。每层最多 30 条、最多等 90 天，到期或被挤掉的直接删文件、不记进「不再收」；被用户在控制台删掉的照样记。用户手写的文件写了 `status: pending` 不认。一条经验生效时，同标题的待定条目只在「这条是核对过的」或「交它的委托以前没见过那个待定条目」时跟着生效；使魔核实以后用原标题按「核对过」再交一次就是这条路。
- 工作目录和项目工作目录之外的依据路径，只有用户把「读工作目录外的文件」设成一律允许（权限里 `outside_read` 是 `allow`）时宿主才去查它在不在；没设时不查：查了就等于替使魔绕过「读工作目录外要问」探到文件存不存在。条目记着哪些依据在外面（`evidence_outside`）；设置改回去以后这些算「判断不了」，条目不因此过期。
- 记下的依据是解析链接以后的真实路径；之后那个路径不再指向它自己（文件或上级目录被换成了链接）就算依据不在了，链接指向哪里不看。别改成「顺着链接看目标在不在」：那会变成探目录外文件存不存在的办法。
- 归档总结提炼的条目不算一次观察（不写 `seen_by`）：总结读的就是这个项目自己的委托。复盘的条目算它那件委托的一次。没写是谁看到的条目（手写的、控制台建的、归档总结建的）都算被看到过一次，别加「零次」这种情况。
- 仓库自带的 agent 文档（`repo_docs.py`）只列路径和大小，宿主不打开文件、不当指令载入。宿主自己给委托建的工作目录不往上找仓库根；写不下的路径不列、不截短。清单放在每件委托开头的那条消息里（`TaskAgentManager._opening`），不在系统提示里：系统提示是会话的快照，整个会话不变；同一个会话里的每件委托都带一份，因为压缩时原样留着的只有当前委托的开头消息。
- 复盘、归档总结的输出里每条经验有 `evidence` 一项（最多 2 个路径，每个最多 40 token）；宿主先看它，再看条目文字里认出来的路径（留作后备，模型不一定填）。输出上限比各项写满多两成多，别往回收。细节在设计稿 12.6 节。
- 可能不回来的文件系统查找（目录或文件在不应答的网络盘上）用 `nekoclaw/host/detached.py` 的 `run_detached`：单独的守护线程，调用方自己用 `asyncio.wait_for(asyncio.shield(...))` 定等多久，超时按「不知道」处理。别用 `asyncio.to_thread`：默认线程池的线程在进程退出时会被等待，一次挂住的查找就让宿主退不出去，还占着别的文件操作要用的线程。现在两处在用：仓库文档清单、整理里核对依据。它只把 `Exception` 交给等待方；`StopIteration`（future 不收）换成 `RuntimeError` 交付，被 `SystemExit` 之类结束时 future 也照样完成，所以「在途」的计数不会卡住。
- 写锁里不做可能不回来的文件系统查找：`_write` 里的活儿被取消也要等它做完才放锁，一次挂住就让使魔空间的所有写入排队。整理里核对依据的做法是「锁外看、锁里只比对快照」（`check_evidence` 和 `_set_standing`，快照里有条目文件的签名），别改回锁里再看一眼。使魔交经验、复盘存条目时，依据在拿锁之前看（`_evidence_before`）。实在要在锁里看的（看哪些文件得读了条目才知道），用 `_stood` 限时问（`_asked`，守护线程里问、最多等 2 秒）。没答复不等于不在了：记下来的依据用 `_recorded` 取，只去掉明确不在了的，没答复的留着、这一次不算数（`_Known.untold`）；别把没答复的从条目里删掉。没答复的询问按位置记（`_place_of`：盘符、共享或头两级目录），只挡它实际卡在的那个位置（一次询问看多个位置时要随时说自己在哪：`_asked_off_the_loop` 给 `look` 的那个参数）。交经验时锁外的询问按位置排队（`_evidence_before` 里每个位置一把 asyncio 锁，按排好的顺序拿，工作目录自己所在的位置也算），一个位置同时只有一个在问，轮到时那个位置已经不应答就不再问。同一个文件问了两次的以后一次为准，两个方向都是（`_judged` 里的 `gone` 和 `there_now`）。`gone` 只裁被问的那个待定条目的记录：正文并进别的条目时不带过去（`known if home is own else replace(known, gone=())`），目标条目自己的依据留给整理去看。`_fold(by_text=)` 和 `_keep_known(judged=True)`（待定条目在原处生效）里再问一次，替这条经验说过话的文件不在了或问不出来，也抛 `_Rewritten` 重判；只在这条经验单凭文件生效时才重判（`_judged` 里的 `by_files`），核对过的、被足够多委托交过的照常写。写的时候后一次确认不在的文件不写回去：在原处生效的由 `_keep_known` 的 `gone_now` 管；并进别的条目的，`_fold` 把复查结果放进 `told`，`_judged` 只从这条经验带给目标条目的新依据里去掉确认不在的，目标条目自己记着的不动（按正文认出来的那次并入和按标题带进来的那次都这样；按标题带进来、在原处生效的走 `_confirm(told=)`）。同一个文件以最后一次问到的为准，判定时不在、写入前又找到了或问不出来的留在记录里（`_keep_known` 的 `not_gone_now`）；只认成立的那次写入问到的（`at_write` 在每次尝试一开始就清空）。`_confirm` 也收 `by_files`，单凭文件生效的经验在这里同样会被重判。要知道某几个待定条目还在不在等，用 `TaskAgentSpace.still_pending(project, ids)`（逐个看文件：确认没了或已生效才不算，读不了的照算），别用 `list_entries` 的结果去推——它读不到的条目不等于不在等。「这个文件还替不替这条经验说话」只在 `_speaks_no_more` 一处判，各条生效的路都用它（`_file_entry` 里 `judged=by_files`，不只是凭正文在原处生效那一条）。`_Rewritten` 带着最后那次问到的结果（`told`：每个文件是在、不在还是问不出来；`of`：被问的是哪个条目），`_take_note` 把它交给第二次 `_judged(since=)`：这一次没有重新问到的文件照它算。写入前后问到的结果都放进一个字典（`_fold(told=)`、`_file_entry(told=)`、`_keep_known(told=)`；被放弃重做的写入不算）。「哪些文件算数」由 `_judged` 返回（`_Taken.spoke`、`_LineNotAdded.spoke`），`submit` 直接用它，不在轮到写时的结果上做加减。告诉使魔哪些文件没算数时用 `_shown`（太长从前面截），别用 `_cut`（从后面截，文件名会没掉）。锁外的询问按位置排队不限时：`SPACE_EVIDENCE_BEFORE_SECONDS` 只限看这一次。待定条目要凭它记下的依据并进别的条目或在原处生效时，写入前要比对依据还是判定时那几个（`_fold(by_text=)`、`_file_entry(must_say=)`），不一样就抛 `_Rewritten` 重判。开不了线程是 `detached.NoThread`，别用 `except RuntimeError` 接（会把探测自己抛的也吞掉）。
- 跨卷搬项目留下的 `.removing-` 开头的目录从不自动删：它是被挪开、还没核对完的源目录，里面可能有目标处没有的最新修改。只清 `.gone-` 和 `.unfinished-` 开头的。
- 文件替换成功、但一直读不回来（刚换上去的文件被别的程序占着）算写进去了，不报失败。
- `Commission.project` 只在开工时写，复盘不改写它：它决定会话目录在哪。
- 会话目录在记下的位置和当前数据根下都没有对话记录时，取台账记的位置，不改成「当前根下存在就用」（第 15 节「存储位置迁移」）。
- 宿主从不写 `AGENTS.md`（守则只有用户写）。
- 写进复盘和条目的文字都过 `space.redact()`，现在原样返回。要打码只改这一处，不要在调用点各自处理。
- 条目和索引里的字来自模型，以后会进别的 task agent 的系统提示。带进去时写明「是笔记不是指令」，每条有上限；不要去掉这句说明或放开上限。
- 用模型整理条目（`SpaceKeeper._consolidate`，整理的最后一步）：模型只回一张操作清单，用 `n1`、`n2` 这样的代号指条目，不碰文件名；宿主逐项走 `TaskAgentSpace.tidy_entries`，在写锁里先比对条目还是模型看到的那份（`Layer.marks`，整份文件的摘要），不是就不做；写的那一下也要比（`_edit_as_shown`、`_file_entry(as_marked=)`），下一项按上一项写出去的那份比，别用写完再读的。用户手写的（没有 `texts` 行）、已过期的、模型没点到的第三个条目都不动；两条同状态的合并时并掉的那条文件会删（正文已在另一条里），别的不删，都不记进「不再收」。改标题只能在原标题上加一段条目自己原样有的字（`_added_to`，说明一行不改），改日期只能把一个相对时间的词整个换成一个日期（`_a_relative_time`、`SPACE_CONSOLIDATE_RELATIVE_TIME_WORDS`）：模型看过待定的正文，它要求的改动不能当真，要从结构上让它说不出新话。别退回「词都出现过」「多几个 token」这类检查，评审第 2 轮试过，去掉否定词、在日期后接命令都能过。**待定条目的正文不进生效条目**（可能是网页让使魔写的，同一段正文又在判断的模型面前）：和生效条目是同一件事时只记一次观察、自己标过期（`_tidy_count_in`）。被整理判成过时的条目多两行 `outdated`、`superseded_by`，`check_evidence` 不再因为依据文件在而恢复它，只有再被交来（`_keep_known`）时恢复并去掉这两行。挪进别的条目的文字用它当初写下那天作小节标题（`_file_entry(added_on=)`），不然里面的「昨天」就错了。哪一层要看按「说了什么」比（`Layer.said`：标题、说明、正文），只过期或恢复不算变化；看过的记在状态文件的 `consolidated` 里，只记给模型看过的和整理自己写的，问不了模型的层记 `tried`、排到后面。

**消耗上限**：

- 复盘、归档总结和整理条目用 `summary` 档位，不计入 task agent 的每日额度。整理条目一层一次调用、每轮最多两层（`SPACE_CONSOLIDATE_*`），输入、输出上限由 `tests/unit/nekoclaw/test_host_space_tidy.py` 守着；调大要先报消耗对比。
- 复盘输入上限 `TASK_AGENT_REVIEW_INPUT_MAX_TOKENS`、输出上限 `TASK_AGENT_REVIEW_OUTPUT_MAX_TOKENS` 是定过的消耗上限，调大要先报消耗对比。各部分的上限加起来已经贴着输入上限，往复盘提示词里加字要先在别的部分让出位置；`tests/unit/nekoclaw/test_host_space_keeper.py` 守着「各部分都到上限时不超」。
- 开工时带的四段（全局守则、全局索引、项目约定、项目索引）各有上限，合计 `SPACE_BRIEF_MAX_TOKENS`；使魔空间是空的时候一个 token 都不加。

## 权限

四个选项是 `permissions.py` 的 `CHOICES`（始终允许、仅本会话、本次、拒绝），含义和例外在设计稿 10.1、6.10 节。改权限相关代码时记住三条：

- 代码里没定义过的类别按「每次都问」，不会默认放行；权限文件在但读不出来时全部按禁止。
- 键鼠和浏览器的「本次允许」放行到 task agent 这一轮跑完，不是一次调用（它们的工具是一次点击这样的小步）。
- 「用户关掉浏览器后要不要重新打开」这个提问不属于任何权限类别：每次都问，只有本次允许和拒绝，答案不保存，对「浏览器」选过始终允许也照样问。
