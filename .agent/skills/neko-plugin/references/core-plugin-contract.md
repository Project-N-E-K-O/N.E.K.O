# Core Plugin Contract

The hard reference for plugin identity, `plugin.toml`, entries, routers,
hooks, i18n, and UI modes. `<plugin_dir>` below is the folder holding the
plugin's `plugin.toml` (in a N.E.K.O checkout, the checkout's built-in plugin
folder plus the id).

## Identity Lock

Settle `plugin_id` before implementation. These five surfaces must express
one plugin concept:

1. folder name
2. `[plugin].id`
3. `[plugin].name`
4. `[plugin].entry`
5. main entry class

They need not be identical strings. The folder and `[plugin].id` are the
stable machine id, `[plugin].name` is the display name of the same concept,
and the main class names it in PascalCase.

Default derivation:

- `plugin_id`: stable snake_case id matching the Market rule
  `^[a-z][a-z0-9_]*$` (see `dependencies-and-market.md`). Avoid a redundant
  `_plugin` suffix; the CLI appends `Plugin` to the class name.
- `[plugin].entry`: keep what `neko-plugin init` generates,
  `plugin.plugins.<plugin_id>:<MainClass>`, also for a plugin developed
  outside a checkout; the host resolves it from the folder holding
  `plugin.toml`.

The id is permanent once published: data paths, config, and the Market
listing are keyed by it. If several ids are plausible, ask; otherwise derive
one and show the Identity Lock before implementation.

## Plugin Directory

`neko-plugin init` creates:

```text
<plugin_dir>/
├── plugin.toml
├── __init__.py
├── pyproject.toml
├── README.md
├── ruff.toml
├── tests/
│   └── test_smoke.py
├── .gitignore
├── .vscode/
├── .github/workflows/    # verify.yml, release.yml (Market CI)
├── AGENTS.md, CLAUDE.md  # agent guides
└── .agents/skills/neko-plugin/
```

Add only what the plugin needs, inside `<plugin_dir>`:

- `DESIGN.md` for the design brief (`plugin-creation-workflow.md`)
- `i18n/` for locale files (required, see I18n)
- `ui/`, `docs/`, `static/` for UI surfaces
- extra Python modules or packages for helpers
- `vendor/`, generated by `sync --clean` and never committed

Do not move helpers outside `<plugin_dir>` to share code: nothing outside it
ships with the plugin.

## Manifest Contract

`plugin.toml` is validated by `check` and at load time. Required: `[plugin]`
with `id`, `name`, and `entry`.

- `entry` is `module.path:ClassName`, no surrounding whitespace.
- `type` is `plugin` (default) or `adapter`.
- The `extension` type and `[plugin.host]` were removed; see the
  [migration guide](https://github.com/Project-N-E-K-O/N.E.K.O/blob/main/docs/plugins/migration-v0.9.md).
- `version` should follow `x.y.z`; the release tag must be `v<version>`.
- `keywords` is a list of non-empty strings; `passive`,
  `[plugin_runtime].enabled`, and `auto_start` are TOML booleans, not strings.
- `[plugin_runtime].timeout` satisfies `0 < timeout <= 300` (the startup
  budget, see `runtime-model.md`); `startup_failure` is `warn`, `fail`, or
  `ignore`.
- `enabled = false` disables loading; `auto_start = false` only means
  manual start, and the module may still be imported for metadata. `passive =
  true` hides the plugin from agent dispatch; it does not stop it.
- UI permissions are the minimum needed; add `config:write` only when the UI
  writes config.
- Custom business sections are fine; do not invent platform sections.
- Identity fields (`id`, `entry`) cannot be changed by config updates.

Field reference: [plugin.toml guide](https://github.com/Project-N-E-K-O/N.E.K.O/blob/main/docs/plugins/plugin-toml.md);
source of truth: [schema.py](https://github.com/Project-N-E-K-O/N.E.K.O/blob/main/plugin/config/schema.py)
and [plugin_toml_semantics.py](https://github.com/Project-N-E-K-O/N.E.K.O/blob/main/plugin/config/plugin_toml_semantics.py).

## I18n Contract

Third-party plugins must ship i18n with at least `zh-CN` and `en`. N.E.K.O's
users run the UI in several languages and the host resolves every registered
string for the user's locale; text written in one language is shown
untranslated to everyone else, and Chinese and English cover most users.

```toml
[plugin.i18n]
default_locale = "en"   # used when the user's locale has no file
locales_dir = "i18n"    # relative to <plugin_dir>
```

`i18n/en.json`, `i18n/zh-CN.json`: flat key → text maps with the same keys.

- Registered strings (plugin and entry names, descriptions, schema labels, UI
  action labels and confirmations): `tr("key", default="...")`.
- Strings built at runtime: `self.i18n.t("key", default="...", **params)`.
- Hosted TSX copy: `props.t(...)` or `useI18n().t(...)` against the same
  files; no per-component dictionaries.

## Entry Contract

Imports come from the public facade `plugin.sdk.plugin` (adapters:
`plugin.sdk.adapter`); why, in `execution-boundary.md`.

```python
from pydantic import BaseModel, Field

from plugin.sdk.plugin import Err, NekoPluginBase, Ok, SdkError, neko_plugin, plugin_entry, tr


class SearchParams(BaseModel):
    query: str = Field(..., min_length=1, description="Search keywords")
    limit: int = Field(default=5, ge=1, le=20)


class SearchReply(BaseModel):
    summary: str
    count: int
    items: list[dict]


@neko_plugin
class SearchPlugin(NekoPluginBase):
    @plugin_entry(
        id="search",
        name=tr("entries.search.name", default="Search"),
        description=tr("entries.search.description", default="Search the catalog."),
        params=SearchParams,                    # validated before the call
        llm_result_fields=["summary", "count"],  # all the AI reads
        timeout=30,
    )
    async def search(self, params: SearchParams, _ctx: dict | None = None) -> SearchReply:
        character = (_ctx or {}).get("lanlan_name")  # optional host context
        try:
            items = await self._fetch(params.query, params.limit)
        except TimeoutError:
            return Err(SdkError("catalog timed out"))  # the caller sees a failed call
        return Ok(SearchReply(summary=f"{len(items)} results", count=len(items), items=items))
```

- **`async def`**: the host rejects a sync handler when it is called.
- **`params=Model`**: the host validates input with the model and passes the
  instance as `params` (or as the single parameter annotated with the model).
  Invalid input fails the call before your code runs. `params` and
  `input_schema` are mutually exclusive; a bare `input_schema` mapping is only
  published, not validated.
- **`_ctx`**: the host injects call context (`lanlan_name`, `run_id`,
  `entry_timeout`, `conversation_id`, `latest_user_request`, depending on the
  caller). It reaches the handler only if it declares `_ctx` or `**kwargs`;
  treat it as optional and never log `latest_user_request`.
- **`Ok` / `Err`**: `Ok(data)` is success. `Err(SdkError("..."))` and
  uncaught exceptions both reach the caller (AI, UI, other plugin) as a failed
  call with that message, so keep the message short and free of secrets.
- **`llm_result_fields`** decides what the AI reads: only those fields of the
  result. Without it, a Pydantic return annotation (`-> Model`) or
  `llm_result_model` sets the fields instead: the model's required fields,
  or all of its fields when every field has a default. To control exactly
  what the AI reads, set `llm_result_fields`. Only with none of these does
  the AI get one sentence (`data.reply` or the run message), and a task agent
  also the full `data` as JSON. Put bulky raw data outside these fields. `llm_result_fields`, `llm_result_model`, and
  `fields` are mutually exclusive.
- **Output contract**: a Pydantic return annotation (`-> Model` /
  `-> Model | None`) is checked at runtime against the value in `Ok`; a
  mismatch logs a warning, or fails the call with
  `PLUGIN_OUTPUT_SCHEMA_VIOLATION` when `strict_output=True`. Return the model
  instance, not a dumped dict. An explicit `output_schema={...}` mapping is
  published only, never checked. `Err` results are not checked.
- **Timeouts**: the decorator `timeout`, the caller's timeout, and the run or
  RPC deadline all apply; the smallest wins. Details and the `<= 0` rules in
  `runtime-model.md`.

More: [Entries & Parameters](https://github.com/Project-N-E-K-O/N.E.K.O/blob/main/docs/plugins/entries.md)
(including what each caller does with the result).

## Router Contract

Routers organize large plugins; they are not a default architecture. Use
`PluginRouter` only when the main module is hard to maintain (roughly over 1k
lines, many entries across distinct feature areas, or separate owners).

- Import from `plugin.sdk.plugin`; mount with `self.include_router(...)` from
  the main plugin.
- Router modules live inside `<plugin_dir>` (commonly `routers/`).
- Router entries follow the Entry Contract; ids stay unique.

## Hook Contract

Hooks intercept entry execution: `before_entry`, `after_entry`,
`around_entry`, `replace_entry`, `hook`. Use them only for a concrete need
(validation, auditing, timing, result shaping), not to organize business
logic.

- Target the narrowest entry id; `target="*"` only when every entry needs it.
- `replace_entry` changes another entry's behaviour: justify it in
  `DESIGN.md`.
- Hooks do not replace `@lifecycle` (startup, shutdown, reload,
  config_change).

## Package Type and Capabilities

- `plugin`: the default. Entries, background work, timers, UI, state,
  cross-plugin calls, ordinary external API/device integrations.
- `adapter`: only for bridging an external protocol or request stream into
  N.E.K.O plugin calls (`plugin.sdk.adapter`). Calling an external service
  does not make an adapter.

Capabilities, chosen after the type:

- callable entry: `@plugin_entry`
- lifecycle: `@lifecycle`; periodic work: `@timer_interval(id=..., seconds=...)`
  (both in `runtime-model.md`)
- host message reaction: `@message(id=...)`
- output into the conversation: `self.push_message(...)`
  (`plugin-system-surface-map.md`)
- UI: `[plugin.ui]` plus `[[plugin.ui.panel]]`, `[[plugin.ui.guide]]`, or
  `[[plugin.ui.docs]]`
- state and config: `[plugin.store]`, `PluginStore`, `PluginSettings`,
  config profiles

## UI Surface Modes

Surface kind is placement; mode is rendering. Do not conflate them.

- Kind: `panel` (management or dashboard), `guide` (quickstart), `docs`.
- Mode:
  - `hosted-tsx` (default for new UI, `entry = "ui/panel.tsx"`): interactive
    panels, settings, forms, tables, actions.
  - `markdown` (`entry = "docs/quickstart.md"`): read-only docs; no actions or
    scripts.
  - `static` (`entry = "static/index.html"`): legacy iframe HTML; only to keep
    an existing page or for a browser capability Hosted TSX lacks.

With `mode` omitted it is inferred from the entry suffix (`.tsx`/`.jsx`,
`.md`/`.mdx`, `.html`/`.htm`). Do not pick `auto`. Authoring details:
`hosted-ui-authoring.md`; component API: `hosted-ui-api.md`.
