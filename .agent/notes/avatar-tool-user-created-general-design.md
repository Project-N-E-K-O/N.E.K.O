# Avatar 用户自定义道具图片交互功能设计

> 状态：已锁定
> 锁定日期：2026-09-02；初始入口与画布体验校正：2026-09-03；名称唯一性校正：2026-09-10；阶段 7 编辑预设校正：2026-09-15
> 本文是后续实施与验收的产品语义基线。除非用户明确要求重新打开设计，否则实施不得改变本文确定的功能、用户概念、运行语义或范围；技术结构和阶段安排由实施文档承接。

本文设计自定义道具图片交互的完整目标形态。用户不再选择固定的切图模式，而是添加完整图片交互并把它们连接起来。现有实现只用于确认接入边界和迁移来源，不限制目标功能需要替换的数据与运行结构。

本文只描述目标功能。代码结构、数据格式、兼容迁移和实施阶段由实施文档负责。

## 1. 目标与范围

目标功能为：

1. 用户可以为道具添加多张同级图片，并选择其中一张作为初始图片；
2. 每张图片可以填写自己的互动描述，也可以不填写；
3. 用户可以添加由“用户触发和图片动作”组成的完整图片交互；
4. 用户可以连接这些完整交互，组合顺序、重复、循环和不同触发走向；
5. 一次鼠标点击的反馈始终由点击开始时已经显示的图片决定，不受该次点击随后切图的影响；
6. 该图片没有互动描述时，只执行本地图片交互，不构造提示词、不调用模型。

以下现有能力继续保留：

- 本地选择图片；
- 普通互动音效和概率彩蛋；
- 创建、修改、删除和装备；
- Web、Full、Compact 与 N.E.K.O.-PC 的现有输入、隔离和反馈链边界。

彩蛋沿用既定语义：命中彩蛋时，本次普通反馈事件直接变成彩蛋反馈事件；不同时产生两次反馈，也不阻止已经配置的本地图片动作。

当前两种固定切图方式、独立默认图片、互动描述必填，以及点击后按变化图片选择提示词，都是现有实现行为，不是目标约束。实施时可以替换这些结构和顺序，但不能建立第二套输入、窗口或模型反馈链。

本次不增加图片生成、系统推荐、预览、自动保存或草稿，也不重新设计现有音效、彩蛋和提示词内容规范。

## 2. 管理入口与编辑空间

桌面端紧凑聊天框中的 Compact 是本功能最重要的管理入口和使用场景。用户继续从现有“管理道具”进入创建或修改，但这不表示要把图片交互连线编辑器塞进 Compact 的狭小内容区。

图片管理、完整交互配置、连线、自连接和回连需要能够看清整体关系的编辑空间。目标设计只确定以下边界：

- Compact 中的入口、保存后返回和道具管理闭环必须完整；
- 连线编辑必须获得足够的独立工作空间，不能为了适应小面板而缩小节点、隐藏关系或牺牲可用性；
- 编辑空间与 Compact 使用同一份道具内容和保存流程，不能形成另一套数据或交互语义；
- 编辑器最终采用独立窗口、扩展工作区或其它形态，由实施文档结合成熟节点编辑器和桌面应用方案研究后确定，本设计不提前指定布局。

画布中的节点以四周边界作为连续连线区域，不显示四个离散圆点；已有连线根据节点相对位置自动选择合适的边界落点，并以留有间距的路径尽量绕开其它节点，不从其它节点内容下穿过。移动节点后连线随之重新选路，自连接、双向连接和同侧多条连接不能完全重叠。全图概览属于一个完整的画布视图浮层：展开内容、收起入口和位置选择保持在一组，并随用户选择的角落整体移动，不写入道具运行语义。展开态直接以缩略图本身作为浮层，缩略图必须显示当前实际节点和视口；收起与位置入口组成不覆盖缩略内容的紧凑工具组，概览位于画布上方时工具组置于缩略图下方，概览位于画布下方时工具组置于缩略图上方，不增加外围白色卡片或底部常驻设置栏。两个展开态操作按钮仅在鼠标位于概览区域或键盘聚焦其中时显示；收起时只保留单图标入口。位置菜单仅在需要时于同一工具行展开，使用能直接表示画布角落的图形，不使用抽象方向箭头。画布就绪提示覆盖在画布内显示，不参与或避让其它画布控件的布局。右侧总区以“道具编辑”作为区域名，内部按实际内容分为“道具设置”和“互动设置”两个页签。

## 3. 道具图片

所有道具图片都是同一种图片项，不再存在特殊的“默认图片”类型。每张图片包括：

- 本地图片；
- 可自定义的图片名称；未自定义时按当前顺序显示“道具图片 + 数字”；
- 可选互动描述；
- 是否为当前道具的初始图片。

同一个道具内的图片名称不得重复，未自定义时显示的默认名称也参与判断。

每个道具必须且只能选择一张初始图片。初始图片决定道具装备或新运行周期开始时首先显示什么，同时作为互动流程唯一、真实的入口；它不是一项用户触发，也不需要虚构“开始使用”事件。道具显示初始图片后，直接等待它在画布中连接的完整交互。

初始图片与其它图片完全同级：它可以有互动描述，也可以没有；后续图片动作也可以再次选择它。删除仍被图片动作引用的图片时，必须先更换相关引用，不能留下失效交互。

## 4. 图片交互编辑器

### 4.1 完整交互

每项图片交互是一个不可拆开的完整单位：

```text
图片交互
├─ 用户触发：用户做了什么，或等待了多久
└─ 图片动作：该触发过程中怎样改变图片
```

连线只连接完整图片交互。用户触发和图片动作不会拆成两类节点，底层 `pointerdown`、`pointerup` 等运行事件也不会直接成为创建页选项。

每项完整交互都可以自定义名称。未自定义时继续按类型和当前顺序显示“鼠标点击 + 数字”或“延时切换 + 数字”；自定义后以用户名称作为节点主标题，交互类型仍通过独立的类型文字和图标保留，不把“交互事件”或类型名称强制拼入用户名称。同一个道具内的完整交互名称不得重复，未自定义时显示的默认名称也参与判断；图片名称与交互名称分开判断。图片名称和交互名称用于编辑、选择和辨认流程，不代替图片互动描述，也不改变运行语义。

文档当前涉及的用户触发如下：

#### 鼠标点击

“鼠标点击”是一次完整的用户操作，只能整体添加、连接、复制和删除。它内部提供两个用户容易理解的图片动作时机：

```text
┌────────鼠标点击────────┐
│ 按下时：不变 / 显示图片 │
│ 松开时：不变 / 显示图片 │
└───────────────────────┘
```

- 按下和松开分别选择“图片不变”或一张目标图片，用户可以只让其中一个时机切图，也可以两个都切图；
- 按下和松开时机固定，用户不需要排列底层事件顺序；
- 两个内部动作不能单独连接到其它交互；
- 两个时机都选择“图片不变”时，完整点击仍可用于当前图片反馈、推进连接或离开循环，不增加专用“保持图片”操作；
- 系统内部仍负责判断按下与松开是否组成一次正常点击，但创建页不显示“有效点击”“点击成立阶段”或“释放事务”等运行概念；
- 正常完成鼠标点击后，才沿该完整交互的连接继续；没有形成正常点击时不推进连接、不触发模型。

常见组合仍使用同一个鼠标点击交互：

```text
点击后换图：
[鼠标点击：按下不变，松开显示图片 B]

按下换图、松开返回：
[鼠标点击：按下显示图片 B，松开显示图片 A]
```

#### 延时切换

```text
[经过指定时间 → 图片不变 / 显示图片 B]
```

用户设置正数等待时间，并选择到时“图片不变”或显示一张目标图片。时间从该交互进入等待时开始；连接离开当前等待位置后，不再执行尚未到达的时间动作。“图片不变”只是不切图，等待完成后仍正常沿连接继续。

用户选择的是能够理解的完整操作，不是平台原始事件；每项用户触发都与自己的图片动作组成一个整体，并使用同一种连接规则。

### 4.2 连接

画布只显示实际初始图片和完整交互，不把其它图片变成流程节点。连线只有两种来源：

- 初始图片连接完整交互，表示道具开始显示初始图片后首先等待哪些互动；
- 一个完整交互连接另一个完整交互，表示前一项完成后接下来等待哪些互动。

普通后续连接仍然只发生在完整交互之间：

```text
[用户触发 → 图片动作] ──> [用户触发 → 图片动作]
```

一项交互可以连接：

- 后面的交互，继续下一段图片变化；
- 自己，重复同一项交互；
- 前面的交互，形成循环；
- 多个使用不同用户触发的后续交互，由实际先完成的触发决定走向。

同一等待位置不能同时存在两个无法区分的相同用户触发。某个后续交互完成后，其它尚未完成的同级等待不再推进。鼠标点击已经从按下开始后，同级延时不能插入这次点击过程。没有后续连接时，图片交互到此停止，当前显示图片保持不变。

初始图片可以连接一项或多项完整交互；这些连接共同构成最初的等待位置。该位置同样不能存在两个无法区分的用户触发。画布显示的是用户已选择的实际初始图片，不增加抽象“开始”节点，也不再为互动设置第二套“起始互动”属性。

### 4.3 顺序、重复与轮播

顺序、重复和轮播由完整交互之间的连接形成，不增加“下一张”“自动轮播”“暂停”“恢复”或循环容器。

```text
每次点击切换一张：

[点击：松开显示 B] ──> [点击：松开显示 C] ──> [点击：松开显示 A]

按时间持续轮播：

[500ms → 图片 A] ──> [500ms → 图片 B] ──> [500ms → 图片 C]
      ▲                                               │
      └───────────────────────────────────────────────┘
```

从循环中的等待位置连接另一种用户触发，即可在该触发先完成时离开循环；鼠标点击的按下和松开都选择“图片不变”时，可以退出循环并停在当时的图片。循环、退出和后续切图使用同一种连接规则，不增加专用退出操作。

现有固定切图方式不再作为创建页模式或顶层分类。它们可以作为一次性编辑预设，把对应视觉过程拼成普通完整交互和连接；应用后不保留预设身份，用户可以自由修改，后续重新应用仍从原始预设重新生成，不受先前修改影响。

## 5. 编辑与保存

编辑没有固定填写顺序。用户可以先添加图片或交互，也可以先连接，再补完整配置。编辑过程中允许暂时存在未完成内容；保存时只进行简单闭环检查：

- 道具名称符合现有要求，图片名称和完整交互名称各自在同类内容中不重复；
- 至少有一张图片，且恰好一张被选为初始图片；
- 初始图片至少连接一项完整交互；
- 每项鼠标点击交互的按下和松开都具有合法图片选项；“图片不变”是合法结果；
- 每项延时交互具有正数等待时间，并选择合法的“图片不变”或有效目标图片；
- 已填写的互动描述符合现有内容限制，空描述合法；
- 所有图片引用和交互连接都指向现有内容；
- 所有正式保存的交互都能从初始图片沿连接到达；
- 同一等待位置没有两个无法区分的相同用户触发；
- 图片、描述、音效、彩蛋和本地总占用符合后端限制。

自连接、回连和多项循环均合法。不要求循环必须退出，不要求流程必须存在结束节点，也不做复杂的终止性或通用状态机分析。

保存失败时保留本次页面内容，并在对应图片或交互处显示错误。保存成功后返回管理页，不自动装备道具。

## 6. 实际运行与反馈

### 6.1 本地图片交互

```text
显示初始图片
  → 等待初始图片连接的完整交互
  → 鼠标点击按顺序执行按下、松开图片动作
    或延时到达时执行自己的图片动作
  → 当前完整交互结束
  → 等待它连接的后续交互
```

按下、松开、时间到达和普通图片变化本身只更新本地画面。图片交互使用现有输入事实和运行边界，不建立第二套 pointer、窗口、取消或模型反馈链。

### 6.2 鼠标点击反馈

鼠标按下时，在执行该次点击配置的任何图片动作前，记录当时正在显示的图片。正常完成这次点击后，彩蛋命中就产生一次彩蛋反馈；彩蛋未命中，则只有记录图片具有互动描述时才产生一次普通反馈，否则不调用模型。

本次点击的按下或松开图片动作只影响随后显示什么，不能改写已经记录的点击图片。没有形成正常点击时，不确认图片结果、不调用模型，也不沿该鼠标点击交互继续。

提示词最终包含什么以及如何处理 memory，由独立提示词设计负责。普通音效和彩蛋继续使用现有功能。

## 7. 用户完整流程

```text
从 Compact 管理道具进入创建或修改编辑器
  → 编辑名称
  → 添加道具图片并选择初始图片
  → 按需要填写每张图片自己的互动描述
  → 添加完整的鼠标点击或延时交互
  → 调整点击内部的按下、松开图片动作
  → 从初始图片连接最先可响应的完整交互
  → 连接后续交互，形成顺序、重复、循环或退出
  → 保留或修改普通音效和彩蛋
  → 保存并完成简单闭环检查
  → 返回管理页并由用户选择是否装备
  → 道具按连接执行本地图片交互
  → 正常点击时，有适用描述才产生一次模型反馈
```

添加图片、填写描述、添加交互和建立连接可以交替进行；上图只表示完整闭环，不是强制填写顺序。

## 8. 验收标准

- Compact 是首要管理入口和使用场景；连线编辑获得足够的独立工作空间，不被强行限制在 Compact 小面板内；
- 创建页不再显示两个互斥切图方式，也不直接显示底层 pointer 事件；
- 所有图片同级，用户必须选择一张初始图片，每张图片的互动描述均可选；
- 图片和完整交互都可以重命名，清空后恢复默认序号名；同类名称不重复，交互类型仍独立可见；
- 画布显示实际初始图片作为唯一入口，它可以连接一项或多项完整交互；互动上不存在额外的“起始互动”属性；
- 用户可以添加、删除和重新连接完整图片交互；
- 节点四周边界均可直接拖出连接且不显示离散连接点；移动后自动调整边界落点，自连接、双向连接和同侧多线保持可辨认；
- 全图概览的展开、收起和位置选择位于同一浮层，浮层随角落选择整体移动，且不改变道具内容与流程；
- 鼠标点击只能整体连接，内部只显示可调整的“按下时”和“松开时”图片动作；
- 创建页不出现“有效点击”“点击成立阶段”或“释放事务”等运行概念；
- 延时交互可以与鼠标点击出现在同一图片流程中；
- 自连接、回连和不同用户触发的分支可以表达重复、轮播及离开循环；
- 保存只要求引用有效、正式交互可达和触发无歧义的简单闭环，不限制合法循环；
- 现有固定切图的视觉过程可以由新结构表达，但提示词取图变化不称为旧反馈行为的无损兼容；
- 正常点击只记录该次点击任何图片动作执行前已经显示的图片；
- 彩蛋命中时产生一次彩蛋反馈，不再产生普通反馈；
- 彩蛋未命中时，记录图片有互动描述才产生一次普通反馈，没有描述则不构造提示词、不调用模型；
- 没有正常完成的点击或取消不确认结果、不推进鼠标点击交互；
- 当前创建、修改、删除、装备、音效和彩蛋等现有能力不回归；
- Compact、Full、Web 与 N.E.K.O.-PC 对同一配置使用相同运行语义，不按道具名称或图片数量增加专用分支。
