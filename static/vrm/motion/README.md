# VRMA 中文动作卡库

这个目录保存压缩动作和机器可读动作卡。动作判断完全在本地完成，不修改角色提示词，不调用动作模型，每次动作额外消耗 0 token。

## 唯一语义链路

1. 中英文括号闭合后，或一轮可见回复结束后，解析器提取动作、身体部位、姿态、情绪、程度、否定和上下文。
2. `zh-CN` 直接进入中文动作帧；`zh-TW/en/ja/ko/ru/es/pt` 只把动作相关含义规范化为中文，不翻译或保存整段对话。
3. `motion-semantics.json` 用中文动作帧判定意图。
4. `manifest.json` 中的动作卡用中文正例、反例、身体部位、风格、情绪和姿态结果选择具体资产。
5. 加载器首次播放时读取 `.vrma.gz`，校验压缩哈希，解压后校验 VRMA 哈希，不长期缓存解压副本。
6. 唯一状态机负责低姿态过渡、持续姿态、短动作和表情；动作卡检索不得在同一意图内盲目随机。

## 命名规则

压缩文件名必须直接描述画面，例如：

- `休闲地盘着腿坐.vrma.gz`
- `害羞地把双手背在身后.vrma.gz`
- `沮丧地低着头.vrma.gz`

文件名允许在人工复核后改得更准确，但 `card.stableId` 永远不能变化。运行记录、缓存和用户反馈只引用稳定 ID；中文文件名和 `card.nameZh` 必须始终一致。

## 动作卡

每项资产必须包含：

- `stableId`：不可变的机器引用。
- `intent`、`kind`：意图族和状态机类型。
- `nameZh`：人能直接看懂的中文画面描述。
- `positiveZh`：至少三个可触发的中文动作表达。
- `negativeZh`：容易混淆但不应选择本资产的表达。
- `styles`、`body`、`emotions`：风格、身体控制范围和适用情绪。
- `inputPose`、`resultPose`、`playback`：进入姿态、结果姿态和播放方式。
- `descriptionStatus`：临时描述、人工验证或维护者批准。

结构由现有的 `00_meta/intent.schema.json` 校验。新增动作不需要修改播放器：运行时会从动作卡自动注册中文正例；新增全新意图时必须同时给出 `kind`，状态机才能按通用契约处理。

## 目录与发布限制

- `00_meta/manifest.json`：资产、动作卡、来源、许可证、时长和双重哈希。
- `00_meta/machine.json`：姿态、播放、语言规范化和检索契约。
- `00_official/`：官方 N.E.K.O 动作的压缩副本，许可证为 Apache-2.0。
- 社区或第三方素材只有在动作卡同时提供可核验来源、明确许可证和维护者批准后，才能进入公开目录。

当前公开包只包含 13 个官方动作。语义表保留更多意图作为扩展契约；若某个意图没有已授权素材，播放器会安全地不执行动作，不能回退到来源不明的文件。

Mixamo 等允许嵌入成品、但禁止单独重新分发原始或转换后动作素材的来源，不得提交到本目录。转换格式或 gzip 压缩不会改变原素材许可证。
