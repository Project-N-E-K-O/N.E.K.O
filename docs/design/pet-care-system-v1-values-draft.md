# 猫形态养宠首版数值与内容草案

> 这是供一一审阅的候选草案，不是锁定规则，也不修改《宠物养成系统方案（修订稿）》。
>
> 所有数值都应进入配置；本文件只给出一套能跑通首版循环的起始方案。正式实现前可以整体替换，不应让页面或动作代码写死这些数值。

## 1. 设计边界

- 产品规则以锁定文档和本轮补丁为准：每个社区账号只有一只猫，绑定账号自己的一个角色；当前角色不是绑定角色时按普通猫处理，不读取另一份宠物记录。cat1/cat2/cat3 和装扮只影响外观。
- 养成可用性直接复用社区登录会话；不新增宠物登录状态或单独的在线状态。正式数据使用社区服务器，本地只保留开发和验收镜像。
- 首版完成任务、喂食、清洁（首版具体操作为梳毛）、用户主动陪玩、一个探索地、负面状态和 3–5 个解锁项。
- 首版不接商店、购买型道具、社区货币、付费猫粮、社交、推送、装扮和复杂小游戏。
- 小鱼干是当前唯一基础食物，只能从每日任务获得，数量由任务上限约束；逗猫棒等陪玩道具是消耗品，主要由探索获得。
- Cat Mind 不参与本草案的数值计算、结算或负面状态判定。用户主动操作和猫的反馈动作分开：操作属于养成动作，反馈动作只是可替换的表现。
- 登录、猫处于猫形态且养成快照完整时，只暂时屏蔽会冲突的旧自主自动触发；在家时正常的喂食、梳毛、陪玩和返回等用户功能不因 Cat Mind 停用而消失。Cat Mind 后续是否接入少量行为提示另行评估。
- 参考常见桌面宠物的轻量循环：状态缓慢变化、短操作即时反馈、任务提供基础资源、探索提供稀有资源和邮件；不照搬旧游戏的商城、死亡或付费规则。

## 2. 基础状态

饱食度、精力、清洁度和心情范围为 `0–100`，每次服务结算后截断到范围内；养成进度是累计解锁值，只要求非负，不套用 `100` 上限。该边界仍属于可编辑草案，未来可由服务配置迁移规则。

| 状态 | 初始值 | 本地模式的候选变化 | 说明 |
| --- | ---: | --- | --- |
| 饱食度 | 75 | 在家每小时 `-1`；喂食 `+25` | 低于 20 只影响心情和生病概率，不直接禁止普通照料 |
| 精力 | 80 | 在家每小时 `+4`；陪玩 `-8`；探索出发 `-20` | 探索中不自动恢复；回家后按正常时间补算 |
| 清洁度 | 80 | 每小时 `-1`；清洁操作（首版梳毛）`+30`；陪玩 `-2`；探索出发 `-10` | 探索消耗较多，生病概率对该项权重最高 |
| 心情 | 由公式得出 | 见 2.1 | 是收益倍率，不作为首版探索硬前置 |
| 养成进度 | 0 | 见第 5 节 | 只在服务确认操作后增加 |

### 2.1 心情候选公式

先计算互动指数 `I`，范围 `0–100`。首次初始化为 `40`；用户主动喂食、清洁操作（首版梳毛）和成功陪玩分别按动作配置增加互动，互动指数按时间缓慢衰减。互动指数属于养成服务自己的长期值，服务保存最近一次结算值和时间，不保存 Cat Mind 的五维。

```text
mood_raw = 0.25 * 饱食度
          + 0.20 * 精力
          + 0.25 * 清洁度
          + 0.30 * 互动指数
          + mood_jitter
mood_jitter ∈ {-3, -2, -1, 0, 1, 2, 3}
mood = clamp(round(mood_raw), 0, 100)
```

| 心情 | 范围 | 收益倍率 |
| --- | --- | ---: |
| 低 | 0–39 | 0.75 |
| 中 | 40–74 | 1.00 |
| 高 | 75–100 | 1.50 |

候选规则是：进度使用整数配置，基础值优先取 4 的倍数；低、中、高心情分别按 `3/4、1、3/2` 结算，避免出现无法解释的小数。完整探索使用一个独立的整数完成奖励配置，不增加未说明的比例乘法。每日登录和任务小鱼干不受心情倍率影响；探索掉落数量或品质使用出发时保存的心情倍率。随机数只在服务结算时生成并随结果保存，读取不会重新摇动。

状态的单次增减和进度结算结果都必须是整数；公式中的权重只用于计算心情，最终心情取整，不能把小数直接写入状态或进度。

## 3. 照料类别与动作反馈

业务操作和表现动作分开配置。首版先用现有动作跑通，后续替换反馈资源不改变业务接口。

| 用户操作 | 业务效果 | 基础进度 | 限制 | 首版反馈动作 |
| --- | --- | ---: | --- | --- |
| 喂食 | 使用 1 条小鱼干；饱食度 `+25`；满值时拒绝；互动指数按配置小幅增加 | 0 | 不新增道具冷却；可用数量受每日任务产出限制 | 复用现有吃零食表现或基础吃饭表现 |
| 清洁：梳毛 | 清洁度 `+30`；满值时拒绝；互动指数按配置增加 | 4（按心情倍率结算） | 沿用锁定稿的清洁 CD；具体时长进配置 | 暂用伸懒腰 |
| 毛线球陪玩 | 用户主动触发且猫有真实回应；精力 `-8`、清洁度 `-2`、互动指数按配置增加 | 每日前 N 次给 4（按心情倍率结算），之后仍可玩但不再给进度 | 不新增用户操作 CD；每日进度次数按锁定稿配置 | 复用毛线球动作 |
| 逗猫棒等消耗品陪玩 | 消耗 1 件；用户主动触发且猫有真实回应；精力 `-10`、清洁度 `-2`、互动指数按配置增加 | 8（按心情倍率结算） | 不新增道具 CD；每日次数上限由服务端判定；可用数量受库存和探索/状态任务产出限制 | 暂用玩球 |

- 没有回应、用户取消、动作失败或超时，都不增加进度；逗猫棒只在服务确认成功后扣除。
- Cat Mind 自主发起的玩耍不计入养成陪玩进度；毛线球每日前 N 次计进度，之后仍可玩但不再计进度；消耗品陪玩受服务端每日次数上限约束。不同陪玩类型使用独立的进度配置。
- 清洁类别中的梳毛操作、陪玩类别中的逗猫棒使用，与猫反馈动作是两个字段；将来可以把伸懒腰、玩球替换成新的专用动作，也可以增加其他清洁或陪玩操作而不改变类别边界。
- 生病时仍可清洁和完成求药任务；生病期间禁止探索。赌气状态以互动恢复为主，不额外改写 Cat Mind。

## 4. 每日任务与基础物品

- 每个服务日按服务配置生成独立任务项。小鱼干领取项和毛线球进度项都可以是每日刷新任务，但任务类型、数量、周期和总产出不在前端固定；小鱼干只能从配置的奖励任务获得。
- 任务内容先使用不依赖宠物状态的短操作，例如整理桌面、查看一封信、完成一次指定互动；避免用户必须先有食物才能获得食物。
- 小鱼干初始库存为 `0`，首日先完成任务再喂食；测试配置可以给 `2` 条种子用于快速验收。
- 每日登录确认增加一档独立的整数进度，每个服务日只记一次；服务日边界先按本地时区 `00:00`，正式服务再由社区账号区域配置。
- 任务完成、奖励领取和每日登录都使用幂等请求；任务资源不受心情倍率影响。

### 4.1 阶段 5 本地起始配置（仍为可替换草案）

为先跑通本地闭环，当前服务配置使用一条不设置完成条件的可领取占位任务：用户打开任务区后直接手动领取，成功发放 `1` 条小鱼干；同时配置一条由真实毛线球回应推进的每日进度任务。两项任务同级返回，只有小鱼干项提供领取操作；标题、任务数量、周期、奖励物品、进度目标和数量都只是配置值，后续可以替换，不改变任务读取/领取契约。

- 服务日按本地时区 `00:00` 切换；正式服务可由账号区域配置覆盖。
- 每日登录初始使用 `+4` 点进度，每个服务日只确认一次；该数值仍可编辑。
- 本地起始解锁目录沿用下表的 5 个占位项（阈值 `40/120/260/480/800`）；名称、资源、类型和阈值只用于验收，可整体替换。
- 任务和每日登录不受心情倍率影响；小鱼干喂食仍只恢复饱食度，进度增量保持 `0`。

## 7. 离线结算与负面状态

这是候选公式，目的只是先把“多个数值 + 离线时间”的关系跑通。

### 7.1 共同规则

- 只在社区登录会话从失效到再次有效、用户重新登录回来时判定；不新增宠物层的在线/离线状态，也不把“开着应用但没有操作”另算一套离线规则。
- 候选触发门槛为离线 `48` 小时；锁定文档只给方向，这个门槛仍可调整。
- 同一离线段只抽取一次；生病和赌气可以同时存在，各自按对应恢复任务处理。
- 如果饱食度、精力、清洁度和心情都至少为 `80`，本次保证不触发。
- 恢复物品由状态任务完成后发放，不在负面状态判定时直接塞入库存。

定义：

```text
time_factor = clamp((offline_hours - 48) / 120, 0, 1)
satiety_deficit = (100 - 饱食度) / 100
energy_deficit = (100 - 精力) / 100
cleanliness_deficit = (100 - 清洁度) / 100
mood_deficit = (100 - 心情) / 100
```

### 7.2 生病候选概率

清洁度占最高权重，饱食度、心情和离线时长共同影响：

```text
sick_probability = clamp(
    0.05
    + 0.20 * time_factor
    + 0.25 * cleanliness_deficit
    + 0.12 * satiety_deficit
    + 0.08 * mood_deficit
    + 0.05 * energy_deficit,
    0, 0.55
)
```

生病后：猫显示萎靡，探索入口关闭；状态任务“求药”完成后获得 1 个药品，使用成功后清除状态。清洁和普通状态读取仍可用。

### 7.3 赌气候选概率

心情占最高权重，离线时长、精力和清洁度提供辅助影响：

```text
sulk_probability = clamp(
    0.05
    + 0.20 * time_factor
    + 0.25 * mood_deficit
    + 0.10 * energy_deficit
    + 0.08 * cleanliness_deficit
    + 0.05 * satiety_deficit,
    0, 0.50
)
```

赌气后：猫表现为不理人；状态任务保证用户能够取得 1 根逗猫棒，成功陪玩后消耗并清除状态。生病和赌气可以同时存在：生病仍禁止探索，赌气恢复路径独立展示，不能互相覆盖或提前清除。

### 7.4 进度回退候选

- 连续离线超过 `5` 天后开始回退。
- 每多离线完整 1 天，回退 `20` 点进度。
- 回退下限是最近一次解锁存档点，已解锁内容永不回收。
- 回来时先补算状态，再执行一次回退和一次负面状态判定；重复读取不能重复执行。

## 8. 重试、时间和失败语义

- 每次写操作都有 `idempotency_key`。网络失败不结算，用户可以重试；成功后返回完整快照、操作结果和奖励信息。
- 召回首次被服务接受时记录 `recall_accepted_at`；同一活动和幂等键的重试沿用第一次结果，不按迟到响应时间重新计算。
- 强制召回比例为：

```text
completed_ratio = clamp(
    (recall_accepted_at - exploration_started_at) / exploration_duration,
    0, 1
)
```

- 客户端不能自行提交一个未来时间来提高奖励；服务使用自己的活动开始时间和首次接受时间。用户看到的“操作时间”以这两个服务时间点为准。
- 召回失败时不展示未确认奖励。统一返回模型可以完成表现收尾，活动和猫窝状态保留，用户恢复连接后继续重试。

- 不引入 qqpet 的商城、货币、付费食物、地图旅行、社交、农场/池塘、复杂小游戏、死亡链或本地自动衰减；N.E.K.O 首版的鱼干、梳毛、毛线球、消耗品陪玩、单一探索地点和负面状态仍按锁定文档定义。

### 10.2 阶段 0–3 的配置与状态留项

- 阶段 0–3 只读取和保存服务确认的基础快照，以及 `last_settled_at`；不在客户端运行状态衰减、时间补算、操作结算、奖励发放或库存扣除。
- 本草案中的初始状态值仍是可编辑配置，服务启动时可由本地 `pet_care.json` 或测试配置替换；它们不是锁定产品数值，也不能被前端复制成第二套规则。
- 后续阶段需要的心情计算必须由养成服务提供互动记录或 `interaction_index` 契约；负面状态必须由服务提供离线段标识或等价的一次性结算标记。这些字段尚未在阶段 0–3 实施，不能由 `character_uid`、Cat Mind 五维或客户端时间推导。
- Cat Mind 的自主调度周期与养宠服务的结算周期保持独立；本草案的候选概率、CD、次数、奖励和解锁内容都不能作为阶段 0–3 的运行条件。
