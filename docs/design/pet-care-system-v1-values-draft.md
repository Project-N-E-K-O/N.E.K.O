# 猫形态养宠首版数值与内容草案

> 这是供审阅的候选草案，不是当前产品合同。产品与架构边界以[《猫形态养宠系统设计与维护规范》](./pet-care-system-design-and-maintenance.md)为准。
>
> 所有数值都应进入配置；本文件只给出一套能跑通首版循环的候选方案。激活到 staging／生产前可以整体替换；已有环境激活后必须建立新的不可变 revision，涉及持久语义时还需要显式迁移。页面和动作代码不得写死这些数值。

## 1. 设计边界

- 产品规则以设计与维护规范为基线：每个社区账号只有一只猫，绑定账号自己的一个角色；当前角色不是绑定角色时按普通猫处理，不读取另一份宠物记录。cat1/cat2/cat3 和装扮只影响外观。
- 养成可用性直接复用社区登录会话；不新增宠物登录状态或单独的在线状态。正式数据使用社区服务器；本地开发和验收运行同一套正式 PetCare 服务代码与隔离数据库，不在 N.E.K.O 客户端保留第二套权威镜像。
- 首版完成任务、喂食、清洁（首版具体操作为梳毛）、用户主动陪玩、一个探索地、负面状态和当前已有真实消费入口的解锁项；不为凑数量保留占位内容。
- 首版不接商店、购买型道具、社区货币、付费货币、社交、推送、装扮和复杂小游戏。
- 小鱼干是当前唯一基础食物，只能从每日任务获得，数量由任务上限约束；逗猫棒等陪玩道具是消耗品，主要由探索获得。
- Cat Mind 不参与本草案的数值计算、结算或负面状态判定。用户主动操作和猫的反馈动作分开：操作属于养成动作，反馈动作只是可替换的表现。
- 登录、猫处于猫形态且养成快照完整时，只暂时屏蔽会冲突的旧自主自动触发；在家时正常的喂食、梳毛、陪玩和返回等用户功能不因 Cat Mind 停用而消失。PetCare 只通过有版本和有效期的只读投影向 Cat Mind 提供少量行为偏置；Cat Mind 仍不保存养成状态、不发奖励，也不参与长期结算。
- 参考常见桌面宠物的轻量循环：状态缓慢变化、短操作即时反馈、任务提供基础资源、探索提供稀有资源和邮件；不照搬旧游戏的商城、死亡或付费规则。

## 2. 基础状态

饱食度、精力、清洁度和心情范围为 `0–100`，每次服务结算后截断到范围内；养成进度是累计解锁值，只要求非负，不套用 `100` 上限。该边界仍属于可编辑草案，未来可由服务配置迁移规则。

| 状态 | 初始值 | 当前候选变化 | 说明 |
| --- | ---: | --- | --- |
| 饱食度 | 75 | 在家每小时 `-1.25`；小鱼干 `+35` | 低于 20 只影响心情和生病概率，不直接禁止普通照料 |
| 精力 | 80 | 在家每小时 `+4`；陪玩 `-8`；探索出发 `-20` | 探索中不自动恢复；回家后按正常时间补算 |
| 清洁度 | 80 | 每小时 `-1.25`；梳毛 `+35`；陪玩 `-2`；探索出发 `-10` | 梳毛可在 CD 后重复，探索和陪玩会增加清洁需求 |
| 心情 | 由公式得出 | 见 2.1 | 是收益倍率，不作为首版探索硬前置 |
| 养成进度 | 0 | 见第 5 节 | 只在服务确认操作后增加 |

### 2.1 心情候选公式

先计算互动指数 `I`，范围 `0–100`。首次初始化为 `40`，在家时每小时下降 `0.10`；当前候选的喂食、梳毛、毛线球和逗猫棒分别增加 `1/2/3/5`。互动指数属于养成服务自己的长期值，服务保存最近一次结算值和时间，不保存 Cat Mind 的五维。

```text
mood_raw = 0.25 * 饱食度
          + 0.20 * 精力
          + 0.25 * 清洁度
          + 0.30 * 互动指数
mood = clamp(mood_raw, 0, 100)
```

| 心情 | 范围 | 收益倍率 |
| --- | --- | ---: |
| 低 | 0–39 | 0.75 |
| 中 | 40–74 | 1.00 |
| 高 | 75–100 | 1.50 |

候选规则是：进度使用整数配置，基础值优先取 4 的倍数；低、中、高心情分别按 `3/4、1、3/2` 结算并向下取整。完整探索使用一个独立的整数完成奖励配置，不增加未说明的比例乘法。每日登录和任务小鱼干不受心情倍率影响。当前首个地点完整完成固定带回 1 根逗猫棒，单件掉落不再乘心情后向下取整；心情仍影响探索进度，未来出现可分档的掉落时再单独配置数量或品质倍率。随机数只在服务结算时生成并随结果保存，读取不会重新摇动。

状态允许保存服务按时间补算得到的小数，进度结算保持整数。客户端只显示格式化结果，不能自行四舍五入后反写服务。

## 3. 照料类别与动作反馈

业务操作和表现动作分开配置。首版先用现有动作跑通，后续替换反馈资源不改变业务接口。

| 用户操作 | 业务效果 | 基础进度 | 限制 | 首版反馈动作 |
| --- | --- | ---: | --- | --- |
| 喂食 | 使用 1 条小鱼干；饱食度 `+35`；满值时拒绝；互动指数 `+1` | 0 | 不新增道具冷却；可用数量受每日任务产出限制 | 复用现有吃零食表现或基础吃饭表现 |
| 清洁：梳毛 | 清洁度 `+35`；满值时拒绝；互动指数 `+2` | 每服务日第一次给 4（按心情倍率结算） | `1` 小时 CD；CD 后可继续梳毛并恢复状态，后续不重复发成长进度 | 暂用伸懒腰 |
| 毛线球陪玩 | 用户主动触发且猫有真实回应；精力 `-8`、清洁度 `-2`、互动指数 `+3` | 每日前 3 次给 4（按心情倍率结算），之后仍可玩但不再给进度 | 不新增用户操作 CD；次数只属于毛线球 | 复用毛线球动作 |
| 逗猫棒消耗品陪玩 | 消耗 1 件；用户主动触发且猫有真实回应；精力 `-10`、清洁度 `-2`、互动指数 `+5` | 8（按心情倍率结算） | 当前动作每日上限 3 次；与毛线球不共享次数，新增玩具另行定义自身规则 | 专用 `play_teaser_wand` |

- 没有回应、用户取消、动作失败或超时，都不增加进度；逗猫棒只在服务确认成功后扣除。
- Cat Mind 自主发起的玩耍不计入养成陪玩进度；毛线球每日前三次计进度，之后仍可玩但不再计进度；逗猫棒使用自己的服务端每日次数上限。不同陪玩类型使用独立配置，不存在“所有玩具共享三次”的规则。
- 梳毛的状态恢复、互动变化和成长进度分别结算。每日成长次数到达上限后仍可在 CD 结束后继续梳毛，不会把“进度限流”误做成“动作每天只能使用一次”。
- 清洁类别中的梳毛操作、陪玩类别中的逗猫棒使用，与猫反馈动作是两个字段；当前梳毛仍复用伸懒腰表现，逗猫棒已经使用独立 `PlayTeaserWandAction`。后续替换具体表现或增加其他清洁、陪玩内容时不改变类别边界。
- 生病时仍可清洁和完成求药任务；生病期间禁止探索。赌气状态以互动恢复为主，不额外改写 Cat Mind。

## 4. 每日任务与基础物品

- 每个服务日按服务配置生成独立任务项。小鱼干领取项和毛线球进度项都可以是每日刷新任务，但任务类型、数量、周期和总产出不在前端固定；小鱼干只能从配置的奖励任务获得。
- 任务内容先使用不依赖宠物状态的短操作，例如整理桌面、查看一封信、完成一次指定互动；避免用户必须先有食物才能获得食物。
- 小鱼干初始库存为 `0`，首日先完成任务再喂食；测试配置可以给 `2` 条种子用于快速验收。
- 每日登录确认增加一档独立的整数进度，每个服务日只记一次；当前候选服务日边界为 `Asia/Shanghai 00:00`，由服务端配置 revision 统一决定。
- 任务完成、奖励领取和每日登录都使用幂等请求；任务资源不受心情倍率影响。

### 4.1 当前候选任务配置

当前候选配置使用一条可配置的每日打工任务：用户执行“整理桌面”短操作，服务先把本服务日的 `daily-work` 从 `active` 确认为 `completed`；随后用户单独领取，服务才发放 `1` 条小鱼干并把任务记为 `claimed`。完成操作本身不发奖励、不增加养成进度，也不能绕过领取步骤。另一条 `daily-yarn-play` 只由用户主动毛线球互动的真实猫回应推进 `0/3`，不可领取且没有任务奖励。每日登录是账号活动结算，不属于任务集合，也不完成或领取打工／毛线球任务。三条链路不能互相代替。任务文案、数量、周期、奖励物品、目标和数值仍是候选配置，后续通过运营配置 revision 调整，不在前端写死。

- 当前候选服务日按 `Asia/Shanghai 00:00` 切换；这是服务端 revision 的全局配置，不由客户端时区或账号自报区域决定。已有激活 revision 后若要改变边界，必须配套显式数据迁移。
- 每日登录初始使用 `+4` 点进度，每个服务日只确认一次；该数值仍可编辑。
- 当前候选解锁目录使用下表的 2 个项目（阈值 `10/140`）；它们仍是可调试的候选配置，不是产品合同。后续内容必须先具备真实消费入口，再通过新的配置 revision 增加。
- 任务和每日登录不受心情倍率影响；小鱼干喂食仍只恢复饱食度，进度增量保持 `0`。

## 5. 进度与当前解锁项

### 5.1 进度来源

| 来源 | 基础进度 | 备注 |
| --- | ---: | --- |
| 喂食（当前仅小鱼干） | 0 | 小鱼干只负责恢复饱食度，不在本候选方案里直接给进度；其他食物未定义 |
| 清洁：梳毛 | 4 | 每服务日第一次按心情倍率结算；其后仍可按 CD 梳毛并恢复清洁度 |
| 毛线球陪玩 | 4 | 每日前 N 次用户主动且猫有回应才计，按心情倍率结算；之后仍可玩但不再计进度 |
| 消耗品陪玩 | 8 | 道具数量和服务端每日次数上限共同限制使用，按心情倍率结算；不与毛线球共用进度值 |
| 正常完成探索 | `mood_adjusted(20) + 4` | `+4` 是完整完成奖励，按出发时心情一次结算 |
| 强制召回 | `floor(mood_adjusted(20) × 完成比例)` | 不享受完整探索奖励；向下取整，避免未完成比例被四舍五入放大 |
| 每日登录 | 4 | 每服务日一次，不受心情倍率影响 |
| 打工任务 | 0 | 只发小鱼干，避免任务和进度重复结算 |

### 5.2 首版解锁清单

以下名称和功能本轮直接作为首版初始内容；阈值仍进入统一配置，后续可替换名称、资源或数值。

| ---: | --- | --- | --- |

## 7. 离线结算与负面状态

这是候选公式，目的只是先把“多个数值 + 离线时间”的关系跑通。

### 7.1 共同规则

- 只在服务收到新的、经鉴权的账号活动时，结算上一次已验证账号活动到本次活动之间的区间；持续登录不等于持续在线，猫形态在家、离场或未显示也不单独划分账号离线段。系统不新增宠物层在线状态，也不靠前台心跳或客户端时钟判定离线。
- 候选触发门槛为离线 `48` 小时；当前合同只规定负面状态的行为边界，这个门槛仍可调整。
- 同一离线段只抽取一次；生病和赌气可以同时存在，各自按对应恢复任务处理。
- 如果补算后的饱食度、精力、清洁度和心情都至少为 `35`，本次保证不触发。按当前 `48` 小时门槛和每小时 `-1.25` 的饱食／清洁衰减，满状态离线 48 小时后两项仍为 `40`，保留一段非零保护窗口；该阈值仍是可调试候选值。
- 恢复任务统一经过 `active → completed → claimed`；完成操作本身不发物品，用户领取成功后才把恢复物品写入库存。负面状态判定不会直接塞入库存。

定义：

```text
time_factor = clamp((offline_hours - 48) / 120, 0, 1)
satiety_deficit = (100 - 饱食度) / 100
energy_deficit = (100 - 精力) / 100
cleanliness_deficit = (100 - 清洁度) / 100
mood_deficit = (100 - 心情) / 100
```

### 7.2 生病候选概率

清洁度占最高权重，饱食度、心情和离线时长共同影响：

```text
sick_probability = clamp(
    0.02
    + 0.18 * time_factor
    + 0.07 * cleanliness_deficit
    + 0.04 * satiety_deficit
    + 0.025 * mood_deficit
    + 0.015 * energy_deficit,
    0, 0.45
)
```

生病后：猫显示萎靡，探索入口关闭；状态任务“求药”先完成、再由用户领取 1 个药品，使用成功后清除状态。清洁和普通状态读取仍可用。

### 7.3 赌气候选概率

心情占最高权重，离线时长、精力和清洁度提供辅助影响：

```text
sulk_probability = clamp(
    0.02
    + 0.16 * time_factor
    + 0.08 * mood_deficit
    + 0.03 * energy_deficit
    + 0.025 * cleanliness_deficit
    + 0.015 * satiety_deficit,
    0, 0.40
)
```

赌气后：猫表现为不理人；状态任务先完成、再由用户领取 1 根逗猫棒，成功陪玩后消耗并清除状态。生病和赌气可以同时存在：生病仍禁止探索，赌气恢复路径独立展示，不能互相覆盖或提前清除。

### 7.4 进度回退候选

- 连续离线超过 `5` 天后开始回退。
- 每多离线完整 1 天，回退 `20` 点进度。
- 回退下限是最近一次解锁存档点，已解锁内容永不回收。
- 回来时先补算状态，再执行一次回退和一次负面状态判定；重复读取不能重复执行。

## 8. 重试、时间和失败语义

- 每次写操作都有 `idempotency_key`。网络失败代表结果未知，不能据此断言服务没有结算；客户端必须保存原请求正文、幂等键和版本前置条件，以完全相同的请求重试或查询回执，直到取得服务确认或稳定拒绝。成功后返回完整快照、操作结果和奖励信息。
- 召回首次被服务接受时记录 `recall_accepted_at`；同一活动和幂等键的重试沿用第一次结果，不按迟到响应时间重新计算。
- 强制召回比例为：

```text
completed_ratio = clamp(
    (recall_accepted_at - exploration_started_at) / exploration_duration,
    0, 1
)
```

- 客户端不能自行提交一个未来时间来提高奖励；服务使用自己的活动开始时间和首次接受时间。用户看到的“操作时间”以这两个服务时间点为准。
- 召回失败时不展示未确认奖励。统一返回模型可以完成表现收尾，活动和猫窝状态保留，用户恢复连接后继续重试。

| 每日一次基础照料，不陪玩、不探索 | 第 2 天解锁猫窝信箱，第 18 天解锁撸猫；第 60 天进度 `486` | 只照料也能缓慢成长，不要求一直开着应用 |

| 陪玩对抗探针 | 毛线球 12 次均可回应，但总进度只来自自己的前 3 次；逗猫棒第 4 次起触发自身每日上限 | 两种陪玩分别限流，不存在所有玩具共享 3 次的规则 |

| 满状态离线 48 小时 | 补算后饱食／清洁均为 `40`，命中保护条件，不触发负面状态 | 符合“状态特别好时一定不触发”，也不要求应用常驻 |

阈值灵敏度探针中，撸猫阈值 `135–145` 都在正常每日参与的第 7 天达到，`150` 延至第 8 天；当前取整为 `140`，并保留约 `6` 点余量。猫窝信箱的 `10` 表示进度阈值，不表示使用天数。这组结果只证明候选在当前行为模型下可以形成闭环。正式数值仍需用隔离账号的实际操作频率、探索选择率和 7／30／60 天留存数据调试，不能因为模拟通过就写成产品合同。

### 9.1 仍需审阅的地方

1. `48` 小时和每日服务日时区仍是候选配置；负面状态只跟两次已验证账号活动之间的服务端区间结算，不用猫形态是否显示或前台心跳替代账号活动事实。
2. 心情倍率作用于梳毛成长进度、陪玩进度和探索进度；当前单件逗猫棒掉落不做会把低心情结果向下取整为 0 的数量缩放。首版小鱼干喂食不增加进度，任务小鱼干和每日登录不受倍率影响；其他食物未定义。
3. 每日任务数量、梳毛 CD／成长次数和当前 2 个解锁阈值用于跑通候选循环；不新增喂食或逗猫棒道具 CD。毛线球只限制自身前 N 次成长，逗猫棒只使用自身次数上限。
4. 梳毛暂用伸懒腰反馈；逗猫棒已接入 `PlayTeaserWandAction`；撸猫使用 `cat1_petting` 客户端动作且不进入陪玩租约。这些表现映射仍可独立替换，不改变长期结算边界。
