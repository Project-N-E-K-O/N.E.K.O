# 自定义 ASR 接管后的语气信息丢失（后续 PR）

> 状态：待处理。前置工作是 issue #3666（自定义 ASR）落地，本文记录那个 PR 刻意不处理的遗留问题。

## 背景

issue #3666 新增“自定义 ASR”槽位（API Key 设置 → 按功能单独指定模型 → 语音识别）。规则是：总开关
`enableCustomApi` 打开且 `asrModelUrl` 非空时，自定义 ASR 覆盖 Core 自带的 ASR，对所有 Core（包括 free）都生效。

接管后，实时语音的链路从

```text
麦克风 PCM -> Omni（自己听 + 想 + 说）
```

变为

```text
麦克风 PCM -> SmartTurn 断句 -> 自定义 ASR（/v1/audio/transcriptions）-> 文本
           -> _submit_core_voice_turn -> Omni 文本轮次（想 + 说）
```

文本注入点：`main_logic/core/asr_runtime.py` 的 `_submit_core_voice_turn`
（`submit_external_voice_turn` / `create_response(text)`）。

## 问题

Omni 只收到转写文本，丢失了原始音频里的副语言信息：

- 语气、情绪（开心、不耐烦、哽咽）
- 语速、停顿、犹豫
- 音量、强调
- 笑声、叹气这类非词汇声音

结果是角色回复缺少“听出你情绪”的感知。这一点和现有的“独立 ASR”模式完全一样，不是自定义 ASR 新引入的；
但自定义 ASR 会把这条链路带给更多用户，包括 free 版用户，所以值得单独处理。

## 第一个 PR 里的处理

- 不修复，只在 ASR 槽位的提示文案里说明：“使用自定义语音识别时，AI 收到的是文字，听不到语气”。
- 不做任何回退：自定义 ASR 失败时报错，不偷偷切回 Omni 原生识别（原因是隐私）。

## 后续可选方向（待评估）

1. **转写附带副语言标注**：如果 ASR 服务返回情绪、事件标签（例如 SenseVoice 一类模型的 emotion/event 输出），
   就以结构化前缀附在文本轮次上，如 `[语气: 不耐烦] ...`。需要确认 OpenAI 兼容响应里的扩展字段约定。
2. **本地轻量情绪分类**：在 SmartTurn 段上跑一个本地情绪或韵律模型，把结果作为轮次上下文注入，
   与 ASR 服务能力解耦。需要评估模型体积和 CPU 开销（参考 speaker_shadow 的 ONNX 资产管理方式）。
3. **音频旁路**：对支持音频输入的 Omni，把同一段音频和转写文本一起发送，让模型自己听语气，文字只作参考。
   这和“声音不出局域网”的隐私诉求冲突，只能作为用户可选项，默认关闭。
4. **只做提示**：在 Omni 的系统提示里说明“输入来自语音转写，可能缺少语气”，让回复别过度解读文字。成本最低，可以作为兜底。

## 待决定

- 先做哪个方向（建议先做 4，再评估 1 和 2）。
- 副语言信息的注入格式，要和 `turn_context` 现有结构对齐。
- 是否需要按 Core 区分（有的 Omni 不支持文本轮次附带额外上下文）。
