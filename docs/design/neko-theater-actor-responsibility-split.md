# 小剧场 Actor 与叙事提案职责拆分

状态：本轮已实现 Actor 写作与叙事提案的职责分离，程序检查完成。本文记录方案与实现边界；真实回合、质量、容量和时延结论以仓库外验证报告为准，程序检查通过不代表演绎质量达标。当前总体合同见[小剧场架构](./neko-theater-architecture.md)，决策见[设计决策 D-57](./neko-theater-decisions.md#d-57-独立叙事提案职责本轮实施边界)。实验输入、响应、报告和失败样本保存在仓库外。

## 讨论收口

公开演出、推荐输入和动态账本具有不同职责。公开演出负责回应玩家并推动当下叙事；推荐只是玩家可以选择的未来输入；叙事提案负责从本轮真实输入和已经生成的候选中记录发生了什么。把职责分清不等于必须拆成独立模型调用，拆成独立调用也不等于放到后台。

本轮选择把叙事事件提案移到独立调用。公开正文、旁白、动作与推荐继续由同一次 Actor 生成；不拆推荐，不逐段生成转场，不提前生成未选分支。Actor 继续读取已提交动态账本来维持状态，但不再输出事件表，也不负责为自己的正文判定入账完整性。

已有纯校验只能检查提案里的形状、引文、归属引用和批准范围，不能自动发现从未被提案的关键变化。现有 Review 已有覆盖完整性的职责，本轮把提案生成从写作中分离；不把字段合法、Review 放行或程序测试通过解释成完整回合质量通过。

## 职责与权限

| 阶段 | 负责内容 | 权限边界 |
| --- | --- | --- |
| Evaluator | 根据本轮输入与已提交历史判断幕完成信号、换幕意图、结局就绪、原有数值依据及完成事实候选；按需提出历史查询 | 不生成公开演出或叙事事件，不直接换幕、批准或提交候选 |
| Actor | 同次生成公开正文、旁白、动作、推荐及原有提议信号和完成事实候选；读取已提交账本 | 不生成叙事事件表，不判断入账完整性，不提交状态 |
| `NumericV2NarrativeProposer` | 仅从本轮玩家原话和冻结候选各阶段的实际正文提取叙事事件；已有状态与历史只作核对参考 | 不把历史重新提为本轮事件，不改稿或回答玩家，不判换幕、幕完成、审批或入账 |
| 现有 Review | 核对本稿正文、推荐、原有完成事实候选及冻结事件编号，判断是否漏掉关键变化 | 叙事事件只批准或拒绝冻结编号，不补造叙事事件；完成事实与固定旁白沿用原复核权限，不提交状态 |
| Workflow | 编排既有调用、冻结同稿提案、同稿复用和改稿失效，转交复核与提交 | 缓存不构成批准，不将旧稿事件或批准转用于新稿，不采纳 Actor 自报的叙事事件 |
| Runtime / Store | 按既有引文、阶段顺序和批准范围派生视图并原子提交 | 原子事务、旧记录重放、缺口和持物交接保护不改 |

叙事提案继续使用现有事件字段、受限属性、主体引用、原文引文、阶段和认知范围，不改变事件 Schema。正式完成事实、数值与换幕授权仍由原链路处理；叙事提案不接管这些判定。

`fact_candidates` 是剧本完成合同中的候选事实，`narrative_events` 是本轮位置、持物、行动、承诺等变化的叙事提案，两者不互相替代。Actor 只为自己本轮实际演出的合同结果提出前者；Evaluator 只为本轮输入或已提交 Runtime 场景事件支持的合同结果提出前者；按原链路校验和确认，启用 Review 时须获其确认。Review 仍可按既有完成合同补提事实候选，但不能补提叙事事件。不能因为移除了叙事整理职责，就顺带删除完成事实合同或让叙事 `stage_result` 决定幕完成。

Actor 继续读取已提交账本及原始历史，这属于写作时承接事实，不是整理账本；其提示词明确该投影只作写作依据，不生成叙事事件或更新账本。公开演出中的状态可以按真实新变化推进，不能把这项写作职责理解为直接改存档。其输出和补推荐不生成叙事事件表，解析链路对旧输出额外携带的事件表仍兼容接收并丢弃。

提案器的提示词仍复用共享行动与历史规则，职责收窄尚未完成。替换时须保留日常行动表达、必要前提、意向与完成、主体归属、原文出处和历史先后语义，并通过冻结同输入的跨题材验证；不能仅凭删除演出与换幕要求或减少 Token 就认定提取质量改善。

## 同步兼容调用顺序

以下顺序保留给初始开场和未启用后台模式的内部调用；HTTP 输入回合使用后文的首字优先交付。

```text
真实玩家输入与已提交 Session
  → Evaluator → Runtime 候选
  → Actor 同次生成公开演出和推荐
  → 原有确定性检查与候选准备
  → 仅在该候选实际进入既有 Review 前：冻结候选并生成叙事提案
  → 现有 Review 审核同稿正文、推荐和提案
  → 原有身份、revision 与提交检查
  → Session、Ledger、表现记录、事实和叙事视图原子提交
  → 返回公开内容并按现有协议进入 TTS
```

候选正文或旁白（含固定旁白与转场分段）发生变化后，须对新稿重新提案，不能把旧稿正文事件或批准转用到新稿。仅推荐变化不改变账本提案，但新推荐仍须进入现有 Review；不能沿用旧推荐批准。同稿因既有流程重复复核时复用本稿提案，不为同一稿重复提案。提案缓存只属于本次回合，提案没有提交权，仍须经现有 Review 和 Runtime 校验。

叙事提案的超时、模型不可用、输入超限、输出格式或逐阶段引文错误按辅助模块失败降级：本稿不携带事件表，仍须经过原有正文、旁白与推荐 Review，通过后才原子提交并交付。失败不能伪装成成功的空表；现有记录标记 `unrecorded`，若保留了本轮原话中已获准的玩家事件则为 `partial`，旧属性继续按 `last_known` 投影。失败原因写入日志、trace 和回合诊断，同稿复检复用失败结果，不增加重试调用；新正文按新稿重新提案。取消请求、正文生成、正文 Review 与存储失败不由该降级吞掉，仍保留原子回滚与现有重试入口。

若提案成功但 Review 在发送前装箱超预算，撤下本稿事件表及其关联审批要求，缓存同稿缺口，再完整审核同一正文、旁白和推荐；已提交账本、玩家原话、作者合同和最新完整历史仍保留。预算降级与提案失败分别记录，成功空表也不能在撤下后冒充已确认无变化。Review 最终装箱仍超限时可只省略状态投影的属性重复引文并累计 `quotes_omitted`，保留全部值、来源编号、近期事件和原账本。无表仍超预算或真正的审核请求失败继续回滚；同稿不重新提案，新稿重新提案，既有已审玩家原话事件仍按 `partial` 收口。有复核的开场沿用同一处理，不增加成功模型请求或后台任务。

漏判转场补救的 Actor 生成或结构检查失败时，可复用此前已完整复核的同一普通事务；原稿正文和邀请须合法且无待触发固定旁白，保留原稿获准事实与叙事事件，经原有校验和原子提交交付，错误推荐整组撤下。不提交失败转场内容，也不新增调用；正式转场审核、取消及存储失败仍回滚。

没有实际 Review 调用就不调用提案器，也不能将未审事件自确认为 `current`。开场原本不复核时，不因本次拆分增加提案或 Review。已有账本仍可供 Actor 读取；本轮没有确认覆盖时继续沿用缺口与 `last_known` 语义。

普通六块与正式转场 Actor 在原有历史淘汰后仍超预算时，仅省略动态状态投影的属性重复引文并累计 `quotes_omitted`；值、来源编号、近期事件、玩家原话、合同、最新完整历史及原账本不变。仍超限则拒绝发送，不抬高上限或新增调用。

## 模型、容量与等待

| 项目 | 本轮约束 |
| --- | --- |
| 正式模型 | `conversation` 配置槽，`qwen3.8-flash`，`enable_thinking=false` |
| 提案输入上限 | 8500 Token |
| 提案输出上限 | 1000 Token |
| 提案 timeout | 12 秒 |
| SDK 自动重试 | `max_retries=0` |
| 常规启用复核回合 | 同步兼容路径 4 次；HTTP 路径前台 3 次、后台 2 次，共 5 次；既有按需分支另计 |

Actor 和 Review 的既有预算保持不变；各调用预算汇总见[LLM Prompt 预算](./llm-prompt-budget.md)。输入必须包括本轮玩家原话和完整待审候选，不能为卡进预算而中途截断原话、正文或事件证据；输出临界或不完整时，也不能把截断内容当成完整提案或完整回合。容量与新增等待成本需要实际测量，不预先承诺提速或更高合格率。

## 同步兼容路径与共同边界

同步兼容路径保持完整回合审核、提交后交付，不在后台补账本。HTTP 路径已实施下节的首字优先交付：正文审核并提交后，后台提案、独立复核和结算账本。两条路径都不展示未审核正文，不新增正文复核层，不迁移数值或完成事实判定。

## HTTP 输入回合：首字优先交付

用户选择以常规调用从 4 次增至 5 次，换取正文复核通过后立即交付。Evaluator、Actor 和正文/推荐/固定旁白 Review 仍在同步链路；只把最终已提交正文的叙事提案及独立账本复核放到后台。正文改稿不再重复提案。未开启 Review 时不新增账本调用，开场沿用原流程，TTS 仍只读取已提交的公开内容。

正文事务先原子提交 `unrecorded` 账本记录和 Ledger 尾项的 `narrative_pending` 标识；旧状态按既有缺口语义退为 `last_known`。后台只处理该回合实际交付的完整分段，用独立调用审核编号事件及覆盖完整性，不能改正文、推荐、完成事实、路线或数值。账本复核输入上限 8500 Token、输出 150 Token、单次时限 12 秒；提案与复核共用 24 秒后台额度，不重试。

后台落盘再次检查正文指纹、剧情 revision、生命周期、结束状态和遗忘水位，沿用存储写栅栏与故事锁。Ledger 记录、表现记录中的账本副本及重放后的 Session 投影在同一次原子写中更新，公开正文保持一致。重复完成无操作；结束、恢复、遗忘、删除或后续回合使旧结果失效。

下一轮准备前至多等待后台模型 1 秒；未完成则取消并将待整理标识封口为明确缺口，继续使用已提交原文历史。后台失败或进程重启后遗留的待整理标识也按同样规则封口，不重试模型，不将旧状态当作当前事实。原子文件写入仍须完成，1 秒不是磁盘事务的硬超时。后台调用使用独立用量与 trace 作用域，不修改已经返回的 HTTP 用量列表；HTTP 用量只表示同步请求调用，后台成本由独立 trace 记录。

服务端正文返回时间、浏览器首个可见字符时间、后台完成时间和下一轮等待分别验收；不能用打字速度、整回合总耗时或算术减去提案耗时替代首字测量。

## 验收与未确认项

程序检查应覆盖职责隔离、同稿冻结与复用、改稿失效、无 Review 不调用、预算边界、提案失败以及原有回滚和重放保护。随后在至少两种题材中运行真实完整回合，按交付正文、旁白、推荐、事件覆盖、持有者与最终状态共同验收。

职责拆分的实现门槛与完整回合质量分别记录。实现门槛通过且没有拆分引入的回归，可以保留已验证的分工；原有 Evaluator/Review 事实误批等问题仍使相应完整回合不合格，独立记录，不能用架构通过掩盖，也不自动扩展本轮修复或撤销不相关分工。没有同轮真实 baseline 的两回合，不能证明因果收益。

最终装箱仍超限时，普通 Actor 可将最新完整角色原文中确证保留的待确认邀约副本改为 `story_so_far` 引用，撤下邀请、仅旧索引或玩家原话中出现的文本不适用。Review 的公开去向表若与最新完整回合全部对白/旁白逐字一致，也可用明确引用替代副本；程序核验仍保留原始引文表。状态、完整候选与最新历史不删减，不新增调用或职责。

轻微且顺着玩家意图的演出补足可接受；擅自改变玩家位置、持有物、任务结果、选择、承诺和关系立场仍不可接受。少提案、错误提案或误判完整性不能靠程序测试通过掩盖。两题材局部验证通过后才考虑整路线压测；没有新的完整路线结果，就不声明约 90% 质量目标达成。真实回合、质量、容量和时延结论以仓库外验证报告为准。
