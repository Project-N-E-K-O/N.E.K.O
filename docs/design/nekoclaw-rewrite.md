# NekoClaw（猫爪）重写设计

状态：已批准方向的提案。第 16 节的第 1 个 PR（内置运行时，`nekoclaw/runtime/`）、第 2 个 PR（宿主新部件，`nekoclaw/host/`）、第 3 个 PR（接主对话）和第 4 个 PR（键鼠与浏览器，`nekoclaw/builtin/`）已实现，落地时的出入分别见 8.9、6.9、6.10 和 11.9 节；其余尚未实现。写于 2026-11-11。同日修订：派工部分改成「任务大脑」方案（第 2、4、5、6、10、12 节相应改写），原来「主对话自己记委托号、每件事都开使魔」的写法作废。

本文是重写 agent 模块（界面名 NekoClaw / 猫爪）的设计稿。「已定」的条目是 owner 拍过板的，实现时不再重新讨论；「待定」的条目在第 15 节集中列出。代码落地后以代码和测试为准。

**术语对照**（2026-11-12 定，其余叫法见第 3 节）：

| 说法 | 指什么 |
|---|---|
| 使魔 | 界面叫法。代码里叫 task agent（`task_agent`、`TaskAgent*`、`TASK_AGENT_*`），即替她办一件事的执行会话。本文说「使魔」时，在代码里都对应 task agent |
| agent runtime | 运行 task agent 的那一层（`AgentRuntime`，`nekoclaw/runtime/`）：内置运行时，或可选的 dsh |
| harness | 移植自 dsh 的内部循环（`AgentHarness`，子类 `SessionHarness`），在 agent runtime 里面 |

「使魔」只用在界面文案（八种语言）和她说给用户的话里；后端代码、注释、日志、协议和发给模型的提示词里都写 task agent，不写 familiar。

## 1. 为什么重写

现有模块约 3 万行（`app/agent_server/`、`brain/`、主服务侧接线、前端面板），主要问题：

- 每轮对话结束后另起一次分析，0 到 5 次模型调用，全局一把锁，慢而且贵；主对话模型自己不知道有没有派工。
- 四个执行通道（插件、OpenClaw、浏览器、键鼠）各写一套登记、执行、回报，没有共同接口。
- 任务表是无类型 dict，没有状态机；取消大多不生效；结果回传失败只打 debug 日志。
- 没有「一个会话持续干一件事」的形态，复杂任务做不了。

## 2. 已定事项

| 事项 | 结论 |
|---|---|
| 总体形态 | 主对话只管说话和派发；记账、路由、汇报归常驻的任务大脑；干活的是插件入口和使魔 |
| 主对话的上下文 | 约每 10 个用户轮次换一次会话，近期历史只留 10 条消息加一段摘要。凡是要它记住的东西（委托号、进度）都记不住，所以任务的记录不放在它那里 |
| 派工方式 | 主对话有两个工具：派发、查询，都是一句自然语言，不带编号。由决策模型路由：插件优先（插件快），选不中或要多步才开使魔 |
| 派发的回执 | 派发可以等，但只等第一轮初步决策就返回（已在做 / 没有相关能力 / 受理），不等执行结束 |
| 她没派发时 | 旁听检查兜底。执行权只跟着她的话走：她派发了，或口头答应了，才立案；她说不做就不做 |
| 改口 | 她先说、判断在后，说错了就改口。可以接受，但要迅速、自然 |
| 消耗 | 不因多一次判断而增加延迟或 token；有增加必须 owner 拍板。已拍板接受的见 6.8 节 |
| 开场提示 | 不加能力简报（容易出戏）；只保留一句，并要求调用任何工具前先说一声 |
| 决策模型 | 可替换的接口。现在用关键词、BM25、小模型粗筛加一次精选；将来要能换成 jev 类模型 |
| 任务偏好 | 要记，由任务大脑管，和台账流水分开 |
| 自己写插件、改设置 | 将来她要能给自己写插件、改自己的设置，方案要可靠、高效、开箱即用地支持（12.3、12.4 节） |
| 底座 | 插件宿主升格为底座，名字叫 NekoClaw（猫爪），不叫 agent |
| 键鼠、浏览器 | 是内置能力，只有执行会话能调，不再和插件平级当通道 |
| 旧插件 | 必须原样兼容：`/runs` 协议、`push_message`、`@llm_tool`、投递语义。旧 agent 代码不用兼容 |
| OpenClaw | 已退环境，不接，相关代码全删 |
| 执行会话的运行时 | 两个。内置运行时必须有；dsh 可选，用户在猫爪控制台里下载，装了就替代内置的 |
| 内置运行时的来源 | 只拿 tau 的核心循环包 `tau_agent`（MIT，约 2600 行）放进本仓库自己维护。不 fork 整个仓库，不跟上游 |
| 工作记忆 | 独立建库，按用户一份，叫使魔空间；按项目归档经验和反思 |
| 使魔的权限 | 默认首次询问；之后都能在猫爪控制台里改 |
| 子使魔 | 使魔可以再派使魔 |
| 并发 | 同时干活的使魔上限默认 10 |
| 提示词和自带工具 | 尽量照抄 dsh 调校过的提示词、工具名、参数和说明（dsh 是 MIT 许可） |
| 向 dsh / Codex 看齐的机制 | 长命令转后台、多级上下文管理、待办与续跑、读图、改文件的宽松匹配、网页搜索、只读工具并行，都做 |
| 系统级沙箱 | 先不做 |
| 浏览器 | 尽量用用户自己的浏览器；不再随包带浏览器；用户没有可用浏览器时用外面的 Electron 壳。登录状态默认用独立资料目录，控制台里可切换成接管正在用的浏览器 |
| 键鼠和浏览器的形态 | 各是一组细粒度工具，由使魔自己一步步驱动，同时给内置运行时和 dsh 用 |
| 约束 | 快、不阻塞前台、性价比 |

明确不做的：`recall_work_memory` 工具（暂时不做）；本体读使魔空间的规则（回头再说，只留位置）；界面上不出现 skill / 技能书。

## 4. 整体结构

```text
她（主对话）
   │ 派发 / 查询（工具调用，一句话，不带编号）      ▲ 汇报、改口提醒（唤醒她 / 下一轮带上 / 只记下）
   ▼                                                │
猫爪宿主（现在的 agent 进程重写而成，插件服务仍在其中）
   ├─ 任务大脑        常驻：委托台账、任务偏好、能力清单、决策模型、旁听检查
   │     ├─ 一步能办完        → 直接调插件入口（走现有的 /runs）
   │     └─ 选不中或要多步    → 开使魔
   ├─ 使魔管理        要开使魔才拉起运行时，一个委托一个会话，同时最多 10 个，空闲就关
   ├─ 驱动接口        派活 / 插句话 / 追加 / 叫停 + 一串事件
   │     ├─ 内置运行时驱动   （子进程，Python）
   │     └─ dsh 驱动         （子进程，装了才有）
   ├─ 能力网关        把内置能力、旧插件入口、MCP 工具统一成一套工具，两个运行时共用
   └─ 使魔空间        开工时取，收工后写
```

进程形态不变：源码运行是多进程，打包版三个服务同进程，Docker 直接起 agent 进程。端口 48915（宿主）和 48916（插件服务）不变。

主对话模型只决定「要不要办」并说出来。「谁来办」由任务大脑定：插件优先，一步能办完的直接调插件入口，不开使魔；选不中或要多步才开使魔，使魔再自己定用什么能力。任务的记录全在任务大脑里，主对话换多少次会话都不丢。

## 5. 委托台账

一个 SQLite 文件，`<数据根>/nekoclaw/ledger.db`，只有宿主写。

- `commissions`：委托号、所属角色、标题、她派发的原话、用户原话、来源（她派发 / 她答应后代派）、路由（插件入口 / 使魔）、项目、工作目录、状态、用的运行时、起止时间、结果摘要、等用户回答的问题、投递方式、父委托号。
- `events`：委托号、序号、时间、类型、内容。使魔的每个事件追加一行，委托板靠它回放。
- `outbox`：要发给主服务的汇报。先写这张表再发送，发送失败按退避重试，成功后标记。现在「结果发丢只打日志」的问题由它解决。

状态只能按第 3 节的表迁移，迁移函数是唯一入口。「已叫停不可被覆盖」在迁移函数里判一次。

委托号和插件的 Run 编号合并成一套：直达插件入口或使魔调插件时，Run 都记在该委托名下。

台账是任务大脑的记忆。主对话的上下文留不住任务记录（见第 2 节），决策模型也不靠自己的上下文记事，每次判断都从台账现取。

### 5.1 任务偏好

事情怎么办的长期交代。和台账流水分开存（同一个库里的 `preferences` 表），归任务大脑管。

- 记什么：同类事用哪个能力、默认参数（城市、保存位置）、办完怎么汇报、哪些事必须先问。
- 谁写：
  - 她经派发工具转述的明确交代，立即生效。
  - 从「被叫停、被纠正」里推断出来的，同一倾向出现两次才生效，并标「推断」。使魔用 `note_lesson` 提交的 `feedback` 也按这一条处理。
  - 用户在猫爪控制台里直接改。
- 谁读：决策模型精选时带上相关的几条，上限 150 token；开使魔时写进交代里。
- 和别处的分工：
  - 本体记忆管「他是什么样的人」，任务偏好管「事情怎么办」，互不读写。她知道的事由她写进派发那句话。
  - 权限是代码强制的开关，偏好只是给模型看的指引，不能用偏好放开权限。

### 5.2 能力清单

任务大脑和能力网关共用的一份登记：插件入口、内置能力、MCP 工具、设置项。每项带说明、参数、风险级、是否一步能办完。

- 不落库，从插件注册表、内置能力和用户配置现算；插件启动、停止、重载、安装、删除时刷新。
- 可见性沿用现有开关：`passive = true` 的插件，以及 `metadata` 里 `agent_auto` / `agent_exposed` / `llm_exposed` 为 `false` 或 `agent_hidden` 为 `true` 的入口，不进清单。
- 任务大脑直达插件入口，和使魔经网关调插件入口，走同一段代码，都是发一个现有的 `/runs` 请求。

## 6. 派发、查询与汇报

### 6.1 她这边：两个工具

主对话的工具注册表（`main_logic/core/tool_calling.py`）新增两个工具，参数都只有一句自然语言，不带编号：

- 派发（`dispatch_task`）：把对话之外要动手的事交给任务大脑。新的事、补充、改主意、叫停、回答使魔的提问都从这里说，说的是哪一件由任务大脑对着台账判断。
- 查询（`query_tasks`）：问现在在办什么、某件事办得怎样（办完的也能查）、某件事能不能办。

配套约定：

- 开场提示里讲「对话之外的操作」的那句话改短，规矩改成「要动手的事只能通过任务工具去办；没有工具结果时不声称已经开始或完成」。不加能力清单，她能不能办某件事靠回执和查询回答。
- 提示词要求她调用任何工具（回忆、派发、查询）之前先说一声。现在的回忆工具没有这样的垫话。
- 模型没照做时就是硬等。聊天窗口用现成的「…」气泡表示处理中（现在只在凝神模式用，后端发 `focus_thinking` 消息驱动）：调用开始点亮，她开口就熄灭。
- 固定开销有上限：开场那句加两个工具定义，中文合计不超过约 221 token（现在那句话是 97），用测试守住。主动搭话的生成请求不挂这两个工具；由会话自己发出的临时轮次怎么算，见 6.10 节。

### 6.2 派发：只等第一轮

| | 做什么 | 耗时 |
|---|---|---|
| 第一轮：初步决策（等） | 查重；用关键词和 BM25 看有没有候选插件；使魔可不可用 | 本地，毫秒级 |
| 第二轮：精选与执行（不等） | 在候选里选入口、填参数、发起执行；选不中或要多步就开使魔 | 后台 |

- 回执是三种之一：已在做（附那一件的状态）、没有相关能力（附原因：没装、装了没开、权限禁止）、受理。
- 唯一多等的情况：本地没找到候选、使魔又不可用。这时等一次小模型粗筛（几百毫秒）再说「没有相关能力」。
- 上限约 1 秒，超时回「收下了」。
- 第二轮推翻了第一轮（受理了却没有合适的入口，或其实是重复），当场提醒她改口，见 6.5 节。
- 叫停、补充、回答提问：回执相应是「已叫停某件」「已转告」；对不上是哪一件时，列出候选让她问清。

第二轮的规矩：

- 插件优先于使魔。先在插件里选；选不中、或这件事要多步，才开使魔。「要不要给使魔」由精选那次调用顺带判断，不另花一次。
- 精选还可以答「办不了」（`route="none"`）：插件入口办不了，使魔靠读写文件、运行命令、改系统设置、上网、操作浏览器和键鼠也办不到，或者根本不是一件要去办的事。这时不开使魔，按 6.5 节提醒她改口。拿不准时交给使魔，不选「办不了」（owner 11-12 定）。
- 精选答了不存在的插件或入口时不追问，直接交给使魔；使魔不可用就按办不了处理（owner 11-12 定）。实测 157 个点名插件的回答里一次都没写错标识符，而追问拦不住「入口存在但选错了」这种真会出事的错。
- 两级筛选保持现在的宽度：全部插件描述超过 3000 token 时先粗筛（关键词命中、BM25 前 10 名、小模型粗筛三者取并集），再精选；不超过就直接精选。`short_description` 和 `keywords` 的用法不变。
- 精选的输入：她派发的那句话、用户原话、台账里相关的两三条、相关的偏好（上限 150 token）、候选插件的完整描述。不再带最近 6 条对话。
- `args._ctx` 照旧注入 `lanlan_name`、`conversation_id`、`entry_timeout`，`latest_user_request` 仍是用户原话。`lanlan_name` 总是宿主的值，参数里模型自己写的会被覆盖（第 3 个 PR 起，owner 11-13 定）。
- 入口的 `delivery`、`result_kind`、`expires_in_s`、`llm_result_fields`，以及 deferred、`needs_confirmation`、`clarify` 的现有行为，在直达这条路上保持不变。使魔经网关调插件时不一样（owner 11-12 定）：`needs_confirmation` 由网关直接问用户，`clarify` 和 deferred 加一句说明回给使魔，`delivery` 不起作用，结果只回给使魔。

### 6.3 查询

- 问进展：不调模型，直接从台账取，有 token 上限。问的是哪一件，用关键词和 BM25 匹配。
- 问能不能办：走派发第一轮的同一套本地匹配，不立案、不执行、不调模型。本地找到了候选，或使魔可用时，它的回答和之后真派发的回执一致。
- 唯一的例外是本地没找到候选、使魔又不可用：派发这时会多等一次小模型粗筛，查询不等。所以这种情况下查询不下「办不了」的结论，只回「没找到现成的能力，真要办可以派发试试」。

### 6.4 旁听检查

她这一轮没调派发、而不花钱的信号显示像是要办事时才跑。信号沿用现在的门：输入时小模型给出的外部意图分数不低于阈值，或命中插件关键词。检查是一次小模型调用，读用户这句话和她的回复，结论四选一：

| 结论 | 处理 |
|---|---|
| 没事，或她有意不办 | 什么都不做 |
| 她说做不到，其实办得到 | 当场提醒她，由她自己更正并派发 |
| 她答应了，却没派发 | 替她派发，并告诉她 |
| 她说办完了，台账里没有 | 当场提醒她更正 |

规矩：

- 一轮只有一个判断者。她调了派发，这一轮旁听检查不跑。
- 旁听没有执行权，执行权只跟着她的话走。只有她调了派发、或她口头答应了要办，才立案；她说不做或做不到，一律不执行。
- 主对话模型不支持工具调用时同一条规矩：靠旁听，她答应了才办。

### 6.5 改口

她先说、判断在后，所以会有说错的时候。可以接受，但要迅速、自然：提醒走现有的「唤醒她开口」通道，判断一出就发，只在她说错时发生。

| 情形 | 处理 |
|---|---|
| 她派了，第二轮发现办不了 | 提醒她改口 |
| 她说做不到，其实办得到 | 提醒，她更正并派发 |
| 她说办完了，其实没记录 | 提醒她更正 |
| 她答应了，却没派 | 替她派发，不用改口 |

### 6.6 汇报

- 沿用现有三种投递方式：唤醒她开口（proactive）、下一轮带上（passive）、只记下（silent）。使魔的结构化汇报里带建议的投递方式，任务大脑按委托的设置定最终方式。
- 先写 `outbox` 再发送。
- 换会话时注入「正在办的事」：沿用现有注入点，数据改从台账取。

### 6.7 决策模型的接口

决策模型是任务大脑里可以替换的一块：输入是一句话加候选，输出是结论。它没有自己的上下文，每次调用都从台账现取一份视图，所以不会像主对话那样丢记录。

- 现在的实现：关键词、BM25、小模型粗筛，加一次精选。
- 本地向量模型是可选能力（内存低于 4GiB 等情况会关），只当加速层：可用且第一名明显领先时，跳过粗筛的那次模型调用。
- 将来要能换成 jev 类模型（按目前的理解，指记忆用的 jina-embeddings 那类本地向量模型），接口按这个留。

### 6.8 消耗对照

约束：不因多一次判断而增加延迟或 token；有增加必须 owner 拍板。基线取本机用量记录的平均值（开发机，不代表线上）：文本主模型一次请求平均输入 3.4k 到 5.4k token，分析器一次调用 0.9k 到 1.4k，输入时的小模型约 0.55k。

| 场景 | 现在 | 新方案 |
|---|---|---|
| 聊天轮，被门挡住 | 主模型 1 次 | 主模型 1 次，多带两个工具定义 |
| 聊天轮，过了门但没任务 | 另跑分析器 1 到 3 次 | 另跑一次小模型检查，约 0.6k |
| 任务轮 | 主模型 1 次，分析器 1 到 3 次；她立刻开口，说完才开始分析 | 主模型 2 次（先说一声并发出派发，拿到回执后说正文），精选 1 次（插件多时加粗筛），少一次通道评估 |

owner 已拍板接受的增加：

- 每轮固定多带约 124 token：两个工具定义约 112，加「调用工具前先说一声」这句 12。没开猫爪的会话只多这 12。
- 派发的工具往返：任务轮主模型多跑一遍；模型没有先说一声时，她晚开口一次往返（估计一秒上下，没实测）。

各家模型是先说话还是先调工具、照不照「先说一声」做、工具往返的实际延迟：第 3 个 PR 在免费档位的模型上量过，结果和实测后的消耗对照见 6.10 节；其它厂商没测。使魔每一步的消耗和旧的浏览器、键鼠循环没法直接比，第 4 个 PR 实测。每个 PR 的描述里带一张改动前后的消耗对比。

代码在 `nekoclaw/host/`，各模块的分工见该包的 `__init__.py`。下面是落地时和第 5、6、10 节不一样、或那几节没写到的地方，以这里和代码为准。标了「暂定」的是先按一种做法实现、等 owner 定的。

台账：

- `commissions` 比第 5 节多几列：`conversation_id`、`lang`、`plugin_id` / `entry_id`（直达的入口）、`name`（子使魔的名字）、`deferred_until`、`status_reason`、`updated_at`、`host_instance`。
- 状态迁移表：排队中可以到忙活中、没办成、已叫停；忙活中可以到等你回话、办好啦、卡住了、没办成、已叫停；等你回话可以到忙活中、没办成、已叫停；卡住了可以到忙活中、没办成、已叫停；没办成可以回到忙活中（过程已落盘，可以接着干）；办好啦和已叫停不能再变。不在表里的迁移不抛异常，返回「没生效」并记一条 `transition_refused` 事件。

- `events` 不是「运行时每个事件一行」：连续的文字增量合成一行，同一次工具调用的进度合成一行，单行最多 4000 字符（只给委托板回放用，不进提示词）。

- `outbox` 的行分四种：`task_result`（委托怎么结束的，字段和现在 agent 进程发给主服务的 `task_result` 事件一样）、`question`（委托在等用户回答或批准）、`correction`（第二轮推翻了回执）、`receipt`（第一轮超时后补发的结论）。发送函数由第 3 个 PR 接上；没接时只存不发。发送失败后 1 秒重试，之后每次翻倍，最长 5 分钟。

任务偏好：

- 按用户一份，不分角色；只记下是哪个角色、哪个委托带来的。
- 「同一倾向出现两次」靠词面相似度判断（阈值 0.5），不调模型。

派发：

- 第一轮怎么认一句话是叫停、回答、补充还是重复，用的是词表加和台账的词面比对，不调模型（暂定，等第 3 个 PR 用真实模型的派发语句校一遍）：
  - 叫停：句子里有叫停的说法。只有一件在办、而且句子没提别的事，就停那一件；有多件时按提到的内容对，对不上就列出候选让她问清。句子提到的内容和在办的事都无关（比如「取消明早的闹钟」），当成一件新的事。
  - 回答：有委托在等你回话，而且这句话带回答的说法、或和那个问题有词面重合、或（权限提问时）能读出同意或拒绝。权限提问的回答读成四个选项之一（第 3 个 PR 起，见 6.10 节；第 2 个 PR 时是三种），读不出来就回一条「看不出是同意还是拒绝」，继续等。
  - 重复：和在办的某件事词面相似度不低于 0.7；用户原话一字不差时放宽到 0.4。
  - 补充：句子里有补充的说法，而且和某只使魔在办的委托对得上，就转告给它。插件的 Run 接不了补充，这种句子当成新的事。
- 第一轮超过 1 秒先回「收下了」，结论出来后作为一条 `receipt` 写进 `outbox`。
- 第二轮比现在少一次调用的地方：插件多、粗筛后一个候选都没有时，不再调精选（现在会带着空列表调一次）。没有任何可见插件时两轮都不调模型。
- 精选答了不存在的插件或入口时不追问（第 3 个 PR 按 owner 11-12 的决定删掉了第 2 个 PR 保留的那次追问，见 6.2 节）。
- 精选的提示词是新写的（八种语言），在原来那份的规则上加了「交给使魔」和「其实是重复」两种结论，去掉了原来用来挡闲聊的几条（要不要办已经由她决定了）；固定部分比原来短。粗筛用原来那份，一字没动。精选的输出格式是 `route`（`plugin` / `task_agent` / `duplicate`，第 3 个 PR 起多一个 `none`）加原来的 `plugin_id`、`entry_id`、`plugin_args`；原来的 `has_task` / `can_execute` 写法也认。

查询：

- 一句话算不算「问能不能办」靠疑问句式的词表认，其余都当成问进展（暂定，同上）。
- 查询任何情况下都不调模型。一个插件都没有、使魔也不可用时，查询直接回「办不了」和原因（这不需要模型，派发的回执也是这一句）；有插件但本地没对上、使魔又不可用时，按 6.3 节回「没找到现成的能力，真要办可以派发试试」。
- 问进展最多列 8 件、400 token，每件一行最多 80 token；在办的排前面，24 小时内办完的排后面。只列她自己的、用户能看到的委托，子使魔的委托不列。

使魔：

- 会话号就是委托号。过程文件在 `<数据根>/nekoclaw/task_agents/projects/_daily/sessions/<委托号>/`，和 12.1 节规划的布局一致；委托没指定工作目录时用该目录下的 `work/`（暂定，项目和工作目录的规则随第 5 个 PR 定）。

- 子使魔的结果用「插句话」送回父使魔，所以正在 `wait_agent` 的父使魔下一次请求模型时就能看到。父使魔这段工作结束而子使魔还在跑时，父委托不算办完，等子使魔的结果把它叫醒；父委托结束（办完、卡住、没办成、被叫停）时，还在跑的子使魔一并叫停。

- 「本次允许」只放行发问的那一次调用，同一个委托里下一次同类调用还会问；要整个委托都放行，选「仅本会话允许」（第 3 个 PR 起，见 6.10 节）。类别设成「每次都问」时只给「本次允许」和「拒绝」。
- `note_lesson` 的其余四类先交给一个可替换的接口，默认实现把它们记成该委托的 `lesson` 事件，等使魔空间来接。

- 运行时的 `spec` 多一个 `gateway`（地址和令牌）。运行时从网关取到的工具不经运行时自己的权限钩子，权限在网关入口判。

权限：

- `permissions.json` 里每一类是四种模式之一：首次询问、每次都问、放行、禁止。文件里没写的类别按默认；代码里没定义过的类别按「每次都问」，不会默认放行。没有这个文件时用默认值；文件在但读不出来（损坏、格式不对）时所有类别按「禁止」，直到文件修好（每次使用都重读，修好立即生效），这期间不许改设置，免得把用户原来的设置盖掉。
- 每个 MCP 服务单独记一项。`mcp_adapter` 的通用入口（`call_tool`、`gateway_invoke`）能打到任意服务、看不出目标，所以不给使魔；各个 MCP 工具照常单独给，按各自服务的权限判。
- 提问等待期间设置被改过的，按新设置重新决定：新设置是禁止就拒绝，否则只放行这一次，旧问题的「以后都行」不会盖掉新设置。
- 任务大脑直达插件入口不经过询问（和现在一样，直接调）；判断点仍是 10.1 节说的两处。所以 `plugin_entry` 的四种模式里，直达只认「禁止」（设成禁止时插件根本不给精选看）；「首次询问」「每次都问」只对使魔经网关调用插件入口生效。「禁止」处处生效：某个 MCP 服务设成禁止时，直达这一路也不会把这个服务的工具交给精选，能打到任何服务的 `call_tool`、`gateway_invoke` 也一并不给；调用前再按当时的设置复查一次。某个服务算不算禁止，和使魔经网关调用时同一条规则：这个服务自己有设置就按它的，没有才按 MCP 服务这一类的设置（类别设成禁止、某个服务单独设成允许时，这个服务照常能用）；`*` 那一格只管没写明服务的调用。服务名从入口的显示名 `[服务] 工具` 读，服务名里带 `] ` 有多种读法时用入口 id（`mcp_服务_工具`）对上唯一一种；认不出是哪个服务的 `mcp_` 工具，按能打到任何服务处理，也不交给使魔。
- 叫停推断出的偏好只在同一个插件入口上累计：两次叫停的是同一个入口才算同一倾向，不同入口各叫停一次不生效。

评审后补的几条事实：

- 判重复只拿真在进行的委托比：直达插件停在 `blocked`（插件要确认或要补充信息）的不参与，用户确认后同一句话会重新执行；子使魔的委托不参与第一轮的叫停、补充和重复判断，它们在等回答时仍可被回答。
- 叫停时去掉日期、时段、「帮我」这类通用词再比对，只共享这类词的不算对上。
- 委托比对的分词另用一套，能切俄语、韩语、假名；插件筛选的分词没动。
- 决策模型给出的偏好只是一句话，类别（先问、汇报、能力、默认、其它）在本地按词表归，不改提示词。
- 委托结束的状态和给她的汇报在台账里同一个事务写入。
- 子使魔不排队：开子使魔时没有空位就直接拒绝，父使魔自己做那部分（父使魔等子使魔时一直占着名额，子使魔排在它后面会卡死）。父使魔收尾时不等已报「卡住」的子使魔。
- 失败或卡住的委托被插话重新办、又没有空位时，状态改回「排队中」，叫停照样生效。
- 直达插件在真正调用前再查一次权限，选入口期间被设成禁止的不会再调。
- 宿主重启后留下的 deferred 委托，计时器在下一次派发或查询时重新挂上。
- 宿主重启后没发出去的汇报，在宿主第一次被用到（派发、查询、叫停、插话、回答、deferred 回调）时开始补发。
- 使魔报「等回答」后会话因运行时空闲退出被关掉的，用户回答时用回答从记录续上，有名额就开、没名额就排队（台账新增「等回答 → 排队中」）。已知窗口：运行时决定退出到会话真正关掉之间（几十到几百毫秒）到达的回答，拒收先到时委托失败；会话关掉的消息先到时（之后的拒收已找不到会话），用这句回答从记录续上，不会停在「进行中」（回答写状态的途中会话关掉也一样）。
- 父使魔这一轮结束、等它开的子使魔时，会话也可能因运行时空闲退出被关掉；子使魔的结果到了就用结果把父使魔从记录续上，有名额就开、没名额就排队（台账新增「忙活中 → 排队中」）。
- 首轮超过 1 秒、先回了「收下了」之后首轮又出错的，只记日志、不补回执（没有「出错」这一类回执文案）。

- 第一轮超过 1 秒先回了「收下了」的，最终受理时也补发一条回执，带委托号。

她这边的两个工具（`main_logic/core/tool_calling.py`）：

- 只在这个会话开着猫爪时注册：总开关开着，而且键鼠、浏览器、插件三个开关至少开了一个。不再看 agent 模型有没有配置：插件不需要它，键鼠和浏览器没配它本来就开不了开关。关掉时从注册表拿掉；开关真的变了才同步给正在进行的会话。文本会话和实时语音会话用同一张注册表，所以都带。

- 派发和查询各是一次发给 agent 进程的请求（`/nekoclaw/dispatch`、`/nekoclaw/query`），最多等 2.5 秒，是整个请求的期限（HTTP 客户端的超时是连接、发送、读取分别计的，加起来可以超过它，所以外面另套了一层）。这个数比第一轮的 1 秒上限宽，因为宿主第一次用到时要先建起来。没拿到回执时不重发，免得同一件事立两次案，回一句固定的话。派发分两种：连不上、或者 agent 进程没处理就拒掉的（4xx），说「这件事没有交出去，不要说已经在办」；请求发出去了却没等到回应、或者 agent 进程自己出错（5xx，可能是受理之后写回执时出的错）的，说「不确定有没有交出去，不要说已经在办，也不要重新派发，稍后用查询确认」，因为 agent 进程那边可能照样在办。查询两种情况都说「现在查不到」。

旁听检查：

- 主服务在一轮结束时给 agent 进程发一条 `turn_check_request` 事件（带确认；没收到确认重发一次，两次用同一个编号，agent 进程按编号只查一次）。发的条件：这一轮是用户发起的、不是回调轮、不是头像拖放的轮次、用户这句话里有文字、她有回复，而且她这一轮没有经工具办过事。

- 会话在一轮中间结束、等不到那一轮的结束信号时，如果上次检查之后用户说过话，补查一次。她在被切断的那一轮里已经经工具办过事的不补查：会话结束的消息带着这个标记。否则她派发的事如果已经办完，查重认不出来，会被再派发一遍。会话结束、热重置清空聊天记录时，「上次查到哪」的位置一起归零，新会话第一轮被切断时才查得到。

## 7. 驱动接口

宿主只通过这一套接口用运行时，换运行时不改宿主其它部分。

命令：

| 命令 | 含义 |
|---|---|
| `start(spec)` | 建会话。`spec` 带系统提示、工作目录、模型配置、能力网关地址和令牌 |
| `prompt(text)` | 派活 |
| `steer(text)` | 插句话：当前这一步结束后、下一次请求模型前送进去 |
| `follow_up(text)` | 追加：这一轮全部干完后再接着干 |
| `abort()` | 叫停 |
| `close()` | 关会话，释放进程 |

事件：`started`、`text`（增量）、`tool_start`、`tool_update`（工具运行中的进度）、`tool_end`、`report`（结构化汇报：`progress` / `waiting` / `ready` / `blocked` / `failed`）、`usage`、`ended`。

内置运行时原生支持全部命令。dsh 经 ACP 协议适配。已核对 dsh 源码（`fcc0ad46`）：ACP 在一次 `prompt` 进行中再收到 `prompt` 会报错，ACP 和它的 SDK 服务端都没有暴露中途插话，所以 `steer` 在 dsh 上退化成 `follow_up`（这一轮干完再送进去）。

## 8. 内置运行时

### 8.1 来源与移植

来源是 huggingface/tau 仓库 `0d256d5`（0.4.10，2026-11-09）的 `src/tau_agent/`，MIT 许可。它是 Pi 的 Python 版里的核心循环，只依赖 pydantic 和标准库。

试移植已在仓库外做过一遍，结果：

- 共 17 个文件 2592 行。要求 Python 3.12 的原因只有 11 处 `type` 语句，分布在 6 个文件。
- 改 31 行后在 Python 3.11 下能导入；10 处改成普通赋值，递归的 `JSONValue` 改用 `typing_extensions.TypeAliasType`。
- 上游自带的核心测试 120 条，119 条在 3.11 下通过。剩下 1 条测的是上游模型层的再导出，不适用。
- 导入耗时约 0.2 秒。

落地时要做的：

- 放在 `nekoclaw/runtime/loop/`，目录内保留上游的 LICENSE，根目录 `NOTICE` 加一行出处。
- 文件头注明来源提交号。以后想要上游的某个修复，对着提交手工挑。
- 上游的核心测试一并搬过来，改成本仓库的测试写法。

### 8.2 我们对循环的改动

- **工具运行中的实时进度**。上游把工具的进度更新攒到工具返回后才一次发出（上游 issue 382，未修）。使魔跑长命令时需要实时输出，所以把「等工具返回」改成「边等边从队列里取进度事件」。
- **只读工具并行**。模型一次发出多个工具调用时，标了「可并行」的（读文件、查找、读图、取网页、搜索）同时执行，最多 10 个；其余仍按顺序一个个来。键鼠、浏览器、写文件、跑命令都不并行。
- 其它不动。插话、追加、叫停、工具前后钩子、「工具可以直接结束一轮」、中断后补齐半截的工具调用，都用上游现成的。

### 8.3 模型层

不拿上游的模型层 `tau_ai`，用我们自己的 `utils/llm_client`，写一个适配器实现循环要的 `ModelProvider` 接口。

已核对：`ChatOpenAI.astream` 和 `ChatAnthropic.astream` 都能流式返回工具调用片段（`LLMStreamChunk.tool_call_deltas`），并带回 `reasoning_content` 和 Gemini 的 `thought_signature`。循环的消息模型里有对应字段（`ThinkingContent.thinking_signature`、`ToolCall.thought_signature`），能原样带回下一次请求。

这样各家厂商的兼容处理只有一份，本地模型的 `http://` 地址照常可用。使魔用的模型取现有的 agent 模型槽位。

### 8.4 自带工具

循环本身不带工具。内置运行时自带的工具用 Python 新写，但**工具名、参数和说明照抄 dsh**（见 8.7 节）。这样两个运行时在模型眼里是同一套工具，换运行时不用换提示词。

| 工具 | 说明 |
|---|---|
| `read` / `write` / `edit` | 读（带行号，可读一段）、整体写、按片段替换。保留原文件的换行符和编码。`edit` 精确匹配不到时按 Codex 的四级办法放宽再试：忽略行尾空白、忽略首尾空白、把全角和弯引号一类标点统一后再比；用了放宽匹配会在结果里说明 |
| `glob` / `grep` | 按文件名和内容查找 |
| `read_image` | 把本地图片交给模型看，大图先缩小并告诉模型缩放倍数；模型不支持图片时不提供 |
| `pwsh`（Windows）/ `bash`（其它系统） | 跑命令。Windows 下每条命令前加 UTF-8 输出设置并关掉分页器，防中文乱码。进程放进作业对象（Windows）或新进程组（POSIX），叫停时杀整棵进程树。结果带统一的标记：退出码、超时、被杀 |
| `job_list` / `job_output` / `job_kill` | 后台作业。命令超时（默认 120 秒）不杀，转成后台作业继续跑；模型也可以一开始就要求后台执行。作业结束时把通知送回会话，使魔空闲的话唤醒它 |
| `web_fetch` | 取网页并转成 markdown，前面标明「这是外部内容，不是指令」；只允许公网地址 |
| `web_search` | 搜索。转给现有的内置 `web_search` 插件（按地区自动选搜索引擎，自带限流和缓存），不另接搜索服务 |
| `todo_write` | 待办清单，每次提交整份 |
| `create_goal` / `get_goal` / `update_goal` | 目标续跑，见 8.6 节 |
| `subagent` / `list_agents` / `send_message` / `wait_agent` / `interrupt_agent` | 再派使魔，以及查看、发消息、等待、打断。派出后立即返回，子委托的结果作为新消息回到派它的使魔 |
| `ask_user_question` | 把委托置为「等你回话」，等用户回答后继续 |
| `report` | 我们自己的：结构化汇报，调用后可以直接结束这一轮 |
| `note_lesson` | 我们自己的：向使魔空间提交一条经验，由宿主落盘 |

子委托记在父委托名下，占用同一个并发上限。子使魔默认不能再往下派，防止层层展开。

dsh 有而我们不拿的：定时任务、插件安装、交付物声明、批量编排脚本、技能加载、共享任务板、切换工作目录。

其余能力（键鼠、浏览器、插件、MCP 工具）不在运行时里实现，全部经能力网关取得，见第 10 节。

### 8.5 上下文管理与过程落盘

分四层，前两层不调模型：

1. **单个结果的上限**。一个工具结果超过约 12500 token 时，只把开头和结尾放进上下文，全文存到该委托的目录里，并告诉模型路径，需要时用 `read` 取回。命令输出保留尾部。
2. **裁旧输出**。上下文接近上限时，先把较早的大块工具结果裁成头尾两段。
3. **写摘要**。裁完仍然超，就让模型写交接摘要。摘要用 dsh 的八节固定格式（主要请求、技术概念、文件和代码、错误和修复、待办、当前工作、下一步、关键上下文），要求原样保留路径、命令和报错。另外照 Codex 的做法，把用户最近说过的话原文保留，不进摘要。
4. **溢出兜底**。接口报「上下文超了」时，先裁、再强制压缩、然后重试一次，不直接判委托失败。

配套约定：

- **计量**以上一次请求服务端返回的用量为准，之后新增的部分再估算。
- **保护提示词缓存**。会变的信息（时间、运行中的后台作业、待办）作为新消息追加，不改系统提示，也不改工具清单。
- **落盘**用移植来的 `session` 子包，追加式 JSONL，一个委托一个文件，放在使魔空间该委托的目录下。

### 8.6 防半途而废

- **待办清单**：`todo_write`。
- **重复调用提醒**：同一个工具带同样的参数连续调用第 3、5、8 次时，往会话里插一条提醒。只提醒，不拦。
- **目标续跑**：委托可以带一个目标。一轮结束而目标没完成时，宿主自动再开一轮，要求模型以当前实际状态为准、先核实再标完成；有轮数上限；同一个阻碍连续三轮都在，才允许标「卡住了」。

### 8.7 提示词和工具定义的来源

dsh 的提示词和工具说明是拿任务基准调过的，我们没有基准，所以直接用它的。

- 来源是 dsh 仓库 `fcc0ad46` 里锁定的快照：`snapshots/sdk/team-default-enabled/` 下的 `system-prompt.expected.md` 和 `tool-schemas.expected.json`（36 个工具，共约 34KB）。
- dsh 的系统提示是「每个工具贡献一段」拼起来的。我们只取自己实现了的那些工具的定义和对应段落，开头的身份说明换成我们的。涉及沙箱的句子去掉。
- 摘要模板、目标续跑的提示、重复调用提醒的措辞，也从 dsh 对应的源文件照抄。
- 这些文本保持英文原文，不翻译成八种语言：它们是给模型看的，翻译会丢掉调校的效果。使魔对用户说话用什么语言，另用一句话指定。
- 放在 `config/prompts/` 下，文件头注明来源提交号和 MIT 许可。
- 照 dsh 的办法加一条快照测试：把最终拼出来的系统提示和工具定义存成期望文件，任何改动都要显式更新它。
- 工具的行为要和说明对得上。说明里写了「输出保留尾部」「超时转后台」，实现就得是这样。

### 8.8 进程与占用

- 内置运行时跑在子进程里，用和插件宿主相同的方式拉起（`multiprocessing` 的 spawn）。打包版也走这条路，插件已经在用。
- 一个运行时进程里跑多个使魔会话，不是一个委托一个进程。上限是 10 个，按进程算要多占近 1GB；会话大部分时间在等模型和等工具，放在同一个事件循环里足够。跑命令本来就是另起进程，不占这个循环。
- 有委托才拉起，全部会话空闲一段时间就关。关掉进程内存全部归还，这就是「动态载入、可卸载」。子进程崩溃不连累宿主；崩溃时进行中的委托标为「没办成」，过程已落盘，可以接着干。
- 核心循环本身是普通的库，也能在宿主进程里直接跑。如果打包版里拉起子进程太慢，可以退回进程内运行，驱动接口不变。
- 实测（Python 3.11，仓库外的隔离环境，没发过模型请求）：子进程导入循环、pydantic、httpx、openai、anthropic、mcp 之后，常驻内存 86 到 92MB，热启动导入 1.5 秒，首次 6 秒。按需只导入用到的那家 SDK 可以更低。对比 dsh 完整配置约 196MB。

### 8.9 落地说明（第 1 个 PR）

代码在 `nekoclaw/runtime/`，入口说明见该包的 `__init__.py`。下面是落地时和上文不一样、或上文没写到的地方，以这里和代码为准。

接口：

- `start(spec)` 的 `spec` 不带系统提示全文。系统提示由运行时自己拼（身份说明、环境、每个工具一段、汇报语言），宿主要补的文字放 `spec.instructions`。能力网关的地址和令牌在 `spec.gateway` 里，是第 2 个 PR 加的（见 6.9 节）。
- `spec` 另有：`session_dir`（过程落盘和大输出落盘的目录，调用方给）、`disabled_tools`（对这个会话隐藏的工具，子使魔不许再派就填 `subagent`）、`top_level`、`goal`、`limits`、`reply_language`、`image_retention`。
- `ended` 表示「一段工作结束、会话空了」，原因是 `completed` / `aborted` / `error`；会话被 `close` 后再发一条原因为 `closed` 的 `ended`。一段工作里目标自动续跑多少轮都只发一条。（第 2 个 PR 加了一个可选字段 `inputs`：这段工作结束时会话已经收下了几条文字（prompt / steer / follow_up）。宿主据此认出「早一轮的结束」：子使魔的结果把空闲的父使魔唤醒成新一轮后，父使魔上一轮迟到的 `ended` 不会终结新一轮。补发的 `ended(error)` 和 `closed` 不带它。）
- 多一个 `error` 事件：命令被拒（会话不存在、运行中又收到 `prompt` 等）。子进程壳另有 `runtime_ready`、`runtime_exit` 两条进程级消息，以及 `host_request` 事件和 `host_response`、`shutdown` 命令。
- `steer` / `follow_up` 发给空闲的会话会直接开一段工作；`abort` 会清掉还没送进去的 `steer` / `follow_up`。
- `start` 之后可以马上发别的命令，不用等 `started`：会话还在创建时收到的命令会等它建好再执行，两种运行时一样。同一个会话 `close` 之后紧接着 `start`，新的会等旧的关完（过程写完、`closed` 事件发出）再打开。
- `prompt` 之后立刻 `abort`（运行还没真正开始）也算数：这段工作不会启动，直接以 `aborted` 结束。
- 关停（`shutdown`，以及子进程退出前）：已经存在的会话立刻开始关闭，关闭的第一步就是让它的后台命令停下；正在创建和正在关闭的会话同时等着，正在关闭的那个把过程写完、发出 `closed`，正在创建的那个一建好就关掉。会话的关闭一旦开始就独立进行：发起的一方不等了或被取消，关闭照常做完，同名的新会话要等它结束才打开。对一个正在关闭的会话再发 `close`（重复发，或者关停已经在关它），不报错，等同一次关闭做完就返回；关完之后再发才是「不认识这个会话」。
- 关停期间新来的 `start` 和新的工作（`prompt` / `steer` / `follow_up`）会被拒绝，两种运行时一样；关停结束后可以再 `start`（子进程运行时会起一个新子进程）。子进程因为空闲自己退出是另一回事：那时来的 `start` 不会被拒绝，而是等它退干净后交给新子进程。
- 等会话关闭有时间上限：进程内运行时 15 秒，子进程里 10 秒。这个上限只管「等会话关闭」这一段，不是子进程退出的时限。
  - 进程内超过上限：不再等，已经开始的关闭自己接着做完，还在创建的会话一建好就关掉。
  - 子进程里超过上限：子进程不再等，收尾、把事件发完就退出；父进程最多等它 15 秒，再不退就强行结束。进程一退，还没关完的会话和还在创建的会话都到此为止，不会接着做。还没关完的会话：没写进过程文件的内容会丢，宿主收到的是原因为 `error` 的 `ended`，不是 `closed`；它的后台命令在关闭的第一步就已经被叫停，这一点不受影响。还在创建、没等到答复的 `start`：宿主收到一条 `error` 事件（`command` 是 `start`），不是 `ended`。
- 权限回调收到的内容里，执行命令时多一项 `cwd`：命令实际运行的目录。模型可以让命令在别的目录里跑，这时它和会话的工作目录不同。
- 子进程空闲退出要先问父进程：子进程发 `runtime_idle`（带上它已读到的消息数），父进程确认自己发出的消息它都读到了，才回 `shutdown` 让它退；从这一刻起父进程不再往这个子进程写任何东西，新的 `start` 等它退干净后发给新子进程，其余命令直接回 `error`。子进程意外退出时，还没等到答复的 `start` 也会收到一条 `error`。
- 宿主回调（`nekoclaw/runtime/host.py`）：`decide_permission`、`ask_user`、`report`、`note_lesson`、`web_search`、`subagent_start` / `subagent_list` / `subagent_send` / `subagent_interrupt`。没给某个回调，对应的工具就不出现。`wait_agent` 在运行时里实现，等的是本会话排队的输入，不经宿主。

工具：

- `grep` 用 Python 的正则语法逐行匹配，没有带 ripgrep，工具说明里两处「ripgrep」字样相应改了。搜索范围在 git 工作区里取 `git ls-files` 的结果（即遵守忽略规则），否则只跳过隐藏文件。
- `grep` 和 `glob` 的匹配用 `regex` 包（已是项目依赖）而不是标准库 `re`：标准库匹配时一直占着解释器锁，模型写出一个回溯爆炸的模式就会卡住同一进程里的全部会话。`regex` 匹配时放锁，单次匹配超过 2 秒就停下并报错。文件逐行读，单行只取前 1 MiB 参与匹配。
- 按目录搜索时不穿过符号链接和目录联接（junction），和 ripgrep 的默认行为一致；这次调用是按它点名的目录过权限的，链接可以指向任何地方。点名单个文件时照常读（权限按链接指向的真实位置判）。
- `write` / `edit` 遇到符号链接时改的是它指向的文件，链接本身保留。
- `read` / `write` / `edit` 比 dsh 多认编码：带 BOM 的 UTF-8/16/32，以及能可靠识别出来的非 UTF-8 编码（如 GBK），写回时保持原编码和换行。
- `edit` 的放宽匹配按整行比较，命中的行用 `new_string` 原样替换，不替模型补缩进。
- `web_fetch` 只允许公网地址，这点比 dsh 严。没有代理时在本地解析域名、检查全部地址、并连接到检查过的那个地址；走代理时域名由代理解析，只能挡地址字面量和本地主机名。走不走代理由运行时自己判一次（按完整的主机加端口对照排除名单），再明确交给 HTTP 客户端，客户端不再自己读环境里的代理设置，两边不会判出不同的结果。
- `pwsh -Command` 把外部程序的非零退出码一律报成 1，这是 PowerShell 自己的行为，和 dsh 一致。
- Windows 的作业对象不设「句柄关闭即杀」：命令正常结束后，它有意留下的程序（比如打开的编辑器）不会被带走；叫停、`job_kill`、关会话时才杀整棵树。

上下文：

- 开始裁剪和摘要的阈值是 `min(窗口 × 0.8, 窗口 − 输出上限 − 余量)`，余量取 `min(65536, 窗口 / 8)`。dsh 的余量固定 65536，窗口小的模型会算出负数。
- 摘要请求失败时，用一段固定文字顶替被压缩的那部分，不让委托失败。
- 过程文件写到一半进程被杀，会在末尾留下半条记录。打开会话时先把这半条去掉（它本来就没写完），否则这个会话以后再也打不开。落盘的大输出文件编号在会话重新打开后接着往下排，不覆盖旧文件。
- 过程里每条记录都指着上一条。某一条写盘失败时先重试两次；还是写不进去就放弃这一条，后面的记录改为接在最近一条写成功的记录上，保证存下来的链条没有断口、会话还能再打开。
- 时间、运行中的作业、未完成的待办在每段工作开头追加一次，长时间运行每 30 分钟再追加一次，不是每次请求都加。
- 模型的回复因输出上限被截断、又没有工具调用时，自动追加一句让它接着写，最多连续两次。

目标：

- 被暂停的目标可以由模型在用户发话的那一轮恢复。dsh 只允许用户在它的界面里恢复，我们的驱动接口没有对应的命令。
- 叫停后目标只是不再自动续跑，状态仍是进行中。轮数默认 20，模型最多能要 100。

## 9. dsh 运行时

- **可选**。安装包里没有。用户在猫爪控制台的「使魔运行时」页点下载，装到数据根下；可以卸载。
- **装了就替代内置运行时**。之后新开的委托用 dsh，可以再装 dsh 插件。
- **默认配置**：关掉随请求上传会话日志和插件清单；模型走我们配置的地址；进程启动目录固定在系统盘（规避实测到的盘符故障）。
- **第三方 dsh 插件**和 dsh 同进程、全权限、无沙箱。控制台安装时要明说。
- **控制台页面**：下载、卸载、版本、dsh 插件的列表、安装、配置。这是给 dsh 写的前端。

已知的坑见研究记录：exe 未签名；装第三方插件要另下约 97MB 的运行时且不支持镜像；预览版每版可能破坏兼容。

## 10. 能力网关

宿主在回环地址上起一个 MCP 服务，每个委托发一个令牌。两个运行时都用 MCP 客户端连它，所以能力只实现一遍。

网关提供三类工具：

- **内置能力**：键鼠、浏览器。各是一组细粒度工具，和使魔自带的工具挂在同一个循环里由它一步步调，自己不带循环，见第 11 节。结果可以带图片（截图）。
- **旧插件入口**：每个对使魔可见的插件入口映射成一个工具。使魔调用时，网关发一个现有的 `/runs` 请求并轮询，插件侧零改动。叫停时网关调 `/runs/{id}/cancel`（宿主已有这个路由，agent 一侧现在不调）。一步能办完的事不经使魔，由任务大脑直达同一段代码（5.2 节）。
- **MCP 工具**：用户在控制台里配的 MCP 服务，网关转发。

### 10.1 权限

默认首次询问。使魔第一次要做下面某一类事时，委托进入「等你回话」，你在四个选项里选一个（owner 11-12 定）：

- 始终允许：写进权限文件，以后这一类不再问。
- 仅本会话允许：这件委托办完之前不再问（卡住后接着办、使魔会话重开都算）；委托办好、没办成、被叫停，或宿主重启就失效。它开的子使魔沿用。
- 本次允许：只放行这一次调用。键鼠和浏览器两类例外：放行到使魔这一轮跑完为止，因为它们的工具是一次点击、一次按键这样的小步，只批一次调用等于每点一下问一次。
- 拒绝：只拒这一次，不改设置。

先支持文字回答。一句话里同时有否定和同意的说法时算拒绝。

| 类别 | 默认 |
|---|---|
| 工作目录内读写文件 | 放行 |
| 工作目录外读文件 | 首次询问（第 3 个 PR 起，原来放行） |
| 工作目录外写文件 | 首次询问 |
| 跑命令 | 首次询问 |
| 键鼠 | 首次询问 |
| 浏览器 | 首次询问 |
| 每个 MCP 服务 | 首次询问 |
| 插件入口 | 放行（插件各自已有开关） |
| 启用她自己写的插件 | 每个新插件问一次（12.3 节） |
| 改设置 | 按设置项的风险级（12.4 节） |

选择存在 `<数据根>/nekoclaw/permissions.json`。猫爪控制台有一页列出每一类的当前设置，随时能改成放行、每次都问或禁止。判断点在两处：自带工具走循环的「工具调用前」钩子，网关里的能力在网关入口判。dsh 运行时的自带工具走它自己的权限机制，由我们按同一份设置生成它的配置。

### 10.2 工具清单

工具多了以后不全部塞给模型：任务大脑把筛出的候选入口交给这个委托，网关给它的清单默认带内置能力和这些候选，其余经一个查找工具按需取。

两类分开算预算，谁也挤不掉谁：内置能力的工具定义 2400 token（定义是我们自己写的，有测试守着不超），候选插件入口 3000 token。要看图才有用的内置工具（键鼠工具、浏览器截图工具）只列给模型能看图的委托。

## 11. 浏览器与键鼠

2026-11-13 owner 定的方向，原话：「键鼠和浏览器要内置在使魔里成为使魔循环一部分而不是独立循环了。（比如给使魔一个 skill 和注册必要工具，不要单独用一个 package 了太重）所以不存在使魔再去调谁。使魔本身就是通用 cua + browser use + 万用 coding agent」。同一天定：浏览器工具不再依赖 browser-use，直接用浏览器的调试协议写。本节按这个方向写，第 4 个 PR 已照此实现，落地细节见 11.9 节。

### 11.1 重写前的状况

- 打包时把 Playwright 下载的 Chromium 和它的无界面版一起放进后端包。本机打包目录里两者共 707MB（433MB 加 272MB）。Playwright 自己还带一个 Node 运行时，包目录 107MB。
- Playwright 在运行时只被用来下载这个 Chromium。browser-use 0.11 直接走 CDP（浏览器的远程调试协议），不依赖 Playwright；它自己 3MB，强制带进来的依赖约 120MB。
- 选浏览器的顺序是先用打包的 Chromium，找不到才用系统里的浏览器。所以打包版用户看到的永远是自带的那个。
- 启动器每次启动都检查，缺了就下载 Chromium。
- 外面的 Electron 壳（N.E.K.O.-PC）自带一份 Chromium：Electron 41.2.0，内核 146，344MB。
- 键鼠和浏览器各有一套自己的循环：键鼠每步让模型写一段 Python 再执行，浏览器用 browser-use 自己的 Agent 循环。第 3 个 PR 之后，使魔调的是两个只收一句指令的工具，工具里面还是这两套循环。

合起来是四个浏览器加一个多余的 Node 运行时，以及套在使魔循环里面的两套循环。

### 11.2 目标

浏览器来源只有两个，按顺序：

1. **用户自己的浏览器**：Chrome、Edge、Brave、Chromium 等 Chromium 内核的，按这个顺序找。Windows 上系统默认浏览器是其中之一时先用它；macOS 和 Linux 还没有读默认浏览器，按固定顺序。
2. **Electron 壳**：没有可用浏览器时，在 N.E.K.O.-PC 里开一个专用窗口，用独立的会话分区，不和桌宠、聊天窗口共用登录状态。

随包不再带任何浏览器。Playwright 从运行依赖里去掉，只留在测试依赖里。Docker 镜像既没有壳也没有用户浏览器，由镜像自己装一个 Chromium；没有显示器的环境（容器、远程服务器）里浏览器一律不开窗口启动。

### 11.3 已核实的限制

- **Chrome 136 起**，用启动参数开远程调试对默认资料目录不生效，必须指到另一个目录。所以「启动用户的 Chrome 再驱动它」拿不到用户平时的登录状态；在那个独立目录里登录一次后会一直保留。
- **Chrome 144 起**，用户可以在 `chrome://inspect/#remote-debugging` 打开一个开关，让外部程序接管正在运行的浏览器，每次连接要点一次允许。这条路能用到平时的登录状态。Edge 是否同样支持未核实。
- **Electron 壳实测**（Electron 41.2.0，隐藏的离屏渲染窗口）：开调试端口后，导航、执行脚本、截图、输入都正常；「新建标签页」（`Target.createTarget`）返回 Not supported，新建浏览器上下文也失败。新页面只能由壳自己开窗。普通的隐藏窗口截图会卡住，要用离屏渲染或可见窗口。
- **不能给主应用进程开调试端口**：那样桌宠和聊天窗口也会暴露给本机任何程序。
- **Edge 启动后会换进程**（本机实测）：被启动的那个进程把活交给另一个进程后立刻退出，退出码 0。所以不能把「子进程退出」当成启动失败，也不能靠子进程号去关浏览器。

### 11.4 形态：使魔自己的循环一步步调

键鼠和浏览器各是一组小工具（看屏幕、点、输入；打开网页、读页面、按编号点元素……），和使魔自己的读写文件、跑命令的工具挂在同一个循环里。使魔带思考，每一步都能看到上一步的结果再决定下一步；叫停、插话、权限、用量统计都只有使魔这一套。没有里面再套一层的循环，也没有哪个工具自己去调模型。

每组工具各带一段固定的说明，只在工具出现在清单里时才进系统提示（8.7 节「每个工具贡献一段」的同一个机制）。这是 owner 说的「给使魔一个 skill」的落地方式，和 dsh 的做法相同；不另做通用的技能加载机制，界面上也不出现 skill 这个词。

这组工具由能力网关提供，所以内置运行时和 dsh 拿到的是同一套，不用为 dsh 另写插件。实现留在宿主所在的 agent 进程里（`nekoclaw/builtin/`），不放进运行时子进程。

Claude Code 和 dsh 也是这个形态：Claude Code 的键鼠、浏览器各是一组工具加一份说明；dsh 的 `computer-use`、`browser-use` 两个包只是登记处，真正的工具由提供方包挂进同一个会话。但都没有能直接拿来用的实现：dsh 的浏览器提供方各包一层上游的 Node 程序，键鼠原生只支持 macOS；Codex 的工具在不开源的桌面应用里。所以借设计，不借组件。

### 11.5 浏览器的登录状态（已定）

默认用用户的浏览器加一份独立的资料目录（`<数据根>/nekoclaw/browser_profile`），要用的网站登录一次后保留。可以切换成「接管正在用的浏览器」，直接用平时的登录状态；这个模式要求 Chrome 144 以上，要用户自己在浏览器里开一次开关，每次连接点一次允许。

选择存在 `<数据根>/nekoclaw/browser.json`（`mode` 是 `own_profile` 或 `attach`，另有 `executable` 指定浏览器、`headless` 不开窗口）。接口已有（11.8 节），界面上的开关随前端 PR 放进猫爪工作台。

### 11.6 浏览器工具（已定，已实现）

**底下**：用 Python 直接走浏览器的调试协议，一条 WebSocket（`websockets`，本来就是项目依赖），不经任何浏览器自动化库。找浏览器、启动、连上已有的、关闭、强杀进程树都是自己写的。

**工具划分**照 Chrome DevTools MCP（Google，Apache-2.0，提交 `ec6fd2cf`）搬，名字加前缀 `browser_`，共 15 个：

| 工具 | 做什么 |
|---|---|
| `browser_navigate_page` | 打开网址、后退、前进、刷新；结果里带新页面的快照 |
| `browser_take_snapshot` | 取页面快照 |
| `browser_click` / `browser_hover` | 按编号点击（可双击）、悬停 |
| `browser_fill` / `browser_fill_form` | 填输入框、选下拉项、勾选；一次填多个 |
| `browser_type_text` / `browser_press_key` | 往当前焦点输入文字；按键和组合键（翻页键用来滚动） |
| `browser_take_screenshot` | 截图（可见部分、整页、某个元素），作为图片返回；模型不能看图时不提供 |
| `browser_list_pages` / `browser_select_page` / `browser_new_page` / `browser_close_page` | 标签页的列出、切换、新开、关闭 |
| `browser_wait_for` | 等某段文字出现 |
| `browser_handle_dialog` | 处理页面弹出的确认框 |

上游有而没搬的：执行任意脚本、上传文件、拖拽、按坐标点击、改窗口大小，以及调试类的工具（网络、控制台、性能）。

**页面快照**的格式和编号规则也照上游（它底下是 Puppeteer 的无障碍树快照，同为 Apache-2.0）：取浏览器的无障碍树，只留「有意义」的节点（地标、控件、能聚焦的元素、有名字的叶子），一行一个，按层级缩进，每个对应页面元素的节点带一个编号 `uid=<快照号>_<序号>`。同一个元素在前后两次快照里编号不变；页面换了文档（跳转）以后，旧编号不再有效。

和上游不一样的地方：

- 导航、新开、切换标签页的结果总带快照（使魔下一步一定要看）；一个动作做完发现页面换了文档，结果里也带上新快照并说明。这样一步少一次往返。
- 快照有长度上限（3000 token），超了在行尾截断，写明截到第几行，带上接着往下读的参数（`offset`）。上游不截断。一个元素一行：元素的文字里自己带的换行（代码块、多行文本框）写成 `\n`，不然按行数截断会数错。结果里别的部分（弹框、页面清单）占得多时，快照的上限相应减小，保证整个结果不超过网关的 4000 token，结尾那句「从哪儿接着读」不会被切掉。
- 只允许 `http://`、`https://` 地址。本机文件用文件工具读，那边有自己的权限询问。标签页里开着的本机文件（`file://`）、`data:` 这类也不列给使魔；后退、前进的目的地同样检查，不会退到一个本机文件上去。
- **本应用自己的服务端口不让这个浏览器碰**（主服务、记忆、监控、评论、agent 进程、插件服务，加上能力网关临时挑的端口）。这些地址对使魔没有正当用途，有的接口对本机来的请求不问是谁。按端口拦、不看主机名（换个解析到本机的域名也是同一个服务）。三层：使魔主动打开、新开标签页、后退前进时直接拒绝；页面自己发的请求、跳转、图片、表单提交，由浏览器的调试协议在网络层拦下（`Fetch.enable` 只匹配这些端口）；标签页里已经开着这类页面的不列给使魔。我们自己起的浏览器是对整个浏览器拦（实测：跨站的内嵌页面和 worker 发的请求也拦得住）；用户的浏览器和壳提供的窗口只对正在操作的页面拦，因为那是别人的浏览器，壳自己的窗口就是连这些端口的。**拦不住的**：WebSocket 连接（调试协议没有办法让它失败，实测握手能到达服务端），以及接管模式下跨站内嵌页面和 worker 发的请求。别的本机地址和内网地址（用户自己的开发站点、路由器后台）照旧放行，要不要改成首次询问待 owner 定。
- 页面能控制的文字都有上限，并且和工具自己的话分开：弹框的文字截到 200 token，单独一行、加引号、写明「是页面写的」；页面清单里每个地址截到 40 token，最多列 12 页（加上当前选中的那页），多出来的只说还有几页。
- `timeout` 参数最多 120 秒：浏览器的调用是一个个排队做的，等多久后面的就陪着等多久。
- 动作做了、但做完以后页面读不出来（新页面太重，取无障碍树超时）时，结果照样报「做了」，另起一句说明页面没读出来、不要重做、另外调一次取快照。整个调用报失败的话，使魔会以为没点上而再点一次，表单就交了两遍。
- 没列进快照的内嵌页面（别的站点的，或者超过了读取的个数和层数）在快照末尾写明有几个，告诉使魔里面的内容读不到。看不见的（统计用的隐藏框架）不算。
- 点击和悬停的落点先裁到窗口可见的部分，再问浏览器那个点上是什么：不是这个元素（或它里面的、包着它的、指向它的 label）就换一个点，五个点都被挡住就报错并说出挡着的是什么，不点到横幅或弹层上去。
- 填文本框分两步：先确认它能填，再给它焦点。页面在焦点移过去时弹了框（要求先登录之类），这个框没填上，如实报「没填」，不算进「已填」的清单。
- 旧编号对不上时报错，让使魔重新取快照，不照旧状态硬点：编号不在最新快照里、这一页还没取过快照、元素所在的文档已经换掉、元素已经不在页面上，四种情况都不往页面发任何操作。
- 页面弹出确认框时，页面和发给它的命令都会卡住。触发它的那个动作立刻返回并说明有弹框，这一页的其它动作在弹框处理掉之前都被拒绝。页面在离开前要确认（「离开此网站？」）时也一样：导航立刻返回并说明有弹框，不等到超时。
- 浏览器自己的页面（设置、登录和同步的弹框、开发者工具）和扩展的页面不列给使魔，也不操作：地址以 `chrome://`、`edge://`、`brave://`、`devtools://`、`chrome-extension://` 这类开头的都算。实测里 Edge 在新的资料目录上会自己弹一个 `edge://sync-confirmation-dialog/`，不滤掉它就成了「第 2 页」。
- 页面中途关掉（点了一个会关掉自己窗口的按钮，比如登录或授权的弹出窗口；或者用户把标签页关了）：那个动作照常返回并说明页面已经关了，带上剩下的页面清单；发给已关页面、还在等回音的命令立刻失败，不等超时。
- 一整行就超过快照上限时（整页是一大段文字），这一行截到上限并写明还有多少字没显示。
- 接管正在用的浏览器时，给干活单开一个标签页；用户自己的标签页会列出来，使魔点名选中才操作，但不能关（只能关为干活开的）。干活的标签页没了，不会自动转去操作用户的标签页，而是报错让使魔新开一个。只有开不了新标签页的窗口（壳提供的）例外：那里现有的页面就是干活的页面。

**已知的限制，记在这里，这个 PR 不改**：

- 调试口是随机端口、只绑本机，但本机上任何进程都能连上它，也就能操作这个带登录状态的浏览器。Chrome 有不开端口、走管道的调试方式（`--remote-debugging-pipe`），以后可以评估换过去。
- 接管模式只试找到的第一个浏览器：设置里指定了浏览器（或设了 `NEKO_BROWSER_PATH`）时它没有资料目录的信息，接不上；装了 Chrome、实际开着调试的是 Edge 时也找不到。等做接管的界面开关时一起处理。
- 启动被取消、关闭被取消这些路径都收过了（启动线程带起来的浏览器会被关掉；关到一半被取消，再关一次还找得到它）。
- 浏览器正在启动时调用被叫停：启动线程会被通知，马上放弃并把已经起来的进程带走（连它可能刚交接过去的那个进程一起，按资料目录找），不再等到浏览器起来或 25 秒超时。浏览器赶在通知之前已经起来的，会话拿到它之后发现已被叫停，同样杀掉，不接着用。应用关停时关浏览器有 4 秒的上限（启动器给 agent 进程一共 8 秒），到时还没关完就直接杀掉自己起的浏览器，不让它留在应用退出之后；用户正在用的浏览器不杀。关停流程里排在前面的步骤各有上限、加起来超过 8 秒，所以关停一开始另起一个 5 秒的计时器：到时不管流程走到哪一步，都把自己起的浏览器杀掉；浏览器按时关完就取消。轮到关浏览器那一步时，给它的时间按离这 5 秒还剩多少算（最多 4 秒，一点不剩就不问、直接杀）；之后只松开按着的键，不再问浏览器一遍。关掉浏览器开关时如果有一次启动还在进行，也会被叫停，不用等它起来。这几个时间和宿主关停的预算放在一起（`config/nekoclaw_settings.py`）。关停时浏览器按时答复了、但没关掉（关闭本身失败），同样杀掉：平时关不掉的浏览器会留着下次再关，关停没有下次。用户点「全部终止」时松键和关浏览器同时进行（先开始松键），互相不等；浏览器按时答复了但没关掉的，和关停时一样杀掉；关浏览器有 4 秒上限，到时杀掉，杀的过程放到后台、不等它（杀要等进程退干净，还要几秒，页面等这个请求只等 5 秒）。这期间新来的浏览器调用要等这次强杀做完才开始：强杀轮到自己时杀的是当时找到的浏览器，不能让它找到之后的任务新起的那个。连按两次「全部终止」会有两次强杀同时在做，新的调用要等两次都做完；已经在排队、轮到时正好有强杀在做的调用直接报「浏览器正在关闭，稍后再调」，不去起新浏览器。按进程号杀之前先看当初起的那个进程还在不在：它已经退出的话（用户自己关了浏览器，或者它把活交接出去了），这个号可能已经被系统分给别的程序，这时改按资料目录找浏览器进程，找不到就不杀。「还在不在」除了问进程本身，还核对这个号的进程创建时间和启动时记下的是否一致（问进程本身在个别时刻会答错）。关浏览器时，当初起的进程退出了不等于浏览器关了：它可能在端口打开之后才把活交接给另一个进程（Edge 会这样），所以它退出后还要看资料目录上有没有浏览器在跑，有就按「不是自己起的进程」处理（等一下、看端口、不行再杀）。强杀除了正在用的和上次没关掉的，也包括「已经起来、会话还没接上」的和「启动被取消后交给后台去关」的浏览器：这两种别处都不知道，关停又等不起。
- 点击、填写、悬停要先向浏览器要元素的句柄。句柄统一要进一个对象组，一次调用结束（成功、失败、被叫停都算）把整组放掉；不放的话，页面已经删掉的元素会一直留在浏览器里，不整页刷新的页面上越攒越多。页面开着对话框时不放（那时页面不答），等对话框处理完再放。
- 一条调试命令的时限把「发出去」也算在内：浏览器不读数据时发送会一直等，不算进去就等不到头。
- 浏览器被强杀后会在资料目录里留下端口文件，那个端口之后可能被别的程序占用。所以发现端口文件且端口能连上时，还要确认这个资料目录上确实有浏览器进程；没有就当作过期文件删掉、重新启动。只要说不准就不这么判：进程列不出来，或者有浏览器进程不让读命令行（比如以别的权限启动的），都当作浏览器可能还在。代价是：机器上只要有一个这样的浏览器进程，所有资料目录都不再判过期，端口被别的程序占了的那种启动失败在这些机器上还会出现，直到那个程序退出；误删正在跑的浏览器的端口文件更糟，所以这样取舍。

**从 dsh 借的做法**（`packages/experimental/browser-use-runtime`）：浏览器同一时间归一件委托用（11.9 节的占用）；同一件委托的操作排队，一个做完才做下一个；截图作为图片进会话，不把编码塞进文字；说明里写明叫停撤不回已经发出的点击和跳转。

**给壳的兜底窗口留的路**：不依赖「新建标签页」这条调试命令。浏览器启动时自带的那个页面就够用；`Target.createTarget` 被拒绝时记下「这个浏览器开不了新标签页」，之后在现有页面上工作，`browser_new_page` 回一句解释。浏览器会话有一个「兜底地址」的入口（找不到浏览器时问它要一个调试地址），壳就绪后接上；现在没接，找不到浏览器就如实回「没有可用的浏览器」。

### 11.7 键鼠（已实现）

- 一个工具 `computer`，用 `action` 参数区分动作：截图、点击（左键、右键、中键，单击、双击、三击）、移动、拖动、滚动、输入文字、按键和组合键（可按住一段时间）、等待。每次调用返回动作之后的一张截图，所以一步只要一次模型请求。
- 做成一个工具而不是八个小工具：同样的文字拆成八个要 923 token，一个是 505 token（坐标说明要在每个带坐标的工具里重复一遍），每次请求都付；一个工具的截图也天然合在一起计数。这个形状也是模型在别的键鼠工具里见过的。
- 坐标沿用原来的约定：横纵都是 0 到 999 的整数，由我们换算成屏幕像素。超出范围的坐标报错，不当成像素（模型看到的截图比屏幕小，当像素会点偏）。
- 截图、输入、坐标换算、松开按住的键这些代码沿用旧实现。滚动的单位改成「滚轮格数」：旧实现在 Windows 上把数字原样交给系统，1 格是 120，模型写的 -5 几乎不动。Windows 上的左右滚动自己调系统接口发：pyautogui 在 Windows 上把左右滚动发成了上下滚动（`_pyautogui_win._hscroll` 直接调 `_scroll`）。这一条没在真机上试过。
- 截图只在上下文里保留最近 3 张，更早的换成占位说明。这 3 张是键鼠、浏览器截图、以及经网关的通用调用入口拿到的截图合起来算的：单张的字节上限就是按「上下文里一共 3 张」定的。
- 松开还按着的键和鼠标键要等正在执行的那次调用结束（最多等 5 秒，等不到就留给那次调用自己或下一次松）。两个线程同时松，会把 pyautogui 的角落急停来回开关，可能永久关掉。
- 动作做了、做完截图失败时，结果照样报「做了」，另说明截图没拿到、不要重做。和浏览器那边同一个道理：报成失败，使魔会再点一次。
- 拖动途中被叫停，鼠标键在当前位置松开，不在终点松开（在终点松开等于把拖放做完了）。
- 输入非 ASCII 文字要借剪贴板粘贴。用户原来剪贴板里的文字在这个动作结束时放回去（等结果、截图之后；动作中途被叫停也至少等 0.3 秒），不在粘贴之后马上放：应用读剪贴板可能比按键晚，放早了它粘进去的是用户原来的内容。期间用户自己又复制了别的，就不动。原来是图片或文件的放不回去（读不出来）。
- 使魔用的模型不能看图时，不提供这个工具。
- 这次没做、以后的方向：像 dsh 自研的键鼠那样先取窗口里的控件列表、按控件编号操作，坐标只当兜底。Windows 上要靠系统的界面自动化接口，是另一块工作；对「看图定位弱」的模型会好很多。

### 11.8 操作中的横幅、Esc 叫停与阻止介入

使魔在用键鼠或浏览器时，屏幕上要有明显的提示，并且随时能按 Esc 叫停。浏览器操作时不拦用户（owner 已定）。键鼠操作时要不要拦用户的键鼠，owner 还没表态，这次没有实现，也没有做成默认开。

**分工**：主仓库只发事件、提供叫停入口；横幅、Esc 监听、输入过滤都在壳（N.E.K.O.-PC）里，复用它现成的教程全局覆盖层、隐藏系统光标的服务、全局 Esc 保护。没有壳（源码运行、Docker）或壳没跟上时没有横幅，操作照常。

**事件契约**（第 4 个 PR 已实现主仓库这一半）：

- 一件委托开始占用桌面或浏览器、以及放手时，agent 进程发 `builtin_activity` 事件，主服务转给每个已连接的页面：

  ```json
  {"type": "agent_builtin_activity",
   "activity": {"group": "keyboard_mouse", "state": "started", "commission_id": "…", "window": null}}
  ```

  - `group`：`keyboard_mouse`（整个桌面）或 `browser`。
  - `state`：`started` 或 `ended`。
  - `commission_id`：占着它的委托（顶层那一件）。
  - `window`：浏览器被操作的那个窗口，`{"browser": 名字, "pid": 进程号, "window_id": …, "bounds": {"left", "top", "width", "height", "windowState"}}`；键鼠是 `null`。浏览器是第一次调用时才启动的，所以第一条 `started` 里可能还没有窗口；窗口确定下来、或者位置变了，会再发一条 `started`。壳把重复的 `started` 当成更新。
- 页面把事件原样交出去：`window` 上的 `neko-agent-builtin-activity` 事件（`detail` 就是 `activity`），当前状态在 `window._agentBuiltinActivity[group]`。
- 晚启动的壳可以问现状：`GET /api/agent/builtin/activity` 回 `{"activity": [...]}`，每个被占用的组一条。
- 后端不在本机的远程部署下，这几个入口和别的 agent 入口一样回 501。
- **Esc 叫停入口**：`POST /api/agent/builtin/stop`，可带 `{"group": "keyboard_mouse"}` 或 `{"group": "browser"}`，不带就两个都停；回 `{"success": true, "stopped": [委托号…]}`。做的事和在任务窗口里点取消一样：先写状态，再取消正在做的调用，桌面或浏览器随即放手，随后会收到 `ended`。
- `ended` 在这些时候发：使魔这一轮跑完、委托结束或出错、委托进入「等你回话」（否则用户没法回答）、被叫停。
- **壳要自己对账**：agent 进程崩溃或被强杀时发不出 `ended`。壳不能只靠事件收横幅，要定时（或在 agent 进程连接断开时）问一次 `GET /api/agent/builtin/activity`，那边不再报这个组、或者问不到，就把横幅收掉；不然横幅会一直挂着。
- **壳的全局 Esc 监听要分清是谁按的**：使魔自己会用 `computer` 工具按 esc（关对话框、取消菜单），那是系统级的合成输入，和用户真按的 esc 走同一条路。监听不加区分的话，使魔一按 esc 就把自己叫停了。区分的办法由壳定（例如只认硬件来源的按键、丢弃带注入标记的），这是壳那一半的验收项。

**键鼠：全屏**（壳这一半，未实现）

- 屏幕四周一圈发光边框，加一条横幅，写明使魔正在操作电脑、按 Esc 叫停。文案八种语言。
- 覆盖层保持点击穿透，并标记为不进截图。否则使魔自己的点击会落在覆盖层上，截图里也全是边框。
- 如果以后要拦用户的键鼠，不能靠覆盖层：使魔的输入是系统级的合成输入，和用户的真实输入走同一条路。要在系统层过滤，放行合成输入、丢弃真实键鼠输入，只留 Esc（Windows 用低级键鼠钩子，macOS 用事件过滤，Wayland 做不到）。默认开还是关待 owner 定。

**浏览器：只显示横幅，不阻止介入（owner 已定）**

- 同样的边框和横幅，只盖住被操作的那个浏览器窗口，跟着窗口移动和缩放。不做全屏，因为用浏览器而不是键鼠的好处就是别的窗口还能照常用。
- 覆盖层点击穿透，用户随时可以自己点、自己输入。旧的浏览器通道在页面里盖一层挡住用户的鼠标，那一层随旧实现删掉了。
- 用户插手之后页面可能和使魔上一步看到的不一样，见 11.6 节「旧编号对不上时报错」。

### 11.9 落地说明（第 4 个 PR）

代码在 `nekoclaw/builtin/`（工具实现）、`nekoclaw/host/`（占用、图片回传、权限）、`app/agent_server/`（开关和事件），工具定义在 `config/prompts/prompts_nekoclaw_builtin.py`。下面是上文没写到、或和别的章节有出入的地方，以这里和代码为准。

**占用**（`nekoclaw/host/leases.py`）

- 原来是「每次调用一把锁」。工具变小以后挡不住两只使魔轮流点，所以改成按委托占用：一件委托从第一次调用起占着桌面（或浏览器），别的委托要用就等。
- 放手的时机：使魔这一轮跑完、委托进入「等你回话」、委托结束。
- 一件委托和它开的子使魔算一队，共用一次占用。父使魔会在自己这一轮里等子使魔的结果，子使魔如果得等父使魔放手，两边就互相等死了。同一队里只保证单次操作不交错。
- 别的委托最多等 120 秒，等不到就回一句「被哪件事占着」，由使魔自己决定先干别的还是报告在等。
- 浏览器这次先整体独占；多只使魔各用各的标签页以后再做。

**权限**

- 键鼠、浏览器两个类别的「本次允许」放行到使魔这一轮跑完为止（原来只放行一次调用，工具变小后等于只批一次点击）。只管问的那只使魔自己，它开的子使魔要另问。「每次都问」的设置下也是这样。

**图片**

- 网关的结果可以带图片（MCP 的 image 块）；运行时的网关客户端和转发工具把它们接成工具结果里的图片。一次结果最多 4 张。
- 要看图才有用的工具（键鼠工具、浏览器截图工具）只给「模型能看图」的委托，也只有它们能调。
- 截图保留张数是所有内置工具合起来算的（`TaskAgentSpec.image_pools` 里它们同属一个池），经 `capability_call` 按名字调出来的截图也算在内。
- 使魔跑到一半才发现模型不能看图（厂商拒收图片）时，这个会话当场就不再给要看图的工具，不只是记给以后的会话：截图已经到不了模型了，继续点等于闭着眼操作。

**模型能不能看图怎么判断**（owner 2026-11-14 已定：默认按能看图）

- 配置里没有这项信息，问模型又要多花一次请求。所以默认按能看图：agent 模型槽位本来就回落到看图模型，被替换掉的键鼠循环也是不问就发截图。
- 厂商因为请求里带图片而拒绝时，运行时把这一次请求去掉图片重发一遍，然后看厂商说的是哪一种：
  - **这个模型不收图片**（「不支持图片输入」这一类）：这个会话之后都不带图，并告诉宿主。宿主把「这个地址加这个模型名不能看图」连同厂商的原话和时间记到 `<数据根>/nekoclaw/model_capabilities.json`，以后开的使魔就不给要看图的工具；当前这个会话也当场不再给。
  - **这几张图不行**（格式、大小、张数太多、图片放的位置不对、读不出来）：只把这几张图从这个会话里拿掉，以后的图照发，**不记**。能看图的模型也会这么说，从这种话里推不出模型不能看图。同一个会话里这样被拒两次，这个会话剩下的部分不再带图（每被拒一次就白花一次请求，键鼠每一步都截图，会步步白花），同样不记。
  - 分不清的按「这几张图不行」处理。
  - 上下文超长的报错（哪怕里面提到图片，例如「……tokens (including image tokens)」）不算拒图，照旧走压缩上下文那条路；否则两次超长就会把这个会话的图和看图工具收走。
  - 网关在每条报错后面附的话（重试次数、限流）不参与判断；「最多 0 张图片」算「这个模型不收图片」。
- 记下的结论 7 天后失效，到时候重新发图试一次：误判的、后来换了能看图的版本的，自己恢复；真不能看图的只是多一次被拒的请求，再记 7 天。
- 文件里手写 `{"images": true}` 可以强制按能看图处理，手写 `{"images": false}` 永久按不能看图（手写的没有时间，不失效）。
- 能看出来：`GET /computer_use/availability` 的结果里有 `model_images`，写着现在给不给这个模型发图；不给的话写明是厂商拒收还是手工设的、厂商的原话、哪天记的、哪天失效。界面上怎么显示随前端 PR。
- 多出的消耗只有被拒绝的那一次请求。

**连通性探测**

- 原来挂在键鼠适配器上的「agent 模型连不连得上」的探测搬到了 `app/agent_server/model_probe.py`。键鼠可不可用现在是「探测通过，并且能发输入」；浏览器可不可用是「探测通过，并且本机找得到浏览器」，找不到时原因码是 `AGENT_BROWSER_NOT_FOUND`。

**固定开销**（每次使魔请求都付，要 owner 签字）

| 情况 | 多出的 token |
|---|---|
| 两组都开、模型能看图 | 2227（键鼠工具 505，浏览器 15 个工具 1401，两段说明 153 加 168） |
| 两组都开、模型不能看图（不给键鼠工具和截图工具） | 1485 |
| 只开浏览器 | 1569 |
| 只开键鼠 | 658 |

第 3 个 PR 时使魔每次请求的固定开销是 4806 token。内置工具的定义单列预算（2400 token），不占插件入口的 3000。

## 12. 使魔空间与插件存储

### 12.1 使魔空间

所有使魔共用，按用户一份。全是明文文件，只有宿主写。

```text
<数据根>/nekoclaw/task_agents/
├─ AGENTS.md              全局守则
├─ MEMORY.md              全局索引，一行一条，开工必带
├─ memory/*.md            跨项目的经验与反思，一条一个文件
├─ projects/
│   ├─ _daily/            零散委托的默认去处
│   └─ <项目>/
│       ├─ project.json   名字、工作目录、状态、起止时间
│       ├─ AGENTS.md      这个项目的约定
│       ├─ MEMORY.md      项目索引
│       ├─ memory/*.md    这个项目里的经验、反思、参考、进度
│       └─ sessions/<委托号>/   委托原话、完整过程、收工复盘
└─ archive/<年>/<项目>/   闲置项目整目录搬来，全局索引留一行
```

- 条目四类：经验、反思、参考、项目进度。「纠正与认可」归任务偏好（5.1 节），不放这里。运行时的 `note_lesson` 工具仍是五类，使魔照常用 `feedback` 提交用户的纠正与认可；宿主收到后记进任务偏好，其余四类才写进使魔空间。
- 每次收工后台用便宜模型写复盘；值得留的提炼成条目，先找同主题的改，没有才新建。
- 项目约 30 天没有新委托就归档：写总结、把通用经验上提到全局、整目录搬走。同名项目再来委托时自动取回。不自动删任何东西。
- 完整过程保留约 30 天，复盘和条目永久保留。
- 开工时带全局守则、全局索引、项目说明、项目索引，各有 token 上限；正文用到再读，其余靠全文检索。
- 用户在控制台里能看、改、删每一条。

### 12.2 插件存储

- 私有空间不变：`<数据根>/plugins/<插件id>/{data,cache,config}`。
- 新增共享空间：`<数据根>/plugin_shared/<发布者插件id>/`。发布者可写；别的插件在 `plugin.toml` 里声明后只读。插件之间没有沙箱，这是约定，不是安全边界。
- 插件不直接碰本体记忆。

### 12.3 她自己写插件

目标是「给自己写一个能查快递的插件」这类事开箱即用。它是一个普通的委托：她派发，任务大脑交给使魔。现成的基础：

- 插件工作台：建项目并登记、发布前检查。登记的项目当源码插件加载，不自动启动。
- `neko-plugin` 命令行：能把第三方库收进插件自己的目录。
- `plugin/PLUGIN_DEVELOPMENT_GUIDE.md`，以及插件的启动、重载、删除接口。

要补的：

- 能力网关加一组「插件工作台」工具：建项目、检查、重载、试跑入口。都是包现有接口。
- 开发指南随包带。任务大脑路由到写插件的委托时把指南交给使魔，并把这件事归到使魔空间里一个固定的项目，经验能攒下来。
- 先试后用：新插件先在任务大脑看不见的状态下试跑（用现有的可见性开关）；过了检查和试跑、用户点了同意，才进能力清单。
- 权限：启用她写的插件，默认每个新插件问一次。
- 出处和回退：标明是她写的；每个插件项目是独立的 git 仓库，改坏了能退回；启动失败自动停用，不拖累启动。
- `short_description` 和 `keywords` 由使魔写好，检查时必填，新插件一启用就能被筛到。

### 12.4 她改自己的设置

先例是内置的 `proactive_controller` 插件，它经主服务接口改主动搭话的设置。

- 一张设置白名单登记在能力清单里：每项带给模型看的说明、类型和取值范围、风险级。读写都走现有接口，不直接改文件。
- 低风险的一步办完；中风险的等用户确认；禁止的直接回「这项要他自己改」。
- 台账记旧值和新值，能改回去。
- 会重启会话的设置（换模型、换声音）走现有的热切换，不阻塞前台。
- 硬规矩：
  - 她不能改权限设置。
  - 她不能读写密钥和模型地址。
  - 改人设类设置每次都问，并给出前后对比。

## 16. 分期：主仓库六个 PR

owner 定的上限是六个。每个 PR 合并后应用都照常可用，按顺序做。

1. **内置运行时**。移植循环加实时进度和只读并行两处改动；模型适配器；照 dsh 定义的自带工具和后台作业；从 dsh 取来的提示词和工具说明；四层上下文管理、过程落盘；待办、重复提醒、目标续跑；子进程壳；快照测试。纯新增，不接线，用假模型测。本设计稿随这个 PR 一起进。
2. **宿主新部件**。任务大脑（台账、任务偏好、能力清单、决策模型的两轮、查询）、驱动接口、使魔管理、能力网关（旧插件入口和 MCP 工具）、权限。挂进现有 agent 进程但不接主对话，旧路径照常。先补插件契约测试。
3. **切换与界面**。主对话两个工具和开场提示的改动、处理中气泡、旁听检查、改口提醒、汇报回流、换会话注入改读台账；键鼠和浏览器先包着旧实现接进网关；删旧判断器、通道分派、OpenClaw。委托板、开关面板、控制台改名和新增页面，八种语言，连同新手教程。实测各家模型的调用顺序和工具往返延迟；更新 `docs/plugins` 里讲 Agent 怎么选插件的段落。落地时界面只做了最小改动，委托板和控制台的新页面没做，见 6.10 节。
4. **键鼠与浏览器**。改成使魔循环里的两组细粒度工具，删 `brain/` 里的旧实现；浏览器直接走调试协议，按第 11 节统一，不再随包带浏览器，去掉 browser-use 和运行期的 Playwright；主仓库这一半的横幅事件和 Esc 叫停入口。落地说明见 11.9 节。
5. **使魔空间与插件共享空间**。守则、索引、复盘、归档、控制台页面；插件共享目录和声明。写插件的工具组和设置能力（12.3、12.4 节）是否并进来，待 owner 定。
6. **dsh**。驱动、下载和卸载、控制台「使魔运行时」页和 dsh 插件管理。

每个 PR 的描述里带一张改动前后的消耗对比（6.8 节）。

N.E.K.O.-PC 是另一个仓库，那边的配合改动不在这六个里：第 4 个需要它提供兜底用的专用浏览器窗口、横幅覆盖层、Esc 监听（事件和入口见 11.8 节），键鼠的输入过滤等 owner 定了再说；第 3 个如果委托板要动壳的窗口，也要跟着改。
