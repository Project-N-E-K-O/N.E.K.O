# 小剧场市场接入

本版提供主动入口、随机邀约选剧及市场导入。市场负责安装剧本，本地剧本选择页负责由用户确认开始或继续；不读取用户记忆做推荐。当前演绎、审核与工坊生成策略见[小剧场架构](neko-theater-architecture.md)。本体在 `assets/theater` 附带《雁回镖局的第十九趟镖》《月台尽头的猫灯》《霓虹下的猫耳重构》三个已筛选的 v2.2 剧本，首次读取剧本列表时经当前编译器和写入栅栏安装到用户剧本目录。同 ID 已有文件与存档不覆盖；独立的 `numeric_v2/bundled_stories.json` 初始化标记保留删除意图，删除后重启不自动装回。资源随既有 assets 打包链路发布，不依赖市场登录或下载。

## 入口与选择

主动搭话菜单的小剧场开关右侧有独立“进入”按钮，打开本地 `/theater` 选剧页，不切换邀约设置。首次即可选择三个内置剧本并点击开始；本地文件导入、继续和删除入口保留。复用本体已有的命名窗口管理，重复点击聚焦已有选剧页。

本地选剧页的“更多剧本”按钮在当前窗口跳转 `/theater?market=browse`，只在此时连接市场，保留本体 opener；不创建随选剧父窗口关闭的市场子窗口。导入等忙碌操作及未完成记忆询问期间不跳转。市场连接仅支持 NEKO 所在电脑的 HTTP loopback 地址；局域网或远程地址显示明确限制，不创建配对。服务间配对使用实际插件服务的本机来源。连接页只显示状态、创建市场操作，再在同一窗口进入 Market 的 HashRouter 页面；不加载本地剧本列表，不处理结束回执。其他入口成功打开市场时仍关闭空闲本地选剧窗口；正在操作或尚未完成记忆询问的窗口保留。

小剧场邀约在投递前从 Market `GET /api/v1/shares/theater/random` 取得一个已发布、已校验剧本。普通搭话与工作休息邀约都冻结作品 ID、作品 revision 和文件 hash。普通搭话实际抽中小剧场后，使用同一次市场响应中 `preview.intro.background` 的公开前情，经一次 conversation 模型调用概括为1—2句短简介（中文约50字，最多80字符；其他拉丁字母语言最多280字符），再用本地化模板介绍剧名、简介并询问是否愿意演绎。只读公开前情，不读取完整节点、结局或玩家记忆；最长等待6秒、不重试，摘要缺失或失败时只介绍剧名，不回退到长原文。工作休息邀约把同一抽中作品的剧名和公开前情传入既有的休息提醒生成，由原本的一次调用同时概括简介并询问是否愿意演绎；不额外增加摘要调用，也不再泛化地请用户挑剧本。接受后携带冻结的同一作品选择进入市场，登录完成后自动导入，再交给本地选择页确认开始。其他活动的概率、开关和冷却不变。

桌面壳从创建选剧窗口起即复用社区的系统原生窗控，连接市场、连接失败、市场目录和返回选剧均可直接关闭；本地页不重复提供网页窗控。主动邀约预开窗口沿用 `neko_theater_market` 名称，让桌面壳在空白阶段也能识别。关闭当前窗口不启动演绎、不关闭本体；浏览器端沿用浏览器自身窗控。

## 连接与导入

`main_routers/theater_market_router.py` 处理 `/api/theater-market/launch` 的创建、状态查询及导入。一次操作绑定当前角色，保留 30 分钟；市场阶段不创建或领取演绎 Session，没有自动开演或等待开场回执的步骤。

一次性配对码由正在运行的插件服务发放。市场通过原 `/market/token-exchange` 换取连接令牌；令牌保留在该标签页会话中，配对码从地址中移除。市场使用自己的已有登录态下载原文件，再经 `/market/theater/launch/{id}/import` 交给本体。桥接验证令牌、受信市场来源与 8 MiB 大小限制，不转发市场账号令牌给本体。

本体再读取当前市场元数据，核对作品类型、发布状态、revision、原字节 hash 与大小，随后使用原剧本编译器、Registry、生命周期锁和写入事务安装。相同规范化 package hash 可复用；同 ID 不同内容返回冲突。导入不修改已有进度或记忆。

## 返回选择页与开始

市场收到 `imported` 及已安装的 `story_id` 后，把当前市场窗口切换到本体 `/theater?story_id=...`，选中刚导入的剧本。复用同一窗口可以保留本体 opener，也不依赖异步弹窗权限；页面上不再保留市场内容。导入失败时仍停留市场，保留重试入口。

用户在本地选择页点击“开始”后，沿用原本体启动握手；胶囊挂载并返回 `theater:start-ready` 后关闭选择页，模型开场由本体继续持有。停麦或接管失败时保留选择页和错误提示。已有未结束进度按原继续流程处理；选择“不记录”且已结束的演绎，通过本地“开始新的演绎”创建新 Session，已保存档案仍保留。

普通本地 `/theater` 的导入、继续、记忆询问和档案管理保留。没有恢复预生成，也不改变演绎引擎。

## 部署与验证

地址沿用 `NEKO_MARKET_API_URL`、`NEKO_MARKET_WEB_URL` 和 `NEKO_MARKET_ORIGINS`，本体与插件服务端口从运行配置解析。Market 使用 `/#/theater` 与 `/#/shares/{id}`；不通过 iframe 嵌入市场。

专项检查覆盖首次三剧安装与开始、同 ID 不覆盖、删除后不自动补装、主动入口先显示本地列表、“更多剧本”进入市场、随机邀约短简介与冻结选择，以及上传校验与导入原字节、幂等安装且不创建 Session、入口不加载旧选剧页、空闲旧页关闭、导入成功定位本地选剧页、导入失败保留市场，以及跨市场返回后的 opener 保留、点击开始后关闭选择页、接管失败保留选择页。浏览器启动检查使用模型桩，不代表真实演绎质量验收。公网 HTTPS 市场访问本机的授权流程仍需在发布环境验收；未上传正式市场。

## 发布边界

NEKO 的后端、市场桥接路由、静态页面和聊天前端需要同版发布，桌面安装包必须携带这份后端构建产物。NEKOPC 沿用既有窗口与本机服务能力，不提交开发机的 `vendor/` 运行副本。

Market 需要部署前后端、新校验快照及依赖，执行部署版本要求的数据库迁移；更新快照后使用 `scripts/revalidate_theater_shares.py` 先预览既有作品，再按结果决定是否 `--apply` 更新校验元数据。此操作不会把本地测试数据库或剧本文件自动上传到正式市场。

开发环境的真实模型和本地测试账号联调不代替正式 OAuth、公开 HTTPS 市场到 loopback 的授权、Windows/Linux/macOS 正式安装包验收。正式发版前应以真实账号完成选剧、登录、导入、开始/继续、退出不记忆后重新开始及随机主动邀约；12 本测试市场作品需另行上传和上架。
