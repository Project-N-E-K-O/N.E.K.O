# 猫形态串门维护设计

> 文档性质：当前已实现行为的长期维护基线，不再记录实施阶段。后续修改入口、交互、归属规则或退出行为时，应同步更新本文和对应验收。

## 1. 产品定位

猫形态串门是现有串门的一种单场形态，不是另一套串门系统。好友关系、邀请、房间、身份、掉线恢复、时长限制和退出继续复用现有能力。

当前边界：

- 通用好友入口只发起模型串门，不再展示猫形态选项。猫形态保留既有邀请、房间、接收和运行能力，供后续猫原生触发方式复用。
- 新触发方式落地前，当前客户端没有主动发起猫形态串门的可见入口。
- 邀请码保留为模型串门的兼容入口，不承担猫形态主流程。
- 猫形态只同步猫和共同物件的可见状态，不传音视频，不生成串门对话、记忆、回家仪式或转录。
- 普通模型串门保持原有流程和表现。

## 2. 可见流程

1. 用户从通用好友入口邀请在线好友时，只发起模型串门。
2. 客户端收到合法猫形态邀请时仍允许接受或拒绝；接受后直接入场，不再增加“门外有只猫”的第二次确认。
3. 双方进入同一个双猫场景：本机猫继续由本机运行，对方猫显示其主人设备产生的结果。
4. 两只猫独立移动和做动作；共同物件及共同碰撞采用房主端自动计算的统一结果。
5. 任一方退出、掉线超时或返回模型时，复用现有离房与房间释放流程。
6. 退出成功后恢复本机模型；退出失败或取消确认时继续保持猫形态。

猫形态接收路径只有“接受进门”和“确认退出”需要人的确认。走路、拖拽、动作、共同物件运动和碰撞均由程序自动处理。

## 3. 表现与归属规则

### 双猫识别

- 同一界面同时显示本机猫和来访猫，两只猫不固定左右位置，可在现有单猫允许的屏幕范围内自由活动。
- 外观、资源和位置都不能作为身份依据；始终用跟随在猫上方的“我的猫／对方的猫”标签区分归属。
- 即使双方使用相同 GIF，标签也必须稳定对应，不能因重载、交叉移动或动作切换而互换。

### 各自主人的猫

- 本机猫继续使用现有单猫实例及其拖拽、移动、重力、边缘、跟随、层级和 Playground 等能力，不复制第二套本地主猫状态机。
- 每只猫的主人设备是该猫状态的唯一来源；一只猫移动或切换动作不能带动、覆盖或隐藏另一只猫。
- 对方设备只还原可见结果，不复制主人设备的窗口结构，也不能反向控制来访猫。
- 官方猫资源由各端本地调用；跨端只需识别资源组和对应动作，不传 GIF 文件。

### 房主统一的共享结果

- 毛线球等共同物件，以及两只猫与共同物件或彼此发生的共享碰撞，由房主端统一计算。
- 客方提交操作意图；房主端依据已生效的房主设置和同版本规则自动产生结果，再同步给双方。
- “房主统一”不是逐步人工确认，也不改变“每个人控制自己的猫”。普通走路、拖拽和独立动作不经过房主重新计算。
- 普通猫形态串门不额外显示问号块。以后若扩展问号玩法，必须复用现有 Playground 的可见入口，不默认添加常驻物件。

### 返回模型与退出

- 猫形态串门期间不允许单独切回模型继续留在房间。
- “送客／叫她回来／立即结束”和“返回模型”共用一个无标题的猫形态退出确认：“是否退出猫猫串门”，操作为“确定／取消”。
- 取消时不改变任何一只猫；确认后复用现有退出流程，退出成功后才恢复本机模型。
- 该确认只对猫形态生效，不改变模型串门的退出行为。
- 对方始终只作为来访猫显示，不出现对方模型返回流程。

## 4. 维护约束

- 不新建第二套邀请、房间、重连、退出或占用释放逻辑；形态只是单次邀请及当前房间的属性。
- 通用好友入口不得再通过并排形态按钮暴露猫形态；后续猫原生触发方式只调用既有猫形态邀请链。
- 保持两类权威边界：各自主人的猫由各自主人的系统决定，共享世界由房主端自动决定。
- 猫资源、猫动作和共享物件相互独立；增加共同玩法不能接管两只猫的状态机。
- 连续移动允许采用最新结果，稳定动作和共享世界最终状态必须能够在重载或重连后恢复。
- N.E.K.O-PC 只让猫、共同物件和退出控件所在的有限区域接收点击，不能把透明全屏窗口变成可点击层。
- 猫形态关闭时，普通串门必须完全保持原行为；形态不兼容时明确结束，不能静默切换成模型串门。
- 现有发布开关继续作为猫形态的整体回退手段，不再增加分散的子开关。

## 5. 回归验收清单

- 在线好友行只显示一个“邀请来玩”按钮，并且只创建模型串门。
- 通用好友入口不显示猫形态选项，也不能创建猫形态邀请。
- 收到合法猫形态邀请时仍只接受或拒绝，不出现第二次形态选择或门外确认；接受后进入双猫场景。
- 双方同时移动、拖拽或切换动作时互不覆盖；拖拽本机猫不会隐藏对方猫。
- 两只猫自由交叉移动且使用相同资源时，归属标签仍正确跟随。
- 双方最终看到一致的共同物件位置和碰撞结果；客方不能覆盖房主结果。
- 丢包、乱序、重载和重连不会造成猫身份互换、旧姿态回跳、重复动作或重复物件。
- Windows、X11、Niri/Hyprland 和 Electron 双窗口保持双猫可见、有限点击区域及远距离双猫裁剪。
- 猫形态的普通退出与返回模型显示同一确认；模型串门退出不显示该确认。
- 取消退出继续留在猫形态；退出失败不返回模型；退出成功后房间和桌面状态均正确释放。
- 猫形态没有音视频、串门对话、记忆、转录和回家仪式；普通串门无行为回归。

## 6. 当前验证边界

- 自动化测试已覆盖邀请形态、双猫独立状态、共享世界收敛、可靠恢复和桌面稀疏输入区域；真实双账号、双设备的完整可见流程仍需发布前手动验收。
- `yui_neko` 当前仍有部分动作使用开发猫 GIF 占位。身份识别不依赖外观，但正式形象差异取决于后续资源替换。
- N.E.K.O-PC 的跨平台窗口规则已有契约测试，真实 Windows、X11、Niri/Hyprland 环境仍需逐平台确认。
- 官方客户端不会发布或订阅音视频；Connect 当前仍发放通用串门房间能力。若未来把“禁止媒体”提升为防篡改安全要求，应在 Connect 建立通用数据房间策略，而不是把猫业务规则写进社区服务。
