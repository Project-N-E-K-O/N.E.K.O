## 复核结论：方向保留，事实边界已校正

对照当前工作副本和 DiceFrame `2bbfe2e8` 的源码后，本文方案可以继续作为候选路线，但以下边界必须以本版为准：

1. **N.E.K.O 不是完全没有事实投影。** `numeric_v2_runtime.py` 已有 `FACT_PROJECTION_SCHEMA` 和 `deterministic_events`，但其 `semantic_status` 明确是 `evidence_only`，不能作为“当前世界为真”的写入权威。P0-1 的缺口是新增语义事实账本，不是重复建立一份演出证据表。
2. **DiceFrame 的引用提交已经包含 WorldState v2。** `src/engine/world_state.py` 在该提交中已有 Entity、Relation、Process 容器；因此“参考实现仍只有 v1、没有实体图”不再成立。N.E.K.O 不做这三类容器应表述为**本产品的范围取舍**，不能写成 DiceFrame 当前能力的事实。
3. **结构化通道名称是 N.E.K.O 的候选命名。** DiceFrame 同一类机制的实际字段包括 `overreach`、`world_requirements` 和 `world_time_advance`（见 `src/llm/tools.py`）。本文的 `asserted_events`、`ownership`、`elapsed_markers` 只能作为 N.E.K.O 的适配设计，不能暗示直接复用上游 schema。
4. **N.E.K.O 已经有一部分提交保护。** 当前已有 `base_revision`、`client_turn_id`、Ledger revision 链、重复回合拒绝、Session 锁和原子替换。P1-2 应先做行为审计，再补“长调用返回后的 stale 丢弃”和明确的重放语义；不能把它描述成从零新增幂等与版本控制。
5. **“新增模型调用 0”只表示不增加网络请求。** 新的结构化通道仍可能增加输出长度、解析成本、输入 token 和 P95；每个阶段必须记录 token、调用耗时和失败降级，不能把“调用数不变”写成“延迟不变”。

本节是方案的校准记录；下方“实施记录”只标记已经由代码和测试验证的部分，不把候选设计提前写成现状。

## 实施前补充约束（按本项目决定收口）

本方案实施时**不保留旧剧本包字段、旧工坊报告字段或旧 Session 的兼容读取链**。小剧场运行端、剧本工坊 SDK、当前剧本包 schema 和测试夹具必须在同一轮修改到新字段；旧版本数据不删除，但遇到不支持的 schema 直接报告 `unsupported`，不做猜测迁移、不静默补字段、不同时维护两套语义。

这意味着：

1. `repairable` 可以直接替换为 `repair_class`，同步修改工坊 SDK、报告生成、优化入口、发布校验、测试夹具和文档；不做双写兼容。
2. 合同字段若确定合并或改名，直接更新当前剧本包字段及编译器；旧字段不再作为运行时输入。发布前必须完成正式剧本包的批量字段更新和 schema 版本提升。
3. 新增 `story_state` 只服务当前 N.E.K.O 小剧场 Session；它不是旧包迁移层，也不承担恢复旧 Session 的职责。
4. 任何破坏性字段调整都必须在同一变更中更新：运行端读取、工坊写入、编译器校验、HTTP 错误码、测试夹具、问题文档和架构文档。

### 1. 第一版事实白名单

第一版只实现四类事实：

- 角色或玩家当前位置；
- 关键道具归属；
- 已完成的作者声明动作；
- 作者声明的时点标记。

暂不引入通用 Entity / Relation / Process、自动剧情目标、自由事实键、地图寻路或事实向量检索。事实键必须来自编译后的剧本合同或 Runtime 已登记的固定枚举，模型不得创建新键。

### 2. 事实写入依据

| 事实 | 允许写入依据 |
| --- | --- |
| 位置变化 | Runtime 已确认的路线或正式转场结果 |
| 道具归属 | 剧本合同、已提交交付结果或确定性物品操作 |
| 已完成动作 | 玩家输入与 Runtime 结算共同确认 |
| 时间推进 | 作者明确标记或确定性转场，不接受模型自由估算 |

模型输出的结构化通道只产生候选；候选必须同时通过 Session、Ledger、当前幕合同和事实白名单校验，才可进入 `apply_fact_ops`。

### 3. 冲突处理矩阵

| 情况 | 处理 | 是否提交 |
| --- | --- | --- |
| 已确认矛盾，且会改变玩家可见事实 | 提交前拒绝、删除或要求同轮改写 | 否，直到候选合法 |
| 已确认矛盾，只影响下一轮叙事约束 | 写入诊断并生成服务端约束块 | 当前回合可提交，约束进入下一轮 |
| 信息不足 | 不写入事实，不阻断合法行动 | 是 |
| 事实账本或剧本 schema 损坏 | 整轮失败并保留错误码 | 否 |
| 旧版本剧本包或 Session | 返回 `unsupported`，要求使用当前版本重新导入/开始 | 否 |

### 4. 性能与可观测性门槛

“不增加模型网络调用”不等于没有性能成本。每次压测必须同时记录：Actor/Evaluator 输入与输出 token、事实投影耗时、JSON 解析耗时、P50/P95/P99、协议失败率、降级次数和提交拒绝率。新增结构化通道若使 P95 超出当前基线，必须先缩短字段或减少投影内容，不能以“调用次数没增加”直接放行。

### 5. 灰度与回退

事实账本按三个阶段启用：

```text
disabled → 只生成诊断，不影响提交
shadow   → 执行裁定并记录结果，但不阻断提交
enforce  → 合法性裁定正式控制提交
```

灰度期间只允许回退开关和当前代码版本，不回写或删除已经产生的事实。进入 `enforce` 前，提前到达、重复演出、归属漂移各至少保留两条冻结正反例，并完成一次完整路线压测。

### 6. 完成门槛与非目标

完成 P0 必须同时满足：旧字段已从当前剧本包和工坊链路移除；新字段从工坊写入、编译、运行到提交保持一致；不支持的旧 schema 明确失败；冻结反例不回归；新增模型网络调用为零且 P95 在预算内。

本方案不负责提升整体文学质量，不自动生成剧情目标，不替玩家做决定，不把模型断言直接当作事实，也不引入跑团引擎的通用世界模型。

## 0. 摘要

一句话：把现在的"**先让模型写散文 → 再让模型判散文 → 再让模型改散文**"，换成"**先定事实 → 再写散文 → 提交时逐字段放行**"。

| N.E.K.O 现有问题 | 可借鉴机制 | 落点 | 新增模型调用 |
| --- | --- | --- | --- |
| 没有可写入的"当前为真"语义事实账本，重复／提前演出／归属漂移反复出现 | 权威事实容器：canonical 键 + 单调 revision + 可见性 + 唯一写入口 + 有界投影 | 在现有 evidence-only 投影之外新增运行期事实账本，作为 Actor 提示与判定的共同依据 | **0 个新增网络调用** |
| 复核能发现、修不好（问题2.143：3/3 轮判对修不好） | 结构化提议 → 服务端裁定 → 渲染"必须遵循"约束块；可核对断言下沉到确定性层 | evaluator 增加可选通道 + Runtime 放行层 | **0**（搭在既有 evaluator 调用上） |
| 每回合至少一次判定 + 一次正文，约 6.4 秒下限 | 一次调用承载多个互相独立的判定通道；失败有确定性兜底 | evaluator 单次调用承载归属/边界/时间断言 | **不增加网络调用** |
| 复核的误杀／漏放没有制度性度量，工坊"发现问题强、修复问题弱" | 字段归属分类（可修／不可动／不可解析）、先验证后提交、摘要绑定不可变、blockers 与 advisories 分离 | 工坊的 `repairable` 语义与发布流程 | 0（编译期） |

不要做的三件事：不要把权威字段交给启发式 JSON 修补；不要把"字符数"当 token 预算；不要用"再问一次模型"当作主要修复手段。

## 1. 现状与问题的精确对应

### 1.1 提前演出：判对但修不好（问题2.143 实测）

三轮真实压测（run-D、run-D2、run-D3）各出现一次同类形态：换场的 `transition_bridge` 把**目标幕开场**的到达与晚霞写了进去，来源幕的 `must_not_happen`（"不得直接到达最高处平台"）被违反。

- 窄判定**判对了**（r37 冻结回放返回两项禁令，同幕"尚未到达"不误报）；
- 改稿后复检**仍然命中**，最终按"不阻断提交"的既有策略提交，玩家看到的仍是提前到达；
- 三次运行都在同一个位置复现，说明这不是采样抖动，而是**生成条件**问题：作者边界以自然语言形式存在，模型每轮都可能越过，而唯一的修复手段是"带着理由重写一遍散文"。

结论：提前演出不是"判定器不够准"，而是**缺少让这件事无法发生的确定性条件**。

### 1.2 重复与归属：没有可查的"已发生事实"

当前 Session/Ledger 保存的是**已提交演出**与数值轨迹；判定器与 Actor 各自从历史文本里理解"发生过什么"。于是：

- 同一事件换措辞重演（问题2.142 已核实多处重复扣分）；
- 归属漂移（玩家动作被写成角色完成）；
- 时点提前（F3 确定性检查只在普通回合做时点粒度核对，历次压测命中 0 次，说明它覆盖面很窄）。

### 1.3 延迟：下限来自调用链，不来自实现细节

单次调用 P50：演员约 4.5 秒、快检约 2.1 秒、前置判定约 1.9 秒、争议复查 15 秒（历次 8/8 超时）。保留判定的每回合下限约 6.4 秒。`review_contract` 开启后净代价约 +0.75 秒 P50 / +1.7 秒 P95（run-D3 对比 run-C）。

结论：**新增检查必须零调用**，否则下限继续上移。

### 1.4 工坊：发现能力强于修复能力

`assess_quality` 能给出 major 级问题，但本轮两个包里多项问题 `repairable=false`、`repair_node_ids=[]`、证据复核 `unsupported`，没有可执行的自动修订；`quality_assessment_stale` 又要求每次改稿后重评。生成侧也脆弱：standard 档 3/3 次 120 秒超时，只能降到 short。

## 2. 六条设计纪律（先定原则，再谈实现）

1. **事实只有一份权威。** 任何"当前为真"的状态只能有一个容器、一个写入口；记忆、摘要、日志都不得再记一份"当前世界"（DiceFrame 把这条写成明确禁令）。
2. **模型只提议，不写权威。** 模型输出永远是 candidate；写权威必须经过确定性校验。
3. **两种检查用相反的极性。**
   - 阻断玩家／阻断演出的检查：**未知不阻断**（没有证据就不许拦），只有"已证明的矛盾"才拦；
   - 放行推进的检查（出口、结局、章节 gate）：**证据不足不满足**，绝不凭"不知道"放行。
   现在这套框架两种检查混用一个 fail-open 策略，是窄判定误报与出口误放行的共同来源。
4. **可核对的不要问模型。** 归属、持有、数值带、去向公开、是否已到达，能由字段判定就不发调用；模型只处理真正语义性的部分。
5. **新增信号搭在既有调用上。** 任何新判定都以"可选、独立、缺失不影响主输出"的通道形式挂在 evaluator 调用里。
6. **修复优先级：确定性 > 同调用一次重述 > 改稿。** 丢弃/夹取/模板约束能用就不用模型。

## 3. P0-1：运行期事实账本（scene facts）

### 3.1 目标

给每一局提供一个"当前为真"的唯一容器，让 Actor 与判定器看的是**事实**而不是对历史的自由理解；让"提前到达""重复演出""归属漂移"从"事后判定问题"变成"生成条件问题"。

### 3.2 形状（建议）

```text
story_state
├─ schema_version
├─ revision                       # 每次成功提交 +1
├─ facts
│   └─ <canonical key> = {
│         value,                  # 标量：bool / 短字符串 / 数值
│         visibility,             # N.E.K.O 自有语义；不要直接复用 DiceFrame 的 gm 字段名
│         source_revision,        # 由哪次成功提交写入
│         client_turn_id,         # 与现有 Session/Ledger 回合身份绑定
│         updated_revision
│      }
└─ scheduled_markers             # 可选：作者声明的时点标记（见 3.6）
```

约束（借鉴 DiceFrame 的权威边界；字段名和可见性按 N.E.K.O 自己的当前契约定稿；旧 schema 不做自动迁移）：

- **键必须是 canonical 机器串**（建议 `[A-Za-z0-9_.:-]`，如 `character:xiaokui.location`、`item:map.owner`、`event:viewpoint_platform.reached`），**不得使用展示名**——否则翻译或改名会变成身份变化。
- **唯一写入口**：一次批量 op（`apply_fact_ops`），先把整批应用到副本，**全批合法才提交**，revision 恰好 +1，键按字典序持久化（存档 diff 与测试不依赖插入顺序）。
- **fail closed 清单**：未知 op、未知字段、非法键、非法标量、坏 schema、未来 schema 一律拒绝。
- **有界**：事实条数、单值长度、单批 op 数都要有上限。
- **读取路径与写入路径共用同一套形状校验**：损坏的持久化数据不能被"静默归一化"成看似正常的状态。

### 3.3 读半边：有界投影

单独一个只读投影函数（建议 `project_scene_facts(...)`），产出 Actor 提示与判定输入共用的材料：

- 按 visibility 过滤（`story` 级事实绝不进入玩家可见材料）；
- 只保留与**当前幕、在场角色、当前持有物**相关的事实；
- 有上界并带 `truncated` 标记；
- 携带 `revision`，便于诊断与 stale 判定。

这一层是纯函数、零调用，也是替代"按需查 Session 原文"（12 秒预算）的主要手段。

### 3.4 边界（不要做）

- **不做** Entity / Relation / Process 图谱。这是 N.E.K.O 的产品范围取舍；引用的 DiceFrame 提交已经包含这些容器，但单机叙事剧场当前不需要为它们引入持久化和迁移成本。
- **不把事实复制进记忆/摘要**。记忆只晋升"结构性变化"（见 3.5），当前事实的权威始终是账本本身。
- **不新增并列 authority**。账本挂在既有 Session 聚合内，不新建第二份存档。

### 3.5 结构性变化才进长期记忆

提交时产出的结构化变更凭据（append-only，形如 `revision:position:kind`），只有一小类**白名单**可以晋升为跨幕记忆：人物进入/离开、物品易主、关系变化、承诺成立、阶段状态落定。**普通事实变更不晋升**——否则会形成"记忆里的当前世界"这第二真相。

### 3.6 作者合同 → 事实谓词

把 `must_not_happen` / `scene_boundaries` / `must_deliver` / `must_preserve` / `endings` 里**可核对**的部分映射成事实谓词，其余保留为文字边界（明确标注"仅提示、不核对"）。判定标准建议：

| 合同表述类型 | 能否结构化 | 处理 |
| --- | --- | --- |
| "不得到达／不得离开某地"、"不得逆转某结果" | 能 | 事实键 + 前置条件，提交时确定性核对 |
| "必须交付某道具"、"必须保留某事实" | 能 | 事实键（持有/出现），已有交付核对可复用 |
| "不得预设某时点已经发生"（如"不得预设晚霞已经完全展开"） | 能 | 作者声明的时点标记（`scheduled_markers`），未推进不得为真 |
| "不替玩家选择或执行动作"、"不拖长篇幅" | 不能 | 保留为文字边界，归复核或直接不核对（本轮已按此过滤） |

### 3.7 验收判据

- 晴川镇 `nodes[11]` 的冻结反例（r36 不报、r37 报）在事实账本下表现为：**"到达"只能由 op 驱动**，普通回合写出到达时在**当轮**被拦，而不是等下一次换场；
- 不增加模型网络调用，并单独记录新增通道带来的 token、解析耗时和 P95 变化；
- 同一局重复提交不产生第二次事实写入（与第 6 节幂等一起验）；
- 反例集：提前到达、重复演出、归属漂移各至少 2 条，全部先在冻结文本上回放，再跑一次完整压测。

## 4. P0-2：结构化提议 → 服务端裁定 → "必须遵循"约束块

### 4.1 做法

1. **evaluator 单次调用新增可选通道**：例如 N.E.K.O 自有的 `asserted_events`（本回合正文里声称发生的事实）、`ownership`（谁做了什么）、`elapsed_markers`（推进了哪个时点）。它们借鉴 DiceFrame 的独立附加输出；上游对应的是 `overreach`、`world_requirements`、`world_time_advance`，不能直接共用字段。每个通道：闭合枚举 + 条数上界 + **独立解析与容错**（一个通道畸形不影响数值/路线主输出）+ 明确写"不确定就留空"。
2. **Runtime 裁定**：拿账本 + 作者合同逐条核对。三种结果：
   - 合法 → 由 Runtime 写入事实（唯一写入口）；
   - **已证伪且会改变玩家可见事实的矛盾** → 在提交前拒绝、删除或要求同调用改写；不能只在提交后追加提示块；
   - 已证伪但只影响下一轮叙事约束的矛盾 → 可以渲染本地化模板块进入下一轮提示；
   - 信息不足 → 不写入权威状态，也不阻断合法行动（纪律 3 的第一种极性）。
3. **约束块的措辞是负向的、服务端拼装的**，例如"以下行动与既有事实矛盾：请叙述为尝试与世界的反应，不得叙述为已经发生"。它是纯函数模板，不是模型生成的建议，也不接受玩家注入。

### 4.2 与 `review_contract` 的关系

现在这个窄判定之所以"判对修不好"，是因为它核对的是散文，而唯一的修复是重写散文。做完 3、4 两节后：

- **能结构化的事实类禁令**移出窄判定，改由账本 + 裁定处理；
- 剩给窄判定的只有"不可结构化且值得一次调用"的部分；如果这部分收益不足以覆盖成本，**建议整体退役**（保持默认关闭，并在文档里写清它覆盖不到的事实类边界已由账本接管）。

### 4.3 验收判据（本轮已有现成基线）

| 控制项 | 期望 |
| --- | --- |
| 越界文本"抵达观景坡侧步道的顶端平台"（r37） | 被拦下/不提交该事实 |
| "还差最后几级台阶"（r36） | 不报 |
| 邀请与自主动作（run-D r1/r5/r13 原文） | 不报 |
| 正常换场来源侧（run-C r38） | 不报 |
| 送全段（含目标幕开场） | 必须仍被判为越界（这正是裁剪前的误报来源，作为负向对照保留） |

这些控制项本轮已经跑过一次，可以直接固化为回归资产。

## 5. P1-1：逐字段放行／夹取／丢弃（把"修复"从模型挪到确定性层）

参考实现里最直接可用的一条：模型可以叙事，但**没有服务端依据的写入会被丢弃并留审计**（例如没有失败判定支撑的伤害标签直接丢弃、越界数值按上界夹取、货币变更直接忽略）。

### 5.1 字段归属表（每条合同字段都要有归属）

| 类别 | 例子 | 处理 |
| --- | --- | --- |
| 派生／技术字段 | 由作者定义可直接推得的道具身份、幕号、阶段 | 与权威定义冲突时**修正** |
| 作者／玩家自有 | 文案、自定义描述、玩家命名 | **永不自动改动** |
| 不可解析 | 找不到对应定义 | **只警告并忽略其效果，不猜、不删** |

### 5.2 丢弃与夹取都要留审计

每次放行/夹取/丢弃都写一条结构化诊断（原因码 + 字段 + 期望 vs 实际），进现有 `workflow_diagnostics`。**"丢弃"不是错误**，而是可解释的正常路径；没有审计的静默丢弃等于把问题藏起来。

### 5.3 两种撤销语义必须分开

- **本次中止**：本轮尚未提交 → 回到玩家输入前，保留已确定的事实/判定；
- **已提交回合回滚**：历史改写 → 连同该回合之后的事实与结构性记忆一起撤回（参考实现的 ADR 明确"回滚到第 N 轮就抹掉第 N 轮之后的整个时代"，而不是"选择性反转"）。

不允许出现第三种"半回滚"。

### 5.4 验收判据

- 未授权写入、越界数值、无依据的结果性写入，必须被丢弃且留原因码；
- 提交原子性不下降（全或无）；
- 回滚后重放同一轮得到相同结果（确定性）。

## 6. P1-2：提交幂等与 stale fence

当前已经有原子提交、`base_revision`、`client_turn_id`、Session 锁和 Ledger 链校验；本节只补齐重放和长调用返回后的边界，不另建第二套回合身份：

- **内部批次指纹（可选）**：如果需要区分“同一请求重放”和“同一客户端 ID 的冲突请求”，由服务端基于现有 `client_turn_id + expected_revision + 规范化输入` 派生，不新增客户端可见的第二个身份；必须先决定重放是返回原结果还是保持现有错误语义，并用测试固定下来；
- **乐观版本**：提交时校验 `expected_revision`，不符即拒绝（而不是"尽力覆盖"）；
- **先在副本上 reduce**，全部成功才落盘；
- **stale fence**：长调用（演员、复核）返回后复验 Session 身份与 revision，过期响应直接丢弃，不覆盖新状态。有了它才敢收紧超时。

验收：同一轮重复提交不二次落账；乱序到达的旧响应不覆盖新状态；崩溃恢复后 revision 链完整。

## 7. P2-1：上下文分层与历史梯（省 token，顺带减少重复）

参考实现把上下文按分节预算组织，并规定了明确的收缩顺序（先砍历史，再砍低价值外设，**状态与合同最后砍**）。N.E.K.O 当前 Actor 输入上限是 10000、Evaluator 是 7000，不能再用“整包 7000”描述现状。可以借用的三点：

1. **分节预算 + 收缩顺序**：替代当前各阶段分别设上限、但缺少统一收缩优先级的做法，让合同与事实在超限时仍有保障。
2. **历史三级梯**：最近 N 轮逐字；命中关键词的关键轮（揭示／冲突／决定／易主）也逐字；其余压成单行；更早交给摘要。关键词表要按中文叙事剧场重写，参考实现那套是跑团词汇。
3. **"已确认事项"块**：一小串"已经落定、不要重复解释"的短句，带明确指令"玩家再问就推进"。

**与参考实现的关键差异**：这个块的来源必须是**已提交的合同节拍与事实变更**，不能像参考实现那样来源于模型自报的标签——否则又是"模型写事实"。

另外建议修一处提示词排序：把**稳定内容放前面、易变内容放后面**（历史连续追加），这样前缀缓存才有机会命中；参考实现的顺序恰好相反，是反例。

## 8. P2-2：工坊（剧本工坊）

DiceFrame 的角色状态 reconciliation 并不提供 N.E.K.O 工坊的分级评分、证据复核和 `repairable` 契约；这里借用的是**变更决策层**，不是把上游能力评价为完整或不完整：

1. **直接用 `repair_class` 替换布尔 `repairable`**：`derived`（可重算，自动修）/ `coercible`（枚举与数值归一，记录默认值）/ `authorial`（作者自有，必须人来改）/ `unresolvable`（警告 + 中性化其影响，保留数据）。同步修改 SDK、报告、优化入口、发布校验和测试夹具；旧报告字段不做兼容读取。
2. **先验证后提交**：每个优化先应用到副本 → 用**真实编译器/校验器**读回一遍 → 通过才原子替换。优化器不需要被信任，验证器才需要；这是"评审发现问题"与"自动修复"之间缺失的那一环。
3. **证据门槛显式化**：模型断言必须附可核对证据（节点、字段、观测值、来源），拿不出证据的问题**按设计**停在"需要人处理"，而不是"没修成"。
4. **摘要绑定不可变**：包一旦被导出/安装/被存档引用就转只读，改动产生新版本与新身份——顺带解决"这份评分报告说的是哪一版"。
5. **blockers 与 advisories 分离**，且**同一个校验器同时服务预览、API 与命令行**，杜绝"预览说有 blocker、保存却通过"。
6. **合同字段收敛**：每个字段只留一个归属点，闭合枚举，**未知字段硬报错**——这是治 `must_not_happen` 与 `scene_boundaries`、`bridge_scene_narration` 与 `must_deliver` 语义重叠的正解（按作用域定归属，而不是靠措辞区分）。
7. **发布纪律**：当前剧本包字段由工坊和运行端同一轮切换；schema 版本提升后，旧包直接 `unsupported`。不做启发式字段迁移，不静默覆盖作者数据；需要保留旧内容时由作者重新导入或重新发布当前版本。

## 9. 工程制度（成本最低、收益最长）

- **ADR（Context / Decision / Consequences）**，并在其中写清**删掉了哪些旧机制、为什么**。现有问题文档的"已退役方案"已经有这个内容，缺的是按决策归档的形态。
- **按"触碰了什么"分级风险**：内部实现 / 架构边界 / 对外契约 / 持久化与权威。第四级必须优先保证数据正确性与确定性，不能为"自动兼容"猜用户数据。
- **架构适应度函数**：用 AST 扫依赖（含函数内延迟 import），把权威边界写成可执行断言（例如"演员层不得引用账本写入接口""Runtime 不得调用模型""Store 是唯一提交者"）；存量违规用**只减不增的白名单**，白名单条目过期同样判失败。
- **"测试保护契约，不保护实现"**，并维护一张"必须始终有覆盖的高风险区"清单。
- **显式"当前不具备的能力"清单**，防止文档漂移把建议读成现状（本文自身也遵守这条）。

## 12. 明确不采纳

**参考实现自身的问题，不要一起搬过来：**

1. 对权威字段做启发式 JSON 修补（补引号、补括号、改写字符串内容，且只记一行 info 日志）——比解析失败更危险；
2. 用字符数当 token 预算，并按模型名子串匹配窗口；
3. 一个模型跑所有角色，且安全关键的那条腿（判定）没有传输重试，叙事腿反而重试三次；
4. 叙事结构解析失败时静默降级（只保留散文、状态静默失同步，连续三轮才提示）；
5. 宽松有损的剧情追踪（按标题匹配、字符串或字典都收、静默改层级）——正是"第二真相"；
6. 世界书里的概率/粘滞/冷却与模块级模糊匹配——对版本化、有作者合同的剧本，`must_deliver` 被概率跳过是正确性 bug，不是风味；
7. 用"系统提示里存在某句话"的断言当作安全保证；
8. 直接复制其代码（AGPL-3.0 与本仓库许可不同）。

**本轮范围之外、不做的**：实体/关系/过程图谱、地图寻路、嵌入向量检索、多人权限、经济与战斗子系统——这些是跑团引擎的必需品，不是叙事剧场的必需品。

## 34. 全开压测问题归因

本轮没有新增代码，先完成失败样本归因。

1. **场景停滞不是状态机错误。** 森林剧本在第 3 回合已完成触碰检测，第 4 回合确认读数熄灭；模型仍在第 5 回合继续询问不存在的记录，第 6 回合才提出蘑菇村。作者稿已明确稳相环不存储记录，问题是 Prompt 没有把检测完成、无记录和下一步公开去向绑定为一个交付单元。

## 48. 压测停滞警告的回合前状态校准

`stalled_scene` 过去只看回合结束后的节点回合数和邀请状态。完成事实在 Actor 输出后经复核首次接纳时，压测器会在同一回合要求正文已经带出出口。这与真实时序冲突：该事实在生成时尚未进入已提交账本，Actor 不能读到未来的复核结果。

压测执行器现在于每次 Actor 调用前记录 `completion_contract_status_before_turn`，值为 `undeclared`、`pending`、`satisfied` 或测试替身无法判定时的 `unknown`。`stalled_scene` 只在以下条件同时成立时记录：

- 本回合生成前完成合同已经是 `satisfied`；
- 仍留在原节点，本回合也没有有效待确认邀请；
- 节点回合数超过作者 `recommended_turns` 的软窗口。

同轮从 `pending` 变为 `satisfied` 时不再报警；若下一回合已能读到完成状态却仍未公开出口，原有警告会继续触发。这只修正压测证据的判定时点，不修改 Runtime、Workflow、模型 Prompt 或路线状态。

## 49. 普通快检价值审计与自相矛盾结果归一

本轮先审计普通快检是否存在可安全整段跳过的结构化范围，再处理真实日志中的矛盾结果。结论是：**不能为了省约 2 秒直接跳过普通快检**。

### 跳过方案审计与否决

- 对 `/private/tmp/neko-theater-*-traces/` 中 182 条普通快速复核结果做离线统计：82 条没有改变状态，100 条产生实质结论；其中邀请判断 28 条、完成事实 27 条、邀请与事实同时出现 17 条、不安全推荐 13 条、正文违规 8 条，其余为组合结果。
- 即使限定为“无场景旁白、无待确认完成事实”，31 条中仍有 13 条产生实质结果，包括 6 条邀请、4 条不安全推荐和 3 条正文违规。现有结构化输入不足以证明某个普通回合可以安全免检。
- 因此没有接入“普通对话直接跳过复核”，也没有按无旁白、无完成事实或无转场标志建立放行白名单。压测汇总新增普通快检总数、无状态变化数、实质结果数及各类决策计数，后续优化必须用这些指标证明净收益。

第一次全开核验 `/private/tmp/neko-theater-zero-review-value-report.json` 也支持该结论：11 个回合全部提交，8 次普通快检中 6 次产生实质结果，包含 4 次邀请判断和 5 次完成事实候选；主轨迹中位 **9.310 秒**，最大 **17.303 秒**。日志为 `/private/tmp/neko-theater-zero-review-value-traces/`。

### 两类自相矛盾的确定性归一

首轮日志同时暴露一类窄问题：复核把旁白“地下信标室·检修入口”标成邀请，但失败理由又明确写“正文仅公开入口位置，未发出明确邀请”。Workflow 现只在以下条件全部成立时清除邀请标志：普通回合、无正文违规、引文只来自旁白且不在角色对白、理由同时包含“正文仅／未发出／邀请”。真实对白邀请和错误目的地均不命中。新增 `narration_offer_flags_cleared` 与 `review.narration_offer_cleared`。

## 51. 主动换场补查的结构化证据前置

第 50 节把“玩家明确要求前往已公开去向、正文仍停在当前幕边界前”的误杀留作下一项。复查真实工作流后确认，这类回合并非只依赖普通正文枚举：当前置 Evaluator 漏判 `initiate` 时，同一次普通快检还会执行 `missed_initiation` 补查；补查成功后，Workflow 会丢弃普通稿，重新生成并复核正式三段换场。

### 根因

- 第一版固定集直接调用普通复核，没有启用生产链的补查字段，因此不足以证明最终工作流是否恢复换场。本轮把固定集提升为 `ordinary_review_zh_cn_v2`，让显式移动样本启用真实 `check_missed_initiation`，并把恢复结果纳入独立指标和整例计分。
- 修正评测入口后，问题仍真实存在：修复前定向探针连续 **3/3** 返回 `missed_initiation=false`，没有公开引文；另一次 10 次探针中，普通正文仍有 9 次被报 `scene_boundary`。
- 实际发送的数据已经包含玩家原话、当前出口和公开去向，但三项分散在 3000 Token 以上的普通复核数据中；补查合同又追加在长系统提示末尾。模型会先套用“接受前不得进入”的边界，再把本轮“带路吧”误读成尚未接受。
- 输出合同还存在一处明确错误：代码尝试把“固定五字段”替换成扩展字段说明，而实际提示写的是“固定六字段”，所以替换从未生效。

### 处理

- 补查开启时，在待审 JSON 最前面新增 `missed_initiation_check`，只包含 `player_request`、`required_exit` 和编号后的 `public_destination_evidence`。公开证据仍只来自本次场景访问中真实播放的演绎原文，候选正文、玩家当前输入和作者预览都不能自证去向已公开。
- 将补查合同放到普通正文合同之前，要求先独立核对这个结构化对象；明确“本轮要求出发本身就是当前授权”，同时继续拒绝询问、准备、考虑、含糊同意、错误目的地和无公开原文的请求。
- 修正六字段扩展说明。模型输出的证据编号仍由代码映射回同次请求实际发送的原文，并通过 Session 逐字复核；模型不能自行填一段文本获得转场授权。
- 固定评测报告升级为 `neko.numeric_v2.review_eval.v2`，新增 `missed_initiation_recovery`、漏恢复和意外恢复样本列表。正文安全与恢复授权继续分开计分，不能把补查成立解释成普通稿自动放行。

## 52. 事实候选隔离、完成时态保护与 Prompt 去剧本化

本轮同时处理第 51 节的事实批次连带丢弃，以及运行端和剧本工坊 Prompt 逐轮积累历史剧本示例的问题。原则是：**校验规则表达状态、证据与权限，不写某个剧本的地点、角色、道具或固定动作答案。**

### 事实候选逐项核验

- Workflow 不再把普通复核与 Actor 的所有事实候选作为一个校验批次。已提交的同值事实先按 `already_committed` 忽略，同一回合已入账的同值候选按 `current_turn_duplicate` 忽略；其余候选逐项调用原有 Runtime 严格校验。
- 单项仍须通过事实白名单、值类型、可见性、确认状态和逐字证据检查；失败只增加该项的拒绝计数。所有通过项仍留在未提交 `outcome`，最后与正文、Session 和 Ledger 一次原子提交，没有把回合提交拆成多次写入。
- 定向集成回归覆盖“旧事实 + 无效引文 + 本轮合法事实”同批输入：旧事实保持、坏项不落账、合法项正常提交，诊断为接纳 1、拒绝 1。

### Prompt 去剧本化审计

- 审计运行端 Evaluator、Actor 相关消息，以及工坊主线生成、续写、节点完善、支线、评分、优化和事实复核共享 Prompt。删除当前压测剧本及历史回归剧本中的专名和固定情节模板，包含具体地点、设备、凭证、店铺活动及固定“签署”示例。
- 保留有跨剧本意义的抽象语义：已执行与仅准备、幕内移动与节点出口、合法邀请与按钮首提、已公开去向与作者预览。固定示例改成“地点甲／地点乙”“已公开的下一地点”或直接写状态规则。
- 新增两组静态回归，分别扫描运行端和工坊全部相关 Prompt，禁止当前压测专名及已确认的历史剧本痕迹重新进入通用合同。
- 去专名后真实评测暴露两处通用歧义：一是玩家已执行动作的直接结果偶发被判代做；二是复核把路线 `reason` 的叙事原因重新解释成硬门槛。最终规则只声明结构语义：第一人称完成态允许承接同一对象的直接结果；`next_scene_direction.status=eligible` 表示 Runtime 已完成路线条件判断，`valid` 只核对邀请能否兑现该出口。按钮的跨阶段公开依据只能来自实际演出或本轮合法邀请，作者方向和按钮自身不能自证。

### 完成时态保护

两次全开日志发现模型仍可能把过程态引文写成完成事实：先出现“即将进入安全区域”，随后又出现“向安全区域移动”，却候选为“已经进入并安全安置”。Runtime 因此增加零调用的保守保护：

- 明确未来态，如“即将、将要、尚未、还没、准备去做、考虑、计划、打算”，不能作为完成事实证据。
- 当事实合同明确要求角色已经进入、抵达、到达、安置或撤离时，只有朝目标移动且没有到达结果的引文不能入账。
- 作用域由事实合同描述决定，因此“撤离已经开始”等本来记录启动状态的合同不会因移动词被一概拒绝；“准备工作已经完成”也不会因包含“准备”二字被误杀。

### 验证

- 最终固定普通复核集 `ordinary_review_zh_cn_v2` 共 14 条 × 5 轮，**70/70 整例命中**。正文拒绝、邀请存在、有效邀请、不安全推荐和主动换场恢复五个分项的精确率、召回率均为 100%；中位 **1.936 秒**、最大 **2.742 秒**。报告 `/private/tmp/neko-theater-review-eval-v2-domain-neutral-final2-20260921.json`，日志 `/private/tmp/neko-theater-review-eval-v2-domain-neutral-final2-20260921-traces/`。
- 有效／错误去向成对复测 **20/20**，已执行／仅准备成对复测 **20/20**；这些规则没有依赖固定地点或动作名。
- 最终全开压测使用《零号日志：星火之后》、70% 推荐／30% 自由、balanced、8 个模块全开、10 个主回合加 1 个 revision 2 分叉，并开启演绎日志。**11/11 回合提交**；fatal、回合错误、质量错误、质量警告、隔离失败、Evaluator 降级、语义改写和事实拒绝均为 0。5 条完成事实接纳，所有引文均为完成态；第二幕正常进入第三幕，时态保护没有造成卡幕。
- 最终主轨迹整回合中位 **9.394 秒**、最大 **16.691 秒**。最大值来自一次 Actor 两次生成和两次复核，没有争议等待。报告 `/private/tmp/neko-theater-domain-neutral-final-v3-stress-report.json`，日志 `/private/tmp/neko-theater-domain-neutral-final-v3-stress-traces/`。
- 相关小剧场、压力执行器和工坊回归 **1547 项通过**，另有 2 条既有依赖弃用警告；语法与补丁格式检查通过。压测结束后 8 个用户模块开关已恢复原快照。

### 后续

本轮证明 Prompt 可以去掉剧本专名后保持甚至提高固定集表现，事实候选也不再因坏同伴整批丢失。当前最大延迟仍来自 Actor 或复核重试；普通快检在最终样本中 9 次有 5 次产生实质结果，尚不能整体移除。下一轮应继续从结构化输出和确定性校验中减少重试，避免再向 Prompt 追加某个新剧本的情节答案。

## 58. 交付核对从“保留即复述”收窄为显式交付

## 59. 普通无效邀请先改写、再决定是否争议复查

### 问题证据

- 争议复查仍沿用当前候选、历史和解析合同，测试改为核对“与最近一次快检证据一致”，不把首稿证据错误带入改写稿复查。

## 66. 场景访问时间线与“明天见”误杀边界（已实施）

### 方案

为重复检测增加 Runtime 生成的 `timeline_projection`。它记录场景离开、进入、同幕回合、提交 revision 和场景访问 ID，访问 ID 形式为 `<node_id>:r<进入 revision>`。重复比较优先使用同一访问 ID，旧记录没有该投影时只保留同节点的保守范围。该结构不从文案猜自然日期，所以“明天”“周末”等仍然只是角色对白。

在没有场景旁白、转场、数值变化和新事实的前提下，允许长度不超过 16 个字符的纯对白重复。这是通用短确认规则，不依赖“明天见”关键词，也不放行带场景变化的长正文。

### 验证与结论

- Runtime／Prompt 定向测试 237 项通过；相关 Actor、Workflow、工坊与压测器回归 241 项通过。
- 都市爱情样本全开压测提交 24 回合，fatal 0；没有观察到跨场景同文案被时间线误杀。仍有 3 个 Actor 重复输出失败，最长 52.131 秒，根因是玩家行动归属错误触发重复修复和争议复查超时。
- 因此时间线结构可作为重复判定的确定性作用域，能降低“同一句短对白跨幕复现”的误杀风险；它不替代玩家行动结果投影、目标开场校验或争议复查超时治理。

## 71. 正式接受换场的来源复用受控重试

### 已确认链路

跨题材长轨迹和逐条 JSONL 追踪确认：玩家接受已公开换场后，Runtime 已经准备好新路线，但 Actor 的三段转场来源段可能复用本幕开场或上一轮来源回应。重复保护随后回滚整回合，待确认邀请仍留在旧状态；压测器再次提交同一接受输入，最终表现为 `stalled_transition`。这是同一条链路上的来源重复与停滞，不是 Review 超时。

### 处理

- Workflow 只在 `transition_intent=accept` 且路线确实改变时，为 `earlier_session` 或 `transition_source` 两种来源复用命中保留一次额外 Actor 采样。
- `actor_retry=false` 的普通回合仍只采样一次；没有来源标签的格式错误、`previous_performance` 重复和非接受换场不进入这条窄重试。
- 第二次仍命中来源重复保护立即回滚，沿用原子提交和重复保护，不放宽重复判定，也不合成来源正文。

### 验证

- 新增两种来源标签的工作流回归，覆盖“通用重试关闭但正式接受换场允许一次采样”和第二次仍重复时的原有上限。
- `tests/unit/test_theater_numeric_v2*` 与压测汇总回归共 **1024 项通过**；另有针对本轮改动的工作流、Actor、Prompt 合同测试 **151 项通过**；`py_compile` 与 `git diff --check` 通过。
- 应用《麦香与准考证》22 次回合尝试的真实轨迹（报告 `/private/tmp/neko-transition-repeat-retry-report.json`，日志 `/private/tmp/neko-transition-repeat-retry-traces/`）提交 **21 回合**、1 次错误、fatal 0、质量错误 0；首条换场已从 `mainline_01` 进入分支，随后从分支进入 `mainline_02`。该轨迹在扩展 `transition_source` 窄重试前采集，样本因此同时提供了该标签的真实触发证据。
- 该轨迹的回合耗时为 **p50 4.244 秒、p95 8.456 秒、max 9.912 秒**；不把一次错误样本当成质量改善结论。扩展后的 12 回合复跑（报告 `/private/tmp/neko-transition-source-retry-report.json`）未走到换场，但普通回合的 `earlier_session` 命中仍保持单次采样和回滚。

### 当前边界

来源复用导致的“接受后回滚—再次接受—停滞”已经有确定性出口，但还没有在同一条扩展后长轨迹中再次捕获 `transition_source` 的实际重试成功样本。下一步继续收集跨题材到结局的真实轨迹，分别观察正式换场成功率、停滞次数和 p95；暂不调整 Review 预算或放宽其他重复保护。

## 72. 跨题材长轨迹复压：正式换场与停滞观察

### 验证口径

使用两部剧本、`recommended`、`balanced`、每部最多 48 次尝试、最多容忍 3 次错误。报告 `/private/tmp/neko-cross-topic-transition-retry-recommended-report.json`，追踪目录 `/private/tmp/neko-cross-topic-transition-retry-recommended-traces/`。

### 结果

- 合计 63 次尝试，其中 57 次提交、6 次错误，fatal 0、质量错误 0；合并回合耗时 p50 **3.491 秒**、p95 **6.547 秒**、max **9.618 秒**。
- 《晴川镇的晚风地图》准备了 6 次正式接受换场：5 次直接提交，1 次因 `scene_narration_invalid` 回滚后下一次提交成功，按候选尝试计算成功率 **5/6 = 83.3%**。已提交的 5 次路线变更全部成功进入下一幕。
- 《麦香与准考证》在 17 次尝试后因 3 次同幕 `earlier_session` 重复回滚停止；本批没有出现 `transition_offered`，正式换场分母为 0，不能把它计入成功率。
- 本批 `stalled_transition` 为 **0**，而上一轮跨题材基线记录过 1 次；由于本批没有命中正式换场来源重复重试，停滞下降只能作为观察结果，不能单独归因于本轮受控重试。
- 本批没有出现 `actor.retry_enabled_for_transition_repeat`，因此尚未取得 `earlier_session` 或 `transition_source` 受控重试在真实正式换场中的命中样本。

### 当前结论

晴川镇的正式换场链路在长轨迹中保持可推进，单次目标开场错误也能在下一次接受尝试后恢复；麦香剧本的主要瓶颈仍在“形成换场邀请之前”的同幕重复输出。下一步需要单独收集麦香形成正式邀请后的样本，再判断来源复用受控重试是否真正降低停滞，而不是继续用无分母的总回合错误推断成功率。
