# 小剧场体验目标与设计约束

状态：当前设计说明。本文说明产品目标、职责分工、交付边界和验证方法；目标不代表已经达到，具体行为以当前代码与测试为准。

小剧场由作者提供有边界的故事，玩家与自己的角色共同演出。剧本工坊负责创作和审核作者内容，小剧场负责实际互动、进度结算与保存。

实现细节见[架构说明](./neko-theater-architecture.md)，关键取舍见[设计决策](./neko-theater-decisions.md)，宿主调用与发布合同见[剧本工坊 SDK](../../services/theater_workshop/README.md)。

## 产品目标

小剧场在作者规定的世界、核心事件和结局范围内，让玩家与自己的角色用有限而自然的互动，完成有选择、有进展、有情感回应、能够收束的共同经历。

角色的个性应体现在关注点、判断、拒绝理由、风险取舍和后续态度中。不同经历允许产生不同反应，不以更换名字、口癖或随机措辞代替个性化。

有限篇幅约束创作规模和无效拖延，不用于强迫玩家配合。推荐回合用于软节奏，不因达到轮数就自动批准事实或换幕；条件已具备时也不为凑回合重复确认。

玩家能够自然追问、拒绝、暂缓或改口。允许的选择应有实际后果；超出剧本范围的要求应在故事边界内回应，不无条件改写世界，也不把拒绝视为答错。

工坊依托已有的剧情、事实、证据和文学质量审核能力，创作与复核剧本，使入口、目标、阶段限制、完成条件和后续承接表达一致，减少运行时临场补救。

验收同时关注：

- 正常参与且依据公开线索推进的玩家能够自然到达允许的结局。
- 玩家决定、角色自主、关键因果与已成立事实得到尊重。
- 新题材的完整实演评分稳定超过 85 分；这是长期目标，不是当前质量保证。
- 首稿合格率、审核准确性、修稿效果和等待时间共同改善，不以其中一项掩盖另一项退步。

不追求完整物理模拟、无限开放世界或把每个微动作变成任务锁，也不将现实聊天中的全部记忆、能力和关系直接搬进剧中。

## 职责与事实权限

| 主体 | 职责 | 权限边界 |
| --- | --- | --- |
| 作者 | 定义世界、初始事实、人物处境、核心冲突、必要事件和允许结果 | 作者规划不证明互动已经发生，不预先代替玩家选择 |
| 玩家 | 决定自己的台词、意图、尝试、关键行动和承诺 | 尝试不保证成功，玩家陈述不自动改变客观世界或角色内心 |
| 演出角色 | 依据人格、剧中身份、实际认知和经历，自主发言、判断、行动或拒绝 | 不代替玩家作出新的决定、操作或承诺，不凭空掌握秘密和能力 |
| 场景与配角叙述 | 呈现相容的环境、配角回应和有前因的可见后果 | 不借旁白跳过关键选择、补造未知结果或解决核心冲突 |
| 运行框架 | 解析合同、校验来源、结算事实与指标、选路、组织交付和保存恢复 | 模型提案不是程序批准，状态提交不等于语义质量已通过 |
| 剧本工坊 | 生成、审核、修订作者项目并编译发布候选 | 不读取玩家 Session，不参与运行时选路，不擅自改写已安装包和旧存档 |

### 证据与推进

作者计划、玩家请求、各方承诺、实际动作和完成结果分别理解。请求角色展示一项内容，不等于角色已经展示，也不等于玩家已经体验或给出反馈。

完成事实只能由其合同允许的来源支持。声明 `evidence_source=performance` 的结果须由实际演出原文支持；展示条件读取实际已提交的固定原文记录，不能扩大为玩家理解或接受的证明。

玩家行动依据玩家原话及其授权范围核对。角色自主行为不要求玩家逐项批准；无争议连续动作可以自然衔接，新的重要决定、额外承诺、实质风险和明确保留条件继续单独尊重。

来源幕的完成与下一步的同意分别成立。达成约定不要求当场执行未来计划；已同意移动不自动授权后续调查、公开、交易或关系决定。

作者入幕状态与后续方向是规划，当前经历以已提交正文和合法的新变化为准。换幕不重置持物、分工、时间、已完成结果和已公开信息。

### 即兴范围

允许自然对白、幽默、态度、神情、相容的环境细节，以及角色能力范围内保留条件的合理估算。

严格核对新增关键人物、能力、资源、手续和任务，以及关键结果、正式阶段变化和玩家自主。作者未逐字写出某个细节，不单独构成违规。

估算不等于核验通过，提议不等于已经执行；不能用新设定修补此前矛盾，也不能把表面文本变化当作剧情进展。

## 运行时交付与审核

### 当前实现

运行入口为 `services/theater/numeric_v2_workflow.py`，由 Actor、Evaluator、Runtime 与 Store 分担生成、语义核对、确定性结算和持久化。

当前固定配置在 `services/theater/numeric_v2_options.py`：完整前台 Review 与 dispute 暂停，正文合同窄检查继续启用。该配置不读取或修改旧用户开关。

符合条件的普通回合复用 Actor 同次产生的判定提案；涉及玩家选择、来源约定、正式换幕或结局等情形，仍按实际条件使用前置判定及相应核对。不能将普通回合优化理解为所有输入都只用一次模型调用。

新完成事实保留独立的来源与证据检查。来源回应须先完成自己的交付，目标开场不能反过来证明来源幕缺失的决定或结果。

正文检查覆盖实际候选内容、主体与适用阶段；作者条款的来源幕与检查范围分别保留。持续限制不因换幕消失，当前幕互动也不应被未进入阶段的要求提前替代。

固定原文由程序交付，角色承接实际展示状态。必要前因须位于结果之前，不能靠结果之后的补做回填；同一原文不由模型长段复演。

Runtime 与 Store 保留 revision、身份、包版本、生命周期及原子提交保护。审核或生成失败时，不把半个回合、未批准事实和失败草稿写成已发生历史。

### 审核与修稿边界

- 合法回应未完成当前目标时，可以保留互动，不把目标未达成直接等同于正文违规。
- 玩家新决定、关键事实、重要前因和正式转幕属于严格保护范围。
- 普通文风、无害补白、可理解的连续动作省略，不扩大成新的硬锁。
- 审核发现须对应原文、主体、时点与适用规则；局部引文澄清不能代替整稿范围判断。
- 当前修稿沿用有界额度，再审仍不能通过时拒绝提交；这项保护不保证一定能产出合格的本幕回应。
- 审核误拦、漏判和重写不收敛仍须独立验证，不能以审核调用次数或拦截数量代表准确性。

降低等待应优先减少无效判定、重复检查与失败后的重复执行。输入容量、模型输出和整轮等待保持显式预算，不能靠无限重试或放过关键越权换取表面流畅。

模型语义判断和程序校验各有边界。提交成功证明完成了对应程序流程，不自动证明事实连贯、人物自然或整条路线已经达标。

## 剧本工坊与发布

### 创作与评改

工坊 SDK 位于 `services/theater_workshop/`，由宿主显式提供模型、输入预算、项目根与写入保护；不是玩家回合中的运行时导演。

`generate` 按框架、逐幕和结局生成，开场状态从本次生成的开场及确定入幕交付的固定原文摘录；失败后从对应阶段或已定位节点续修，保留其余已完成正文。

生成时的结构、字段和编译检查与剧情审核分别承担责任。`generate` 不自动串联 `assess_quality`，也不自动优化、安装或替换正式包。

显式 `assess_quality` 已提供以下审核能力：

- 逐幕剧情与事实检查，核对直接入边、出边、完成合同和实际原文。
- 对符合范围的自动出幕，核对来源结果与后幕既成事实的绑定及保证关系。
- 独立证据复核，区分已有证据支持的问题、误报和不能核清的情况。
- 分块文学表现检查、整体评分及按需修订方案复核。

审核报告保留原文依据、节点覆盖和修订权限。事实检查、证据核对和文学判断不能互相替代，无法完成整份核对时不以部分报告冒充通过。

`optimize_node` 依赖当前、未过期且经复核的质量报告，只修改已授予的目标字段；结构性建议不自动取得改条件、重排章节或新增路线的权限。

按幕修订只处理当前真实位置的诊断，保留其他幕尚未解决的问题。新的跨字段校验结果继续完整处理，不能为简化当前请求而过滤掉。

支线使用显式草稿与应用操作。可用端点、数值分段和结束方式受现有合同约束，不假定任意文字选项都能自动编译为分支。

### 编译、复验与安装

发布按 `compile → validate → export` 取得同一 revision 和 hash 的不可变候选；需要安装时再由宿主显式调用 `install`。

质量评估、静态就绪检查和发布凭据各有作用。编译与复验证明数据及字节满足对应技术合同，静态就绪检查不授予实演质量通过结论。

宿主写入遵守运行根、写栅栏、项目 revision、生命周期锁与并发保护。生成期间不持有文件锁等待模型；返回后重新核对版本和可写状态，旧结果不能覆盖新编辑。

导出、安装和读取不得混淆：工坊不迁移玩家存档，不清理用户数据，不覆盖已有同 ID 不同内容的正式包。

## 验证与维护

### 验证方法

- 冻结源码、模型配置、原包、玩家策略、预算和停止条件，保留首次失败；定向重放与新题材完整路线分别报告。
- 模拟玩家只依据实际展示内容、公开历史和当前可见选项行动，不读取隐藏目标、数值或后幕规划来凑通关。
- 使用完整路线验证关键选择、拒绝与不同结局的实际后果；未运行、未结束和未覆盖的部分明确列出。
- 实演结束后统一评读已展示正文，不逐回合停下来评分，也不将未展示的被拒草稿算作玩家已经看到的内容错误。
- 失败尝试、内部重写及原样重试的调用与等待完整保留，内容质量与失败成本分别核对。

完整实演使用事实连贯 30、玩家自主与路线 25、节奏收束 25、演绎 20 的评分口径。未完成样本单独标注范围，不冒充完整路线评分。

等待至少区分玩家输入准备、后端完整回复、失败与重试累计等待、首个可见内容、语音开始及播放。未测量的前端或语音部分不能由后端时长推定。

离线单测、格式校验、提交成功、自然结束和语义质量分别作为证据；测试通过数、单个熟悉剧本或一次高分都不证明新题材稳定达标。

具体运行、恢复、压测命令与容量合同由[架构说明](./neko-theater-architecture.md)和[SDK 接入文档](../../services/theater_workshop/README.md)维护，避免在本文复制易过期的参数清单。

修改运行时职责、事实来源、审核、作者合同或发布流程的实现者，应在同一变更中核对本文及相关实现文档；涉及 SDK 的变更同时核对其接入说明。

本文维护当前产品语义和设计约束，具体协议归架构与 SDK 文档，关键取舍归设计决策。代码与测试不一致时先核对实现，再更正文档，不依据过程笔记恢复已删除的机制。

原始压测请求、演出全文、失败稿、分数表、批次流水和撤回实验记录保存在仓库外验证产物中，不向本文或其他仓库设计文档转存。
