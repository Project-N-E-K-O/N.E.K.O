# 统一知识库与成品包分享开发方案

> 本文已按“只保留一个知识库”第二版方案收敛。早期独立个人资料库方案由 Git 历史保留，不再作为实施依据。现行实现与验证以 `Knowledge_Base` 分支及对应测试为准。

## 1. 产品边界与已确认决定

- 只有一个知识库：内置、市场和用户导入的资料都是现有 `knowledge` 的 pack，统一检索、索引、任务与容量。
- 只有一个入口：插件管理器既有知识库页面；桌面端通过统一管理器入口打开该页。
- 知识库归 Memory Server；Main 仅保留 `/api/public-knowledge` 薄代理，Plugin 继续承担现有账号、配对和市场桥。
- 新导入个人文档创建的 pack、通过本地上传导入的 JSON/ZIP，默认 `enabled=False`、`auto_context=False`、`local_embedding=True`。启用意味着命中片段可能发给云端模型，导入及启用界面明确说明。市场订阅继续使用既有安装语义；默认关闭约定不扩大到市场订阅。本地 JSON/ZIP 替换已有包的新正文也先关闭检索，由用户重新开启；已经过确认的来源版本更新保留原开关。
- 原件、全文和历史版本全部保留，成品包默认保留。仅当用户明确删除一次本地导出时，移除该导出记录及未被引用的 ZIP；知识库仍使用的成品文件保留。不在开发过程中对真实用户目录执行迁移、清理或删除。
- 冻结重试输入遵守保留决定，不自动按时限回收。显式丢弃任务时一并删除其冻结重试输入；其余冻结输入仍全部保留。用户取消或替换尚未提交的预览时，只删除该预览自己的原件与解析文本两份文件；已提交的预览及其冻结版本保留。不做按时限的预览回收；未点取消直接关闭页面的预览保留，磁盘长期预算仍待另行产品决定，不能以索引清理代替资料删除授权。
- 前台请求全部接纳，但实际模型计算串行。后台常规空闲执行，持续前台压力下允许最小批次保底。
- 不做旧客户端、独立个人库格式或双产物市场发布兼容；统一 pack JSON 仍是文本基础格式，保留 JSON 导入，导出统一为 v2 成品 ZIP。
- 三仓继续各维护现有整体功能分支和 PR，不按 PDF 的示例再拆成多个 PR；不自动合并或部署。

## 2. 目录与进程归属

| 位置 | 职责 |
| --- | --- |
| `knowledge/importing/documents.py` | 有上限的 TXT/Markdown/DOCX/PDF 解析、位置与隐私保护 |
| `knowledge/importing/sources.py` | 原件、不可变全文版本、预览和历史；不存向量 |
| `knowledge/importing/projection.py` | 当前文档版本投影为严格 schema-v1 pack，写入 `doc:` / `ver:` 标签 |
| `knowledge/service.py` / `store.py` / `registry.py` | 既有任务、SQLite FTS/向量、注册表与查询；不增加第二套 Store |
| `knowledge/archive.py` | 用已计算向量导出通用 v2、读取成品种子向量；不调用模型 |
| `utils/knowledge_package.py` | 纯标准库包规范、规格、ZIP 安全与数值检查；市场逐字同步 |
| `memory/_embeddings/spec.py` | 只读模型规格与无截断 token 计数；不加载 ONNX |
| `utils/embedding_contract.py` | 无进程依赖的结构化编码结果和后台延后异常 |
| `app/memory_server/knowledge_routes.py` | 统一 `/internal/knowledge` 管理接口与共享编码器适配 |
| `frontend/plugin-manager/src/views/KnowledgeManager.vue` | 来源、启用、文件预览、历史、导出和分享，沿用八语 |
| `plugin/server/routes/knowledge_market.py` / `knowledge_publish.py` | 现有订阅和新增发布；账号凭据不进入 Main 或页面 |

运行资料归 `ConfigManager.knowledge_dir`：

```text
knowledge/
  registry.json
  knowledge.db
  packs/
  history/<pack_id>/
  jobs/<job_id>.json
  jobs/<job_id>.pack.json
  .staging/
  sources/<pack_id>/
    manifest.json
    originals/<doc_id>/v<n>/original
    versions/<doc_id>.v<n>.json
    previews/
  artifacts/<sha256>.neko-knowledge.zip
```

不再使用 `services/knowledge_library`、独立 `knowledge_library` 资料根、页面、FTS、余弦检索、任务系统或嵌入 HTTP RPC。

## 3. pack 与历史数据

- 导入 pack 的 ID 为 `imp.<uuid>`；前缀便于识别，规则依据 `origin` 字段，不依据字符串前缀。
- `PackRecord.origin` 为 `builtin/market/imported`，只表示出处；`enabled` 决定参与检索，`auto_context` 决定被动注入。
- 旧记录缺少 `enabled` 时按 True 读取；新导入的默认关闭由导入流程显式写入。
- `enabled=False` 同时排除工具检索、turn_context 和 tool_available，但不阻止后台补向量。
- 文档版本只存全文与章节。文本提交即可关键词检索；向量由现有索引器逐块按 text_hash 回填，不用文档级 unchanged 阻止补齐。
- 解析在分配大量章节对象前执行字符预算；DOCX/PDF 逐段累计，所有格式遵守调用方限额。版本持久化与读取执行相同的字节上限；同一预览重复提交复用冻结版本，版本落盘而 manifest 写入失败时重试修复关联。
- DOCX 脚注引用与正文使用同一活动分支过滤；PDF 无可提取文字但含图像、实际描边/填充或其他绘制时明确拒绝，避免混合文档静默漏掉描边文字页；纯图形状态、裁剪和未绘制路径不拒绝空白页。Form 采用显式栈并按资源作用域去重，避免自身递归溢出；不代表 pypdf 所有上游路径均无递归限制。XLSX/PPTX 的段间分隔符计入字符预算。
- 所有历史版本保留。显式移除整个数据包后，该包从普通数据包列表消失，刷新与重启也不补回空占位；原件、历史正文与成品仍保留。仅移除最后一份文档时，才显式保留可恢复的来源组，不伪装为可检索的活动 pack。
- 预览阶段保存的原件与全文在取消导入或改选新预览时删除，只限该预览自己的两份文件。删除与提交共用写锁：已写出冻结版本的预览视为已提交，不删除，重试仍可使用；先完成删除的预览再提交时返回 `preview_not_found`，不会冻结已删除的输入。删除是尽力而为：写锁繁忙或删除失败时文件保留，与此前行为一致，前端不重试；提交请求进行中时界面不发起删除。
- `sources_managed` 是本机是否实际持有原件历史的能力标记。离线成品不附带原件，不能根据其中的 `doc:` / `ver:` 标签伪造本机历史，也不能追加文件后覆盖既有成品正文；仍可检索和导出。
- 来源投影保留词边界，既有硬窗口投影只用于核对历史，不改写原件。列表按正文、manifest 和版本文件状态缓存能力判断；编辑操作仍完整验证来源权威。损坏 sidecar 不阻止普通移除，恢复仍要求有效历史。
- pack 更新保留旧 JSON；原件与 source sidecar 不受索引回收影响。提交后的清理失败不能把已成功的任务改成 failed。
- DOCX 脚注和尾注仅由可见正文引用引入；隐藏 run 内的引用与隐藏正文一起跳过。知识库导入与聊天附件遵循同一可见性规则。
- 继续使用单 pack 10,000 chunk、全局 20,000 entry/chunk、200 pack 的现有限额，不凭估算上调。

任务状态沿用 `queued → building → active/failed/cancelled`。激活提交点是 `registry.json` 原子写入；来源侧的 `manifest.json` 仅描述历史和空来源组的 `retained` 展示选择，不决定当前可检索版本。移除时先写展示选择，再提交注册表；任一写入失败都保留活动包，提交后没有标记写入失败将成功误报失败的窗口。没有显式 `retained=True` 的旧来源记录不再自动补成列表占位，无需改写旧原件或历史。

| 中断位置 | 已保留内容 | 重启与恢复动作 |
| --- | --- | --- |
| 预览或原件版本写入后、入队前 | 原件、完整解析版本 | 版本未激活，当前 pack 不变，可重新选择历史 |
| 冻结任务落盘后、构建中 | job、冻结 pack、原 ZIP（若有） | 未命中注册表提交事实则标为 `process_interrupted`，按原 job 重试，不创建新文档版本 |
| 准入持久化期间关闭服务 | 冻结重试输入 | 不向已退出的 runner 留 queued 任务，持久化 `knowledge_stopping` 终态 |
| 新 pack/SQLite 提交后、注册表提交前 | 新旧文本均保留 | 查询版本闸门不提供不匹配的索引，启动按旧注册表重建 |
| 注册表提交后、任务终态写入前 | 新注册表与不可变正文 | 依据正文摘要、订阅和原 ZIP 身份将任务恢复为 active |
| 成功后的索引刷新或清理失败 | 全部原件、正文、历史和产物 | 保持 active，后台继续恢复可重建索引 |

导出在暂存文件 fsync 后、发布前通过与取消共用的任务锁关闭取消窗口；已接受取消不能再公开成品，提交开始后取消明确返回 False。通过提交 gate 后由独立 owner 接收真实线程结果并持久化下载记录，即使 runner 正在退出也不丢失已发布产物。两种交错均有直接回归。

ZIP 校验从请求到达起占用同一准入位置并保留订阅顺序；重复正文但不同归档身份仍需安装。拒绝准入只回收本次新建且无任何安装/任务引用的副本，预存成品保留。订阅 JSON 重试使用发布时的原始字节，不拿规范化正文冒充签名产物。显式丢弃任务后，晚到的持久化不能重新生成该记录；显式丢弃任务时一并删除其冻结重试输入；其余冻结输入仍全部保留。终态释放内存种子向量。

丢弃任务以持久化锁内的任务 JSON 删除为提交点，成功后才移除可见任务并返回成功。删除失败时任务及重试输入保持可见和可恢复，不能先报告成功再在重启时补回。请求取消不打断已接管的删除 owner；晚到写入遵守同一把锁和删除标记，独有冻结副本仍按既有规则清理。

任务记录只保存有界元数据，读写共用 128 KiB 上限；来源选择由 `.pack.json` 中规范包的 `doc:`/`ver:` 标签冻结，不在任务记录里逐文档重复，因此 5,000 个文档的来源包重启后仍可列出、重试和丢弃。超限记录只按 job_id 记录告警，不记内容。首次准入记录未生成时，失败仅清理该次无引用的冻结副本；如果任务记录实际已落盘，即使写入随后报错也保留重试输入。来源列表的缓存提示绑定被验证的正文摘要，另一窗口替换同 ID 包后不能沿用旧版本的管理入口。

导出删除使用独立入口，只接受已完成且持有成品结果的 `pack_export`。删除前确认包名和导出时间，删除后卡片立即移除并刷新父页面；取消或失败时保留卡片。清理范围只含 NEKO 内保存的该次导出及其未被引用的 ZIP，不删除用户已下载到其他目录的副本，不撤回市场内容，不调用 pack/source 删除链路。仍被安装资料、恢复任务或其他导出引用的成品文件保留，并向用户说明。

已完成且仍持有成品的导出任务不受最近任务窗口淘汰，重启后仍提供下载、发布和删除入口。移除最后一份文档前，在同一写锁内检查该包排队、构建中及正在接纳的导入；已有追加任务时返回 `job_in_progress`，不代替用户取消追加。

已用独立进程 `os._exit` 注入验证构建中断、重启及冻结重试；不把它等同于真实断电和所有平台文件系统耐久性验证。

## 4. 嵌入调度与完整分块

- 默认前台兼容既有 `embed/embed_batch`；新 `embed_query` 为前台，`embed_documents` 为后台。
- 记忆回填、统一知识库索引、导入资料与种子向量缺口都显式进入后台 lane。
- `embed_ex` 返回 `ok/unavailable/loading/disabled/busy/timeout/error` 和无正文的状态计数；后台 busy 用 `EmbedDeferred` 延后，不能变成 None 后增加 attempts。
- 调度与知识库接口不调用 `request_load()`。未就绪时文本仍可用，warmup 完成后由原索引循环补齐。
- 后台 token 预算按实际 padding 成本计算：4–8 GiB 为 1,024，8 GiB 以上为 2,048；未知内存采用保守预算，原低于 4 GiB 默认禁用规则不变。
- 后台占空比为 15% / 25%。冷却不占模型槽、不阻塞前台；有后台真正等待、达到 8 次前台且冷却结束后，保底只执行 1 条，剩余保序重新竞争。
- 取消保持真实原生线程 drain；关闭应唤醒等待者，不等漫长后台冷却结束。
- `spec()` / `count_tokens()` 不加载 ONNX；首次指纹和 token 计算须 offload。
- 具有规格接口但暂时无法验证资源时延后编码；向量就绪统计同时绑定完整规格，不能仅凭 model_id。每批前后核对规格，失效种子尝试可在策略变化后重试。
- 规格暂不可验证时，空快照不能标记为已构建；资源恢复后允许同一 generation/model_id 重载。后台刷新对未加载快照返回未完成，等待下一轮调度，不能立即自旋重试。
- `chunk_bodies(..., fit=...)` 和 `derive_chunks(..., fit=...)` 检查包含标题/摘要的完整输入，超过 token 预算继续切分，不静默截尾；未传 fit 保持现有 v1 哈希规则。
- 提交时用同一 token 规则计算容量、写索引和登记片段数。单包重规划失败只延后该包；SQLite 已变更而注册表写入失败时，先修复片段计数再继续容量判断与编码。
- 启动重建与失败回滚依次尝试 token/归档规划、去除 token 规则的归档规划及既有本地布局，仅采用同时满足单包和总片段上限的方案。全部超限时拒绝写入，保留当前索引、注册记录和资料，不当作 SQLite 损坏清库。启动时复用现有 `broken` 表示该包暂不可检索，其他包继续可用；回滚时仅版本不匹配才设此标记，正确旧索引仍可用，并沿用计数协调阻止后续准入失算。
- 规划第一个包之前，先按每包 `max(登记数, SQLite 保留行数)` 预留总量，拒绝的包维持预留，成功重建后才采用新计划数。原文件不可用并移除派生行后，仍登记的包继续保留原准入数量；任何遍历顺序都不能以旧计数突破预算，不额外扩展全局最优规划。
- 注册表持久化的文件 I/O 或注册表校验失败进入既有启动不可用路径，不触发通用索引损坏清库。数据库文件及本轮协调后的行保留，原子写入失败时旧注册表不变；协调期间已删除的失效索引行或重建的向量不回滚，不保证失败前后所有行和向量相同。写入条件恢复后可重新启动协调，未成功持久化的计数不能作为已就绪状态提供准入；不套用仅按物理行数修正的重规划协调器，以免清掉仍登记但原件暂不可读包的预留容量。
- 容量允许后，可通过现有同包重新导入或重启协调恢复；有失败任务时也可重试冻结输入。计数协调和向量开关不负责自动重建待修复包，不新增恢复任务。页面对此统一显示“暂不可用”，不把容量拒绝误报为文件丢失，八语保持一致。
- 分块因上限被拒时记住包摘要、规格及拒绝原因；总量不足另绑定其他包片段总量，输入不变不重复整包计算。超长片段的失败标记同时核对片段 ID、正文摘要和所属包。相关输入变化时重新开放该包片段，由现有索引循环重新规划；腾出容量后可自动继续，不重置其他包的编码失败次数。
- 保留 ZIP 缺失或损坏不阻断已有规范正文的普通回填及其他包的索引；损坏内容的校验结果按文件状态缓存，文件变化后重试，临时读取故障仍可重试。
- 后台补种先聚合核对当前完整规格、索引版本与登记片段数；全部兼容向量已就绪时跳过保留 ZIP 的重复校验，不把这次观察写成永久成功缓存。出现新缺口或资源规格变化后仍可恢复补种，数值损坏沿既有向量快照检查并清空坏行后重试；真正重建仍完整验证归档，不新增每包 BLOB 扫描或墙钟拒绝规则。
- 启动重建实际执行归档验证时，无论成功还是异常都记录包 ID 和毫秒耗时；不记录原件名、路径、正文或异常原文。耗时仅用于定位启动延迟，不参与接受规则或增加超时拒绝。
- 单包失败尚未写 SQLite 时可继续处理其他包；若出现部分写入但计数未同步，本轮结束，后续规划先协调真实数量，不能由下一包保存覆盖待修复标记。分块前优先接受已完整符合 token 预算的正文，再查找切点。
- 文件状态只作为摘要缓存失效信号，权重语义依旧由实际 SHA-256 冻结；POSIX 使用 ctime，Windows 读取真正的 ChangeTime。仅元数据变动可重算摘要，不使相同内容的已加载模型失效。tokenizer 缓存也须匹配实际字节；Windows 实机验证仍待完成。

## 5. 通用成品包 v2

格式名 `neko.knowledge-package`，`format_version=2`，后缀 `.neko-knowledge.zip`，固定成员：

```text
manifest.json
pack.json
chunks.jsonl
vectors.f32
```

- `pack.json` 是统一 schema-v1 pack 文本。来源、条目和容量继续按既有 pack 规则校验。
- `chunks.jsonl` 按条目和 chunk_index 记录实际 embedding_text/text_hash；向量按同一顺序为 little-endian float32。
- manifest 固定作品、发布版本、模型规格、每成员大小/摘要及数量。原件、绝对路径、任务状态和模型不进入成品。
- 发布版本由后端自动生成 `auto-<首次导出任务 UUID>`，每次新导出产生新版本，不沿用导入包的版本，也不依赖可重置的计数器。版本在入队前写入现有任务记录，失败、取消或重启后重试均沿用原版本；成功任务不支持重试。manifest 与结果保存同一发布版本，公共接口拒绝客户端指定 `version`；内部发布版本不再拼入用户下载文件名。
- 下载名采用“数据包名称_本地日期_时间.neko-knowledge.zip”，内部仍按 SHA 存储，不重命名历史文件。名称兼容 Windows/macOS/Linux，清理路径、控制字符和设备名，并按 UTF-8 字节限长。新结果冻结展示名称；HTTP 下载从产物 manifest 获取原始名称，结合任务创建时间生成友好文件名，历史任务无需回写。前端优先采用两跳代理透传的 `Content-Disposition`，避免旧任务记录重新覆盖友好名称。
- 导出仅提供 v2 成品 ZIP，读取 knowledge.db 已有向量，不重算；缺向量或缺可信资源规格时拒绝导出。移除 v1 文本导出及其下载链路，历史 v1 任务不可恢复执行或重试，界面不再提供旧 JSON 产物的下载入口，已有历史文件仍保留；内部 schema-v1 正文与既有 JSON 导入保持不变。
- 包列表的 `export_ready` 独立于本地向量开关和当前编码器就绪状态：存量向量完整、绑定唯一持久规格、索引与注册版本一致且包可用时允许导出。关闭本地推理、模型未加载或加载另一模型，不要求重新启用或重算。列表复用聚合统计并仅读取包版本，不把向量 BLOB 逐包展开；实际导出仍按存量规格校验完整向量与归档，界面统计不替代内容校验。
- 直接导出和失败导出的重试在修改锁内再次核对包未损坏、索引版本与注册版本一致；不满足时以既有 `vectors_not_ready` 结束，不依赖列表曾显示的就绪状态。校验不绑定当前加载的编码器，完整存量向量的离线导出仍可用。
- derived DB 只增加规格绑定元数据，保留已有资料与向量；没有真实权重规格记录的旧向量不能冒认已验证 v2。
- 安装仍走统一 import job。资源身份一致且包维度不低于本机维度时截前缀、重新归一化后种入；不兼容或本机更高维时留空交原索引器补算，不补零。
- 已校验成品的完整片段若符合本机输入限制，安装沿用归档中的实际输入与顺序，不因当前分块算法不同丢弃同规格向量；不适配的条目才重新分块。准入、提交及索引重建共用这份规划与实际片段数，避免限额误拒和重启后再次重切。
- 归档校验证明的是原始正文覆盖。标题、摘要或正文经过本机 NFC、控制符或聊天标记清洗后发生变化的条目，不沿用原始片段及向量，改用规范正文重新分块回填；其他未变条目仍复用向量，流读取保持对齐，原始 ZIP 继续保留。
- 任一向量截取本机维度后为零范数时，通用校验器将整包 `semantic_available` 置为 false，不产生部分种子布局；本地按完整规范正文分块回填，尾文不会因缺少种子向量而消失。
- 包压缩 64 MiB、展开 128 MiB；拒绝 ZIP64、分卷、重复/NUL/路径别名、链接/特殊文件、加密、异常解压、伪造长度、非有限/零范数向量。
- 重复正文的片段覆盖校验保留所有合法游标路径，使用有界位集避免贪心误拒绝或指数回溯；每条目最多缓存 128 种正文的匹配集合，全包共享 4,000,000 次匹配枚举预算，超限返回既有容量错误。普通片段沿用原生子串搜索，每个片段枚举 32 个真实匹配后转为 KMP 线性扫描，保持重叠匹配顺序、缓存和预算扣减完全一致，不加入依机器速度变化的墙钟拒绝。80,000 重复字符、42 种合法长片段的同机对照约从 15 秒降到 0.5 秒；这是局部 CPU 样例，不是低配或全包耗时保证。标题去重与本机一致，执行 NFKC、空白归并及 casefold；市场校验器通过既有同步脚本逐字更新，记录真实源提交和摘要。
- 发布版本使用与 builder、订阅和市场路由一致的 ASCII 规则：首字符字母或数字，后续仅字母、数字及 `._+-`，总长 1–100；不接受斜杠、空白或不可寻址版本。
- 包摘要只能证明字节完整，不证明作者语义真实；市场账号及审核仍承担内容信任边界。
- 文件系统读取故障保持为运行错误，由调用方映射可重试/存储失败；不伪装成作者归档损坏。畸形 ZIP、摘要或数值错误仍使用包校验错误。

## 6. API 与统一代理

新增路径均在 `/internal/knowledge`，由既有 Main/Plugin 白名单代理：

| 接口 | 合同 |
| --- | --- |
| GET `sources?pack_id` | 文档列表、当前版本；已移除文档仍能打开历史 |
| GET `sources/versions?pack_id&doc_id` | 不可变历史列表 |
| POST `sources/preview` | raw Blob；文件名/新 pack 名使用 URI 编码的 `X-Knowledge-Filename/Name` 头，避免进 URL 日志 |
| POST `sources/preview/discard` | preview_id；取消或替换时删除该未提交预览的两份文件，已提交的预览返回 `deleted: false` 并保留 |
| POST `sources/commit` | preview_id、sha256、enabled、enabled_confirmed；新 pack 默认关闭，返回既有 import_commit job；提交时再次核对实际启用状态，追加到已启用包须独立确认 |
| POST `sources/remove/restore` | pack_id/doc_id/版本，复用原任务状态和取消 |
| POST `packs/enabled` | pack 级参与检索开关 |
| POST `packs/export` | pack_id、format_version 固定为 2（默认 2），返回 pack_export job；后端自动生成发布版本，显式请求格式 1 或传入 `version` 会被拒绝 |
| POST `packs/exports/delete` | 仅 job_id；删除已完成导出记录及未被引用的本地 ZIP，返回 artifact_retained 说明文件是否因引用而保留 |
| GET `packs/artifacts?artifact_id` | 只接受 SHA-256 身份，受控二进制下载 |
| POST `packs/jobs/retry` | 原 job_id，重用冻结输入；仅失败或取消任务可重试，busy 不生成重试 |

管理搜索的词和条目标题使用 URI 编码的 `X-Knowledge-Query/Title` 头，两跳代理仅对对应路径转发；不把资料文件名、正文、查询词、命中标题或异常原文写入日志与诊断。包展示名与许可是作者原文，不自动翻译。成品包不含原件，因此 PDF/DOCX 原件元数据不会随导出公开。

上传 ZIP 和大资料采用落盘流式接收；代理不解析正文，继续先过 bridge/CSRF/Origin/容量门。Memory 的生产中间件仅对原始知识包导入路径放宽到包传输上限，普通非 multipart 请求维持 16 MiB；订阅 multipart 继续由流式解析器执行 64 MiB ZIP 加有限表单开销的上限。断连或超限关闭 multipart 暂存句柄。临时输入归实际解析和准入 owner 管理，取消请求后也须等真实工作结束才回收。Main 不 import knowledge。

上传暂存目录创建、文件打开/写入/关闭的 I/O 故障返回 HTTP 500 和既有 `knowledge_error`，不误报为作者请求无效；畸形输入、断连和超限维持原来的 4xx 分类。日志仅记录异常类型，不记录路径和异常原文。PDF 私有解析的日志工厂每次安装时固定捕获委托，允许其他库保留或叠加包装；退出不覆盖外部工厂，动态 pypdf 子日志及并发线程的原有脱敏边界不变。

Main 的本地原生读取保留既有访问方式，未向外部浏览器来源授予 CORS 读取权限，Host 守卫阻断 DNS rebinding；远端实例访问还由实例身份和同源门禁限制，跨站来源在转发到 Memory 前拒绝。生产 App 回归分别覆盖正文、来源版本和 ZIP 下载，不把本地无 CORS 授权误写成所有 GET 都执行 Origin 拒绝。

发布流程总截止时间为 240 秒，包含 Auth 刷新；Main 对知识包发布代理为 245 秒，前端等待 250 秒；其他市场请求仍为 30 秒。到期先返回稳定的业务错误，受跟踪 owner 继续排空真实线程并清理临时文件。提前返回的上传响应也须显式关闭正文生成器，再删除暂存目录。先识别 HTTP 失败状态再解析 JSON，401 正确提示登录；非 loopback 明文 HTTP 市场拒绝上传。本地私密构件下载关闭环境代理，远端 HTTPS 发布使用独立客户端遵循环境代理与 `NO_PROXY`；loopback、`localhost` 与私有/链路本地地址上的市场（含局域网自建 HTTPS 市场）保持直连，发布与订阅下载共用同一判据；普通远端下载保持既有代理规则。发布凭据不附加到本地构件 GET 或代理 CONNECT；刷新令牌的临时失败可重试，2xx 非 JSON 映射既有无效 Auth 响应，401 重试不占重定向次数。

## 7. UI、桌面与市场

- 在现有 pack 表展示来源和启用；在同一页预览确认、文档列表/版本恢复、导出与公开分享。
- 导出区按“导出与分享”和“已导出的数据包”分组，提供就绪状态、自动版本说明及唯一的“导出数据包”按钮。历史产物以卡片展示冻结包名、时间、大小和状态，下载/发布/删除使用固定操作组；删除须确认，且与同一产物的下载或发布对话框互斥。排队任务不显示原始 UUID，公开确认也使用包名。窄屏操作组换行，深浅主题沿用 Element 变量。所有文案同步八语，不展示 v1/v2 格式选项或版本号输入框。
- 导出就绪提示优先展示完整存量向量可直接导出；不可用包沿用修复提示。本地向量关闭且尚未就绪时，明确提示开启并补齐后再导出，不暗示后台正在计算，也不自动修改开关或加载模型。
- 聊天沿既有知识链路：全局知识库与 pack 的“参与检索”均开启时，主聊天获得 `query_public_knowledge` 工具；插件/agent 开关不能代替知识包开关。“自动参考”另控制文字聊天及独立 ASR 转文字后的回复前检索，原生实时语音不走这一自动参考入口。
- 是否检索、是否命中以诊断中的 `lookup/passive` 结果为证据，不能用模型回复中“我查了/没查”的自述判定；有工具不等于每次都会调用，有检索不等于每次都会命中。
- 对已启用 pack 追加文件须明确提示检索与云端发送范围；公开发布有单独确认，原件不公开。
- 追加确认冻结到任务，并在激活时再次检查启用状态，防止另一窗口先启用产生未经确认的公开范围。目标包消失时预览失效；普通索引进度更新不清预览。公开发布按产物保留幂等 UUID 与首次提交内容，切换产物后返回也不能把新表单误配到旧请求。
- 重试返回的新任务保留到轮询首次确认该 ID，再交由服务端快照更新；过期快照不能抹掉新排队任务及其取消入口。丢弃成功同步移除未确认的本地影子，失败保留，后续轮询不能补回已丢弃行。
- UI 文案只进插件管理器八语，删除独立页面的 static/locales 文案及构建登记。
- PC 指向 `/api/agent/user_plugin/dashboard?page=knowledge`，复用现有插件管理器窗口和运行时地址，不固定端口；复用时导航到知识库子页，避免仅聚焦旧插件页。
- PC 入口依赖配套后端支持 `page=knowledge`，须先合入后端或同批发布；旧后端会落到管理器首页。未保存表单保护沿用既有页面卸载机制，不新增窗口协议或专属通知。
- 发布复用现有市场 shares、OAuth、配对和幂等 UUID；订阅安装复用现有 worker。
- 市场描述符只采用明确 protocol_version=2，客户端不把 ZIP 误认成旧 JSON；不做旧客户端或旧 personal 包兼容。市场详情页复用现有配对和订阅 worker，“已交给 NEKO”表示完成传输暂存，不能显示为知识库已安装完成。
- 市场沿现有配对服务接收 NEKO 发出的 `neko_pair/neko_port`，校验 loopback 端口后先清 URL 再交换凭据；不为知识库伪造小剧场的 reservation。先部署市场服务/新校验器及网关容量配置，再开放新发布；本地测试不冒充线上 OAuth、PostgreSQL 或生产部署。
