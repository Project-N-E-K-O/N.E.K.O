# 外部插件开发目录

开发模式使用独立页面，侧栏入口位于「服务器日志」下方。开关、目录加载、开发卡片和打包操作集中在此页面；普通插件管理页不再嵌入开发卡片。卡片展示功能入口 ID 与说明，重载后读取更新后的元数据。

首次进入开发模式页面会自动显示使用说明；关闭后将已读标记保存在当前客户端的 localStorage，后续进入不再自动弹出。工具栏右侧常驻「使用说明」按钮，可随时重新打开。说明覆盖源码目录、手动重载、打包及数据保留行为，提供八种语言。清理客户端存储后会再次自动显示；存储不可用时仍允许关闭和手动查看。

开发目录通过用户数据目录下的 `plugin-development.json` 登记。文件只保存开发模式开关、登记 ID、源码绝对路径、插件 ID 和版本号；名称、版本及入口重新读取清单，运行反馈使用现有插件注册表。

登记目录与安装来源账本分开。加载、刷新、启停及构建使用同一登记身份，安装和卸载仍然只管理既有内置、用户安装目录。相同插件 ID 不允许跨开发来源或安装来源占用；安装包也不能接管仍有关联的开发插件 ID。

## 生命周期

- 登记后尝试启动，失败保留关联和错误；目录失效可重新绑定，更改插件 ID 需要重新登记。
- 重载先检查最新清单、目录、入口、声明依赖及 Python 语法，再停止旧宿主并检查登记身份，最后启动新宿主。
- 预检查失败保留旧实例；旧实例停止后启动失败，保留失败反馈供重试，不恢复用户之前的源码。
- 移除关联确认进程停止后才删除登记，保留源文件和运行数据。
- 关闭开发模式停止开发插件并保留关联；失败不报告关闭成功。应用启动发现关联，但不自动启动开发插件。
- 刷新开发来源同样校验本地调用；单插件刷新还需携带登记 ID 和 revision，校验及发布与登记操作串行。全量刷新含开发登记时要求本地调用，无开发登记的普通刷新保留原访问行为。发现阶段再次校验实际解析出的插件 ID，拒绝清单编辑竞态导致的身份变化。
- 开发登记文件损坏时，全量发现报告错误并跳过开发来源，继续发现和自启动普通插件。只对已确认清单位于受管插件根目录中的普通插件容错，外部、未知或带开发标记的来源保持拒绝；不自动覆盖损坏的登记文件。
- 批量关闭前读取最新登记数量及后端停止配置计算的客户端等待预算，至少五分钟，并随串行停止的预计耗时增长。该有限预算用于防止失去响应后页面永久忙碌，不是服务端强制取消期限；请求超时不代表停止操作已经取消，界面显示错误并刷新实际状态，不自动重试。其他客户端并发新增登记或异常 I/O 仍可能使实际耗时超出估计，可手动刷新核对结果。
- 登记、重新绑定、移除及生命周期操作复用现有跨进程操作锁。登记版本用于拒绝过期请求，旧管理协议要求改用携带登记版本的 HTTP 操作。

开发宿主和元数据扫描器接收中立的 `source_only` 参数。加载器只对该插件命名空间直接编译 `.py`，不读取或写入字节码缓存，保留延迟导入策略；`vendor/` 和其他插件继续使用原加载机制。普通安装插件默认不开启此策略。

开发插件自身模块以 `plugins.<包名>.*` 为规范名称；兼容的 `plugin.plugins.<包名>.*` 导入转发到同一个模块对象，普通子包和无 `__init__.py` 的命名空间子包均遵守此规则。两种路径混用时不重复执行源码，模块状态、相对导入与重载身份保持一致；该映射不扩展到 `vendor/` 或其他插件。

## 构建

分发前源码目录名须与插件 ID 一致，入口包名也须对应；现有包格式按 ID 创建安装目录。不一致时构建会明确报错，开发者需修正目录名及入口/导入、重新绑定后再打包，不自动改写源码。全部打包逐项报告失效登记，继续构建其他有效来源；整合包仍要求全部来源有效。

`/plugin-cli/build` 接受 `development_ref` 或 `development_refs`，每项由 `registration_id` 和 `revision` 组成。接口不接受未登记的任意外部路径。单独、选中、全部及整合包模式统一解析来源并去重。

构建使用独立 staging 和现有文件规则、包格式、依赖校验、元数据生成器。复制前后及发布前对参与构建的源码进行指纹检查；检测到修改或登记失效时失败。最终发布在操作锁和登记锁内复核身份，使用唯一产物名和原子重命名；取消请求阻止尚未发布的产物继续发布。

输出只能进入现有插件包目录，不能覆盖开发源码。插件停止时也能构建。成功表示格式及完整性检查通过，不表示功能验证或市场审核完成；沿用排除规则不等于自动清理全部密钥。

## HTTP 访问边界

开发接口要求后端收到的连接来自回环地址，Host 为本地地址，携带 `X-Neko-Development: 1`，若有 Origin 则必须为本地 HTTP(S) 页面。现有兼容性 `require_admin` 不作为鉴权依据。

因此这一版本支持本机 Electron 和本机网页。局域网远程页面及反向代理访问开发能力暂不开放。网页输入路径指后端机器上的绝对目录，不能通过文件夹上传实现原地开发。
