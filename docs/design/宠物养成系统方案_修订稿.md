# 宠物养成系统方案（修订稿）

> 在原方案基础上，合入拍板结论（Q1–Q15、Q3a/Q3b、Q9a–c、Q10a、Q11a、S1–S5）。添加补丁（F1，F2）
> 标「默认」的条目是讨论中提出、未被否决的处理方式；标「待定」的见第 9 节。此文档禁止后续任何更改。

## 1. 使用前提与数据归属

- 必须登录 N.E.K.O 统一账号才能使用养成。
- **未登录**：猫的行为和现在完全一致，只是没有养成入口和数值。（Q2）
- **每个角色一只宠物**。猫的档位（cat1/cat2/cat3）和装扮只是外观，不单独存档。（Q7）补丁（F1）：现在不做每个角色一只猫，每个账号只有一只猫，绑定自己的一个角色，其他猫和未登录的猫一样。
- **服务器是权威数据源**：每只宠物只存"上次结算时间 + 当时的各项值"，读取或操作时按公式补算，不跑定时任务。客户端用同一套公式在本地推算显示，不轮询。（Q4）补丁（F2）：采用社区的服务器
  - 负载估算：服务器压力只和操作次数有关，与在线时长无关。按 10 万日活、每人每天 30 次操作算，平均约 35 QPS，峰值约 200 QPS。
- **货币**
  - 猫薄荷：免费的社区货币。在养成里用来买额外的食物和玩具（都是消耗品），不卖进度。（O1）
  - 猫粮（付费货币）：首版不接；以后接入时只卖外观和装扮，不卖任何数值或进度。（Q5）

## 2. 核心数值

| 数值 | 作用 | 变化 |
| --- | --- | --- |
| 饱食度 | 是否需要进食 | 随时间下降；喂食恢复；探索消耗 |
| 精力 | 限制连续陪玩和探索 | 活动后下降；随时间恢复；部分食物恢复 |
| 清洁度 | 是否需要清洁 | 随时间下降；清洁恢复；陪玩轻度下降，探索大量下降 |
| 心情 | 收益倍率：低 0.75 / 中 1.0 / 高 1.5（数值进配置） | 由三项状态和近期互动推算 |
| 养成进度 | 解锁新内容 | 喂食、清洁、陪玩、探索、每日登录都能涨；长期不登录会回退 |

- **心情按什么时刻计算**（默认）：探索按出发那一刻的心情算，其他操作按操作那一刻的心情算。
- **惩罚分工**（Q9b）：心情减成罚"没照顾好"；进度回退和负面状态罚"不上线"。两者可以叠加。
- **进度回退**（Q9 / Q9a / Q9c）
  - 连续 5 天不登录后开始回退。
  - 每完成一次解锁形成一个存档点，进度最多退回最近的存档点，不会归 0。
  - 已解锁的内容不收回。

## 3. 核心功能

### 3.1 喂食
- 基础食物是小鱼干，通过"打工小任务"挣（见 3.7），每天有上限。（Q6）
  - 默认：小鱼干只能靠任务获得，不能用猫薄荷买，避免影响社区经济。
- 饱食度满时不能喂。其他食物待定。

### 3.2 清洁
- 基础操作是梳毛；洗澡等后续解锁。都有 CD。清洁给少量进度。

### 3.3 陪玩（主要进度来源）
- **毛线球算陪玩**（Q10）：用户主动拖或点毛线球、并且猫有回应，就算一次。每天前 N 次给进度，之后照样能玩，只是不再给进度。
  - 猫心系统自己发起的玩耍不算。
  - 现状参考：聊天框最小化后会变成毛线球，猫要不要去玩由猫心决定（阈值 52、冷却 10 分钟，`app-cat-mind.js:232`）。重力猫猫模式里点毛线球，猫会去追。两者目前都没有次数限制。
- **新增逗猫棒等玩具，全部是消耗品**（Q10a），主要来自探索掉落。
- 每日次数上限由服务器判定，防止脚本刷。

### 3.4 探索
- 消耗精力、饱食度和清洁度。由少量探索地或 CG 加倒计时组成，没有复杂玩法。
- 探索期间不能喂食、清洁、陪玩。
- **桌面表现**（Q11）
  - 猫出发后，原位置留下一个猫窝或空坐垫，上面压一张小纸条显示倒计时。
  - 探索期间随机来 1 到 3 次"来信"：明信片或气泡，带一张探索地小图和一句话。
  - 回家时播动画，并把收获带回来。
- **强制召回**（Q11 / Q11a）
  - 用户切回模型时，用一个机制加动画把猫强制召回，动画不超过 1 秒。
  - 按已完成的时间比例发奖励；完整走完的额外有加成。
- 奖励以陪玩道具为主，概率出食物或其他内容，收益受心情影响。奖励必须等服务器确认后才显示。

### 3.5 养成进度与解锁
- 用来解锁新食物、新道具、新探索地、新动作。
- 已有的小功能不强行改成收费解锁，例如重力模式（代码已合并，但还没推送上线）。同类问题一事一议。（Q1）

### 3.6 负面状态（Q3 / Q3a / Q3b）
- **定位**：主要用来惩罚不上线。在线时没照顾好不会触发，只吃心情减成（默认）。
- **触发**
  - 只在玩家回来时由服务器判定一次，同一段离线期不能靠重新登录重掷。
  - 触发概率由离线时长和回来时的状态值决定（状态值已算上离线衰减）。运气好可能一直不触发，运气差两天不上线就可能触发。
  - 保底：状态值特别好时一定不触发。
- **两种状态**
  - **生病**：猫萎靡，期间不能探索。做一个简单的"求药"小任务拿到药，用药救它。药平时拿不到。
  - **赌气**：猫不理你，要用逗猫棒等互动把它哄回来。赌气状态下，一定能通过简单方式拿到一根逗猫棒。
- 无论哪种状态，左键返回模型和悬停按钮都照常可用。

### 3.7 任务系统
- 一套任务系统，分两类：
  - **每日打工任务**：挣小鱼干，提供"我在挣钱养猫"的感觉。（Q6）
  - **状态任务**：生病时求药，赌气时拿逗猫棒。

## 4. 和现有猫心系统的关系（Q15）

- 猫心系统（`app-cat-mind.js`）已经有一套本地需求模型：食欲、困意、精力、社交需求、刺激需求。它只存在内存里。
- **养成数值作为猫心的输入**。例如服务器上的饱食度低时，猫更常做讨食动作。
- 猫心继续负责短期情绪和行为。猫自己"吃零食"（`cat1_eat_snack`）只是表现，不影响饱食度。

## 5. 交互

- 左键点猫保持现有行为（返回模型）。
- **养成操作通过悬停浮出按钮**（Q12）
  - 约 400ms 延迟后才浮出。
  - 猫在移动、被拖拽、在重力下坠或贴边探头时不浮出。
  - 浮出按钮不能改变猫心系统对悬停的计数。
- **网络表现**（Q13）
  - 服务器在线时：喂食、梳毛、陪玩先播动画和数值变化，失败再回滚并轻提示。
  - "获得类"操作（探索奖励、解锁、货币增加）必须等服务器确认后才显示。
  - 已知服务器连不上时：养成入口置灰，猫本身的行为不受影响。

## 6. 养成循环

~~~text
时间流逝/活动，饱食度和清洁度下降
→ 做打工小任务挣小鱼干
→ 喂食、梳毛、陪玩（毛线球 / 玩具）
→ 精力和条件允许时出门探索（桌面留猫窝，期间来信）
→ 带回道具和养成进度（二期：还会带回社交内容）
→ 解锁新探索地、动作和道具
→ 长期不上线：进度回退到存档点，可能生病或赌气，靠状态任务恢复
~~~

## 7. 社交（二期，依托 nekoverse）（S1–S5）

- 首版不做。二期依托已有的 nekoverse 社区，不重新做一套。
- **社交对象**：来自 nekoverse 的社交匹配，不另建好友关系。
- **探索带回的社交内容**
  - 系统生成的被匹配者动态，比如"遇到了 XX 家的猫"。
  - nekoverse 卡牌社区里的内容。
  - AIGC 生成的内容。
- **拜访**：被匹配者来拜访，可以降低负面状态的触发概率，但降不到 0，每天有次数上限。
  - 默认防刷规则：只有系统匹配给你的对象来访才算数。
- **隐私**：只对指定范围可见，并提供"不让别人来访"的开关。（S5）
- **被匹配者能看到的内容**：主人的兴趣和近期趣事，来源是卡牌社区绑定 ID 下的公开信息。（O2）
- 推送、装扮、社区展示：后续再做。

## 8. 实现约束

- 所有道具、货币、数值、奖励和进度变化，都必须先由服务器核对并写入。
- 每次操作都要检查是否和当前活动冲突；失败时不扣道具，不改变长期数值。
- 状态上限、衰减速度、活动消耗、奖励数量、掉落概率、心情倍率、负面状态概率曲线、回退速度、解锁条件，统一放在数值配置里管理。
