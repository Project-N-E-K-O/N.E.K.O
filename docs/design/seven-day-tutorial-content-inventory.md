## 1. 本轮目标与边界

后续教程的已确认方向：使用暗色遮罩突出当前操作按钮，用户亲自点击后进入下一步。

本轮先整理现有 7 天教程教了什么、指向哪里、目前怎样推进。仅新增本文档，不修改教程、样式、文案资源、进度数据或构建产物。

盘点完成标准：

1. 覆盖当前 7 个日模块中的全部 **48 个场景**，保留原顺序与场景标识。
2. 区分讲解内容、自动演示动作和真实用户操作，不能把台词中的“点一下”当成代码已经等待点击。
3. 收录影响内容完整性的动态开场、第 1 天托盘说明和每日破冰对话衔接。
4. 新版尚未决定的内容单独列出，不把现有演出方式直接写成新版要求。

## 2. 当前真正生效的教程

### 2.1 内容事实源

首页 `templates/index.html` 实际加载 `static/tutorial/yui-guide/days/` 下的 7 个日模块，再加载 `UniversalTutorialManager`。每日的内容和顺序以日模块的 `round.scenes` 为准。

中文显示内容主要来自 `static/locales/zh-CN.json`：

- 第 1 天部分台词使用 `tutorial.yuiGuide.lines.*`。
- 其余每日台词主要使用 `tutorial.avatarFloating.dayN.*`。
- 第 3 天开场还会根据语音使用记录选择另一段台词、语音和表情。
- 破冰对话另有独立脚本和 locale，不在上述每日场景数组中。

旧的 [七日悬浮角色教程实现记录](avatar-floating-7day-complete-guide-dev.md) 中，“七日内容边界”的部分主题已与代码不同，尤其是第 2、3 天。日模块文件名也保留了旧主题：例如 `day2-screen-voice-guide.js` 目前实际教的是互动工具和 Galgame。后续不能只根据文件名或旧文档标题判断内容。

### 2.2 当前推进方式

当前首页教程以角色讲解和自动演示为主：

- 场景按顺序交给时间轴执行，等待旁白、场景操作和必要的动画结束，再进入下一场景。
- 高亮目标可能是按钮、整块面板、聊天框或临时展示区域，并非每个场景都有高亮。
- 模拟光标的移动、点击动画与真正触发功能是两回事。是否操作真实界面，要继续查 `operation` 和对应方法。
- `getAvatarFloatingSceneButtons()` 当前返回空数组，每日场景没有统一的“下一步”按钮列表，也没有统一的“用户点击目标后继续”条件。
- 教程有交互接管、鼠标打断反应、跳过与清理恢复逻辑；用户鼠标操作可能触发打断演出。因此改成用户操作引导时，不能只替换遮罩样式。

执行依据：`static/tutorial/core/scene-orchestrator.js`、`static/tutorial/core/operation-registry.js`、`static/tutorial/core/settings-tour-flow.js`、`static/tutorial/yui-guide/director/director-core.js`、`static/tutorial/yui-guide/director/avatar-rounds.js`。

项目还存在 `static/tutorial/core/page-tutorial-manager.js` 中的 Driver.js 页面教程，用于模型、角色、设置、记忆等独立页面。它们与当前首页 7 天教程是不同入口；本次 48 个场景不包含这些独立页面教程。

### 2.3 天数、触发与重新查看

| 项目 | 当前代码规则 |
| --- | --- |
| 自动启动入口 | 首页管理器检查是否有待展示的一天；已在运行教程时不重复启动，并再次确认当日内容已注册。 |
| 天数依据 | 按 `firstSeenDate` 与当前本地日期的自然日差计算可展示范围，最多到第 7 天，不是累计使用满 24 小时。 |
| 展示顺序 | 第 1 天未完成或跳过时先安排第 1 天；之后在已经到期的天数里，找最早未完成、未跳过的一天。 |
| 当日频率 | 正常自动调度受 `lastAutoShownDate` 限制，同一日期不重复自动安排；手动重置指定天数有优先规则。 |
| 缺席后回来 | 例如第 5 天回来但第 2 天还未结束，会先安排第 2 天，不直接跳到第 5 天。 |
| 完成与跳过 | `completedRounds` 与 `skippedRounds` 分别记录；两种结果都视为该天已处理，但后续破冰触发规则不同。 |
| 存储 | 后端 `seven_day_tutorial_state.json` 保存教程进度，前端通过 `/api/seven-day-tutorial/state` 同步并保留本地缓存。 |
| 重新查看 | 记忆管理页面的教程重置选择器支持首页某一天和首页全部天数；正式重置入口也处理对应破冰状态。 |

依据：`static/tutorial/core/seven-day-state.js` 的 `getNextAutoRound()`、`static/tutorial/core/universal-manager.js`、`utils/seven_day_tutorial_state.py`、`static/tutorial/avatar/floating-guide-reset.js`、`static/js/memory_browser.js`。

这些是当前规则。新版是否继续分 7 天，尚未由本次需求决定。

开场分支的实际判断是：**第 1 天结束后、第 3 天开始前，是否记录到语音使用**，不是简单判断用户“曾经用过语音”。

- 未记录到：使用 `tutorial.avatarFloating.day3.intro`，表达还没听到用户声音，邀请说一句。
- 记录到：使用 `tutorial.avatarFloating.day3.introVoiceUsed`，表达记得用户语气，邀请继续语音聊天。

分支依据：`static/tutorial/yui-guide/director/director-core.js` 的 `resolveAvatarFloatingSceneText/VoiceKey/Emotion()` 和 `static/tutorial/yui-guide/director/foundation.js` 的 `hasAvatarFloatingGuideVoiceUsedAfterDay1EndBeforeRoundStart()`。

### 5.2 每天正常完成后的破冰对话

破冰是独立的聊天内容，使用选项引导用户与角色交流，不属于上述按钮教学的 48 个场景。

| 天数 | 当前开场话题 | 第一轮选项内容摘要 |
| --- | --- | --- |
| 第 1 天 | 新家、可以坐在哪里、如何拉近距离 | 邀请坐沙发；允许自由坐但不能抓沙发 |
| 第 2 天 | 饮食喜好 | 喜欢甜食；喜欢辣味 |
| 第 3 天 | 在家最喜欢待的地方 | 床或沙发上放松；书桌前游戏或阅读 |
| 第 4 天 | 空闲时的娱乐偏好 | 竞技或射击游戏；看剧、动漫或听音乐 |
| 第 5 天 | 尾巴表达的心情 | 观察到角色很开心；以后会注意尾巴 |
| 第 6 天 | 耳朵、脚步声与彼此熟悉 | 能认出角色脚步；踮脚测试听力 |
| 第 7 天 | 相识一周后的陪伴约定 | 继续相处；用表现与奖励回应 |

当前每一天配置 7 个对话节点，以二选一分支连接，末端有接回后续聊天的内容；这些是分支总数，不代表每次都会播放 7 个节点。

触发代码监听教程正常完成事件。**跳过教程或生气退出不会由这条结束事件链新启动破冰**；已有未完成破冰会话另有恢复逻辑。后续更换引导形式时，需要单独决定是否继续衔接这些对话。

依据：`static/tutorial/icebreaker/icebreaker_scripts.json`、破冰中文文案（`static/tutorial/icebreaker/locales/zh-CN.json`）、`static/tutorial/icebreaker/new-user-icebreaker.js`。

## 6. 转为“暗色遮罩 + 高亮 + 点击推进”前需要区分的内容

以下是从现有内容推导出的设计问题，尚未指定新版步骤数量、技术方案或最终交互。

| 内容类型 | 现有例子 | 后续需要明确的推进条件 |
| --- | --- | --- |
| 打开功能入口 | 历史记录、工具菜单、设置、猫爪、插件管理 | 用户点击真实目标之后，需要等到对应面板或窗口就绪，再显示下一步。具体目标和条件待新版步骤设计。 |
| 只读介绍 | 开场、陪伴说明、毕业、功能说明 | 没有可点击业务目标，需决定合并、移除，或提供明确的继续按钮。不能凭空指定一个无关按钮。 |
| 非点击操作 | 拖动聊天框、滚轮缩放、旋转工具菜单 | 需决定只说明并继续，还是检测用户真正完成手势。不能把“点击一下”作为完成该手势的证明。 |
| 会改变设置的操作 | 主动搭话、目光跟随、锁定、Agent/键鼠控制 | 需决定要求认识入口还是实际操作；若实际操作，要考虑已有开启状态和用户不愿更改的情况。 |
| 需要权限或外部条件 | 麦克风、屏幕共享、插件执行 | 需决定展示到哪一步，以及权限拒绝、未配置等情况下如何继续。不能把现有台词当作功能已成功开启。 |
| 会隐藏当前教学对象 | 角色回窝、关闭面板、更换角色 | 需明确隐藏后怎样继续和恢复，不能假定高亮目标一直存在。 |
| 跨窗口操作 | 第 6 天插件管理、桌面独立聊天窗口 | 需确认新窗口就绪、引导由谁承接、返回后从哪里继续。 |
| 重复介绍 | 第 1/6 天猫爪，第 3/5 天角色设置，第 5/7 天记忆 | 需决定保持分日重复提醒，还是在新版里合并。 |
| 教学外衔接 | 第 1 天托盘说明、每日破冰对话 | 需单独决定保留方式，不能在改造 48 个场景时遗漏。 |

后续设计还需收敛：是否继续按 7 天分发、是否保留角色语音与剧情演出、跳过与重新查看的范围。用户目前已确认的是新的引导形式，尚未要求删除这些内容或改变进度规则。

现有交互接管与鼠标打断演出也需要对照新目标处理：用户点击当前高亮目标应成为正常推进动作，不能继续被当作打断教程。当前的完成、跳过、清理、模型恢复与跨窗口结束链路则需要逐项核实后复用。
