## 回归报告 / Regression Report

覆盖及查询接口原来可能把本次希望写入的状态当作实际结果，弹窗无法据此正确选择动作。
现在接口返回 `attempt_outcome`、`voice_state`、`state_sync`，写入结果必须具有正回执；
配置变化、旧操作迟到和记录版本冲突都不能开放不安全的覆盖入口。
新恢复路由只接受上下文、操作 ID 和预期记录版本，并在原子边界重新检查。
恢复已落盘但配置随后改变时返回上下文变化，仍如实保留 `state_sync=saved`；
单纯状态读取失败则返回空快照，界面保持查询出口。

追加审查修复后的反馈合同如下。`attempt_outcome` 描述本次 provider 尝试，
`voice_state` 是当前持久化记录的独立快照；`state_sync` 仅描述本次尝试结果的状态同步，
不将此前的准备或提交权登记当作本次结果已同步。三个字段不能相互推导。

| `state_sync` | 证据与消费者规则 |
| --- | --- |
| `saved` | 本次结果同步取得 `applied=true` 写入回执；后续读取失败不会撤销该事实 |
| `unchanged` | 尚未发起结果同步，或条件写明确未应用；不表示记录今后不会被其他任务改变 |
| `failed` | 结果同步调用明确报错；不代表远端未接受，也不授予重试权限 |
| `unknown` | 结果同步写入仍在进行、回执未确认，或路由缺少 service 证据；写入可能在响应后完成 |

新增 `unknown` 是有限的接口枚举扩展。仓库前端只按有效 `voice_state.actions` 展示动作，
不根据 `state_sync` 放开覆盖；旧或外部消费者应保守处理未知值。
取消或查询超时不停止线程内写入，原 CAS/operation ID 约束继续生效；
请求所属的完成回调消费迟到失败，不无限 join，也不新增后台任务平台。

潜在回归集中在旧服务端字段缺失、保存失败、操作接管及取消落在后台写入期间。
已用真实服务入口、版本冲突、故障注入、受控 barrier 和实际子进程终止验证。
页面在 Chromium 153（Playwright 自带）和 Electron 41.2.0 中运行，使用隔离 API 和虚构凭据。

## 验证证据

- 受影响 Python 模块与缓存契约：709 项通过，合计覆盖率 93.53%；service 91%、恢复模块 87%、路由 100%。
- Node：管理状态、试听正文读取、恢复动作与迟到响应通过；原有前端合同套件通过。
- 实际页面：管理、试听、恢复在 Chromium 和 Electron 均通过。
- 五个真实进程终止位置：准备后、转换后、发送中、接受后、最终保存前；重启后核对存储、身份和服务商实际接受次数。
- 恢复旧逻辑、伪造转换回执、移除恢复动作门控均能触发相应测试失败。

- Ruff、既定静态守门及八语言键和缓存契约通过。
- GitNexus 已在实施工作树重建；新恢复入口与阶段转换影响为 LOW。动态图谱不完整的锁与路由调用另行人工追踪。

一项是 `test_pr3078_review_evidence.py::test_c1_closed_gemini_then_real_swap_differential` 的历史版本差分。
