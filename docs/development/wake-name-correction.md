# 唤醒名字转写矫正与录音复测

本规则用于独立 ASR：本地唤醒词命中之后，只有第一个准备好的语音回合有矫正资格。普通对话、仅声纹激活、后续回合、句中提及和实时预览不做替换。最终文本先经过原有语音准入检查，再将校正结果交给聊天记录与模型。第一个最终结果为空或不匹配，也会消耗这一次资格。

这是已知误识别的有限补救，不是 ASR 模型训练，也不能修复任意漏字或截音。扩充表项需要记录「实际说法 → 原始 ASR 输出」，不要枚举所有同音词。

## 2026-09-29 样本

合成语音使用 Windows `System.Speech` 的 Microsoft Huihui Desktop 和 Microsoft Kangkang，共 12 条，单声道 PCM16 / 16 kHz。TTS 可能存在发音偏差，这些样本只补充转写覆盖，不能替代用户真人录音。另有 2 条已有录音重放，两组都收到了预期数量的 ASR final。

「忧郁」「由于」「英语」是普通词，仅在整句只包含它和空白、闭引号或句末标点时替换；「忧郁症」「忧郁的人」「忧郁，怎么办」「由于天气不好」「这是由于网络问题」「英语怎么学」和「我说英语」保持原文。其他表项仍采用显式句首匹配，保留后续指令。即使限定了唤醒首回合，真实语义恰好与表项相同仍可能被误改，例如唤醒后的首句实际回答「英语」。新增样本时应同时增加反例。

重复形式「忧郁忧郁」也只接受整句匹配，不改「忧郁忧郁的人」或带有后续分句的文本。15:13 的现场样本属于后续对话回合：它能证明存在这种转写，但不是矫正资格已触发的证据。扩充映射不能让既有后续回合获得资格，必须重新进入待机并由唤醒词触发来验证。

「刘怡」可能是真实人名，因此同样只接受整句匹配；「刘怡是谁」「我叫刘怡」「刘怡，帮我打开灯」和未经确认的重复形式「刘怡刘怡」保持原文。唤醒首回合若实际只说人名「刘怡」，仍存在误改风险；当前有限规则无法仅凭转写消除这种歧义。

## 怎样收集自己的误识别

「又一又一」同样仅做整句匹配；「又一」「又一又一地出现」以及包含后续分句的文本保持原样，不推导未经用户确认的单次「又一」映射。

1. 每条录音保存为单声道 PCM16 WAV，16 kHz 或 48 kHz；一条文件只放一次呼唤或一句指令，避免把多个独立试验混在一起。
2. 分别录「悠怡」「悠怡悠怡」「悠怡，今天有什么安排」「悠怡悠怡，帮我打开灯」。每种读法在正常、慢速、快速下各录 3 次；再按需要加入远距离或背景噪音，标签写清楚，单次先只改变一个条件。
3. 用当前配置的 ASR 重放。下面命令会把指定录音发给已配置的 Qwen ASR，并将原始转写保存到本地 JSON；`--show-transcripts` 是显式保留原文的选项，报告不要直接公开：

```powershell
$env:PYTHONUTF8 = '1'
uv run --no-sync python scripts/asr_realtime_smoke.py qwen C:/voice-fixtures/single-normal-01.wav --show-transcripts --output C:/voice-fixtures/single-normal-01.result.json
```

4. 记录输入说法、音频来源、语速/距离、ASR provider、原始输出和期望校正。报告 `ok`、`business_finals` 正常后再比较输出；没有 final 不能当作矫正规则不匹配。同一音频可复跑，但复跑不算新的真人样本。
5. 将稳定复现的拼写加入显式规则与测试，验证保留后续指令、句中不替换、声纹触发不替换、下一回合不替换、准入拒绝不被绕过。
6. 最后在实际网页或 Electron 麦克风链路复测：每次开始新的麦克风会话、等待 `waiting` 后呼唤，确认日志是 `wake_word_detected`，再检查最终聊天文本。若是 `owner_confirmed`，该回合按设计没有唤醒词矫正资格。实时预览暂时显示原始错字是预期行为。

本次已有现场录音未留存，不能从历史文字重建音频，也不能用上述 14 条重放样本宣称真人召回率或误改率。端到端漏唤醒、队列溢出和声纹先触发需分别定位。
