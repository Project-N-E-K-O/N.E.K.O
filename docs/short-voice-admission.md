# 激活后短人声准入与收尾

本轮在 #3149 整合分支增加可选择的实验策略，默认保留旧策略。
覆盖独立 ASR 的 provider／SmartTurn 共用入口；声纹激活、RNNoise、唤醒词、AGC、供应商端点参数不变。
原生直连语音没有获得本次独立 ASR 准入保护。

## 实现与边界

- 普通路径仍使用 224ms 有效人声、480ms 滑窗、65% 占比；满足后立即准入。
- 实验路径将 0.35～0.5 的证据保留为不确定区间，不计入有效人声；连续最多 96ms、累计最多 128ms，候选总期限仍是 640ms。
- 短候选在明确低分尾巴达到 128ms 后补判；实验默认至少 192ms 人声、96ms 连续人声且至少三个连续支持窗口、核心占比 80%、核心平均概率 0.7。128／160ms 仅用于离线对照。
- 尾部明确低分单独统计；词内低分、不确定区间仍计入整个核心，不挑最高分片段。
- 短候选补判跨度最多 572ms，为原有 700ms 保留容量内的 128ms 前置音频留空间。32ms 窗口离散化可能让判定更早发生拒绝；不额外延长候选期限。
- 检测积压不能靠此算术保证音频仍完整。准入使用现有按采样区间的缓冲检查，首部缺失、中间断裂或容量不足仍失败，不截短上传、不扩大缓冲。
- 准入才会准备回合和交付音频。短候选通过后衔接原有 Silero 活动状态，计入已经观察的静音，保持原有暂停阈值、连续模型上下文和恢复讲话事件。
- provider 的本地补判不代替供应商 endpoint；SmartTurn 在活动暂停后继续由现有语义评估决定提交。两者均不伪造 final，不把 partial 当 final。
- 没有修改 Core、前端、生命周期缓冲容量或恢复白名单。失败提示沿用现有契约，无新增翻译文案。

`SpeechEvidence` 新增核心、尾巴、不确定区间和缺失统计；准入路径及终止判定采样边界冻结。后续观察不能改变先前回合保存的不可变证据快照。采样缺失与低分是不同问题。

## 会话固定配置

保留现有 `NEKO_ASR_ADMISSION=1` 前提，新增 `NEKO_ASR_SHORT_SPEECH`：

| 值 | 行为 |
| --- | --- |
| `off`（默认） | 原有准入 |
| `shadow` | 原有准入；共用同一次模型推理，额外记录实验拟判定，不上传被原策略拒绝的候选 |
| `enforce` | 使用实验准入和配套活动衔接 |

配置在一次 `start()` 建立连接前读取，之后该会话及其恢复复用同一配置。非法显式值或未启用准入却启用实验会准备失败，不静默退化为持续上传。

受控整合实测可在启动后端前设置：

```powershell
$env:NEKO_ASR_ADMISSION = '1'
$env:NEKO_ASR_SHORT_SPEECH = 'shadow' # 验证拟判定；受控实验再改 enforce
```

这些是后端进程环境变量，不是浏览器开关。运行中的后端不会自动读取另一个终端新设的环境变量。部署配置变更后，在新进程、新语音会话生效。回滚设置 `off` 并重新创建会话；不回放已经拒绝的历史音频。

普通资源优化开关不改变以上配置。注入自定义 detector gate 的测试／调用方必须自己提供相应配置；构造器不会覆盖一个已创建 gate。

## 验证证据

定向测试检查实际 PCM 内容和顺序，以及准备、上传、语义提交、final 的次数：

- 192ms 高分核心加 128ms 低分尾巴能进入实验短路径；普通 224ms 不增加等待；单个 32ms 高分脉冲仍拒绝。
- 有限词内不确定段、持续灰区、离散高分、候选期限和短核心质量分别验证。
- provider／SmartTurn、资源优化开／关：首尾音频逐字节一致，回合只准备一次、final 只交付一次。
- 开始与暂停同批发生时顺序一致；旧 final 到达后不会清理已积累的新短候选，后继音频只交付一次。
- 缺失首部、中间有洞、容量不足：不准备、不上传并明确失败。
- 在 detector 等待期间关麦，以及补判前关闭：旧输入不继续上传。
- 会话在建连等待中改变环境变量不会热切换；下一次启动才使用新配置。
- shadow 不改变正式事件、音频准入或回放；实验短候选可以连续观察，不停留在上一次拟准入状态。

回归包含原有分包、旧边界、生命周期、转写及恢复相关用例，不运行全量测试。确定性概率序列只证明代码契约，不证明模型能识别轻声或分辨环境音。

2026-09-24 最终合并工作区定向运行：17 个测试文件，458 项通过；仅有现有 websockets 弃用警告。RNNoise／激活诊断在首个提交另行通过相关定向验证，两批结果不作无重叠总数相加。新增和修改 Python 文件通过 Ruff；每个提交前执行 GitNexus staged 范围检查。

真实本地录音对照使用生产 Silero、16k 直入和 48k 实际预处理链路，见 [测量报告](benchmarks/short-voice-admission-local-2026-09-24.md)。已有“停”录音在旧规则下就能走普通准入，两份录音均未触发实验短路径，因此不足以选定部署阈值或证明短词改善。

网页／Electron，16k／48k 和两种端点模式应分别实测“喂”、轻声、正常“嗯”、连续两句及“停／取消”，并用人工标注环境音作负样本。分别记录通过率、误准入／误打断、实际上传量、语音起点到准入，以及词结束到停止播放的延迟。

当前日志只有内部身份、数值、固定原因和时序，不记录原始音频或转写。RNNoise 日志可区分输入等待、线程排队、处理等待与激活证据积累，但尚未据此确定此前长等待的现场原因。

入口拒绝仍无新增上传或打断；一旦短噪声误准入，ASR 费用无法追回。已准入“嗯”的现有文字规则仍放行，不能视作误触发兜底。模型对轻声一直低分时，本实现仍可能拒绝。

192ms 高分加 128ms 结束观察的理想准入点为起声后 320ms，尚不包括调度、推理、网络或供应商响应；不能作为真实打断延迟承诺。噪声误触发明显增加、打断过慢、SmartTurn 等待异常或音频归属错误时，不扩大启用范围。
