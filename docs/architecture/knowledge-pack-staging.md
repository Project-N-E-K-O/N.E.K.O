# 知识包暂存与激活

> **实现更新（2026-08-24）**：暂存状态机已按现行实现校正；FTS/分块、预构建索引校验、激活与原子状态落盘均从异步协调循环卸载到工作线程，避免磁盘 I/O 阻塞 Main Server 事件循环。

用户导入的知识包不会直接写入在线知识库。Main Server 先把经过校验的五字段原始内容放入
`<knowledge-root>/.staging/<job-id>/`，后台完成 FTS、确定性分块和可信预构建向量校验后，再替换在线来源。
更新期间旧版本继续服务，暂存内容不参与 BM25、语义检索、自动上下文或素材路由。
用户授权的本机向量维护不属于暂存激活的必经阶段，而是在包激活后由知识索引协调器按预算渐进执行。

## 索引策略

- 知识正文始终可以独立安装，默认检索模式为 BM25。
- 可信市场 protocol v1 可同时交付正文、索引清单和向量矩阵三个制品；清单与向量必须成对出现。
- 预构建索引只有在三个制品摘要、本地确定性分块、模型 ID、维度、编码和所有向量行都通过校验后才进入暂存库。
- 社区包默认 `prebuilt_only`。预构建索引不可用时直接以 BM25 激活，不会静默加载本机模型。
- 用户在管理器中明确开启“允许本机维护向量”后，该包才切换为 `local` 策略，由知识索引协调器补算、更新或重建向量。
- 禁止把知识正文或任一索引制品交给 Memory Server；知识索引任务与记忆业务保持隔离。

## 固定容量边界

- 规范 JSON 最大 10 MiB。
- 单包最多 5,000 个条目。
- 单包最多派生 5,000 个 chunk。
- 全部社区知识累计最多 20,000 个条目、20,000 个 chunk 和 64 MiB 正文。
- 在线 ready 向量总预算为 20,000 个 chunk。
- 暂存前至少保留 512 MiB，或预计工作空间两倍的可用磁盘容量，取较大值。

超过单包或社区累计限制时拒绝导入。同一知识包更新会先扣除在线旧版本再计算容量，不会重复
计费。超过在线向量预算时不拒绝知识内容，而是以 BM25 模式激活，避免 CPU 和内存随用户知识量
无限增长。HTTP 接口在流式读取过程中执行大小检查，不会先把超大请求完整载入内存。

## 状态与宽容降级

```text
请求内校验 → queued → building_fts → verifying_index → active
                                                  ├─ hybrid（可信索引完整有效）
                                                  └─ bm25（无索引、拒绝或超预算）

任一非终态 ─→ cancelled / failed
```

`validating` 只作为旧任务的兼容恢复状态接受，新的导入请求在写入 `queued` 前已经完成格式和容量校验。激活后，用户授权的渐进式本机维护可让在线包在 `bm25`、`mixed` 和 `hybrid` 之间变化，但这不是暂存作业的额外 `embedding` 阶段。

预构建索引缺失、校验失败或超过向量预算时，任务仍会以 `bm25` 激活。包已带可信向量但运行时 Embedding 提供方不可用时，单次检索安全回退到 BM25，不改变暂存作业终态。不可恢复的暂存异常会明确进入 `failed`；旧在线版本与聊天服务不受影响。取消和失败只保留不含正文的 `state.json`，暂存正文与数据库会被清理。应用重启后，非终态任务由知识索引协调器继续处理。

`state.json` 始终使用原子替换写入。异步协调路径通过工作线程执行状态写入、暂存数据库构建和在线激活；状态仍可恢复，但同步磁盘 I/O 不占用事件循环。

激活后的 `packs.json` 记录 `index_origin`、`index_trust`、`index_validation`、`index_fallback_reason`、`local_embedding_enabled` 和预构建 chunk 计数。它们只用于状态展示和策略恢复，不替代对制品的实际校验。

管理接口：

```text
GET  /api/public-knowledge/packs/jobs
POST /api/public-knowledge/packs/jobs/cancel
```

维护脚本的默认 `--status` 会只读显示任务；`--preflight-pack PATH` 可在导入前检查容量，
`--cancel-job JOB_ID` 可取消暂存任务。
