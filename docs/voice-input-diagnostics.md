# RNNoise 与激活等待诊断

本轮仅增加诊断，不调整 RNNoise、声纹、唤醒词、Silero、AGC 或云端参数。代码在新后端进程中生效；不会向正在运行的进程热注入日志。

## 日志含义

每条输入管线首次收到有效音频时记录一次，此后有输入时最多每 2 秒输出一次汇总。激活候选同样限频；发出声纹验证请求时另外立即输出。没有新音频时不启动日志定时任务。

- `[voice-rnnoise] pipeline=…`：管线身份、输入／输出时长、块数、RNNoise 帧数、不可用块数、分数均值和峰值、最后一块的 last／EMA，以及 `peak_ge_0_5_chunks`。
- `probability_mean` 按 RNNoise 帧数加权，`probability_peak` 是本次汇总的最大分数；不存在的分数为 `None`，不能解读为零分。
- `peak_ge_0_5_chunks` 是块级统计，不是逐 10ms 人声帧数。当前激活入口按块内 peak ≥ 0.5 判断，再用整块时长累计。
- `dsp_ms / dsp_max_ms`：本地音频处理函数耗时，包括 RNNoise、重采样、AGC；不是纯 RNNoise 推理耗时。
- `thread_queue_ms / thread_queue_max_ms`：从请求处理到本地工作线程开始执行的等待。
- `lock_wait_ms / lock_wait_max_ms`：输入管线自身串行锁的等待。
- `pipeline_ms / pipeline_max_ms`：本次 process 调用从等待锁到完成音频处理的总耗时，包括可能的处理器初始化和调度；不包括 Core 上游队列或网络传输。
- `input_interval_max_ms`：相邻 process 调用入口的最大时间间隔，不是麦克风物理采样间隔。
- `[voice-activation-evidence] scope=… microphone=… route=… epoch=…`：当前激活实例、输入代际和待机轮次，`input_ms / matched_ms` 为本汇总接收到的音频／认可为人声的时长。
- `candidate_voice_ms`：当前候选累计人声；`first_checkpoint_ms / reset_gap_ms` 为当前规则；`verification_requests` 是此次实际发出的验证请求数。
- `reset_speech_gap`：低人声判定持续到清零门槛；不等于真实静音。`reset_capture_gap`：下一块被认作人声时，与上一段认可人声的时间间隔达到门槛；不单独证明网络丢包。
- `reset_candidate_unavailable`：声纹请求对应音频已不在候选缓存内。`reset_state_change`：原有生命周期路径清理候选。
- `cleared_voice_samples / cleared_voice_max_samples`：清理的累计采样和最大单次量，包含正常状态转换，不能全部称为误拒绝。
- `capture_age_max_ms`：当前进程单调时钟与激活帧 captured_at 的最大差值；该字段受入口时间戳来源影响，不能称为端到端设备延迟。

诊断默认开启，仅包含内部随机身份、固定原因码、数量和耗时，不含 PCM、转写文本、关键词或声纹向量。汇总使用固定数量计数器，不保留逐帧历史，不创建额外任务。日志输出失败不阻止音频处理。

## 如何定位等待

1. 管线仍持续收到音频、DSP 很快，但 matched_ms 很少且 reset_speech_gap 增长：优先调查人声判定和累计规则。
2. thread_queue 或 lock_wait 较高：调查执行器负载或前序音频处理，而非先降低人声阈值。
3. 管线输入间隔较大：结合上游接收日志核对采集、网络与排队，不能仅据此判为 RNNoise 算得慢。
4. candidate_voice_ms 达标并发出 verification_requests 后仍未激活：继续检查声纹验证、状态通知和音频回放。

不同层的 scope 独立，需结合时间、麦克风／路由代际及已有会话状态日志关联；不能只按一条全局“最新分数”判断并发会话。

## 激活后短人声的修复边界

默认准入仍是普通路径：224ms 有效人声、480ms 滑窗、65% 占比、96ms 最大间断、640ms 候选预算，Silero 以 32ms 窗口给分。短候选实验已实现，默认不启用；配置、测试边界见 [实施说明](short-voice-admission.md)。

确定性概率序列复现：连续 192ms、每窗 0.95，随后 128ms 低分，仍以 speech_gap 拒绝；连续 224ms 高分则准入。3 个高分窗口、4 个 0.4 窗口、4 个高分窗口会在中间拒绝并另建候选。这里是规则边界复现，不是真实“喂”的录音结论。

以下边界由实验实现遵守，具体阈值仍未完成真实设备验证：

1. 保留普通路径，增加同一候选内的高质量短语音判定。以连续多窗口支持、候选长度、人声占比和低分分布共同约束，不允许单个高分脉冲放行；不能只凭激活状态跳过人声判断。
2. 区分起音、弱证据与明确低分。允许有限的词内弱证据过渡，但不能把它全部计成人声、无限累计或跨已拒绝候选拼接。现有 640ms 候选预算和采样归属约束保持。
3. 短语音结束时，在销毁候选前进行一次完整候选评估；结束尾部不应简单冲淡语音核心的占比。只凭 Silero 短高分仍可能放进碰撞声，必须用真实噪声验证。
4. 当前准入 evidence 中 RNNoise 字段尚未接入，不能直接宣称两模型联合判断。若需要联合证据，先按采样范围传递并冻结，禁止读取当前最新块；16kHz 无 RNNoise 的路径不能默认拒绝。
5. SmartTurn 原始活动门控最低 200ms，按 32ms 窗口实际需 224ms。短窗准入若先于它确认，必须有配套的、带身份的活动开始／暂停协调，否则可能上传了短词却不触发语义结束评估。保留原始 resumed 事件及当前端点权属，禁止伪造 final 或增加固定强切。
6. 准入通过前依旧无 ASR 上传、无回合准备、无打断；通过后保留连续音频和必要尾音。若采用“先送 ASR、等文本再决定”，就不再满足前述成本约束，必须另行讨论，不能混入本修复。
7. 文本“停／取消”的放行不能救回音频入口已丢掉的输入；真实“嗯”也应作为正样本。当前填充词规则允许已准入的回合，不能指望它兜住所有因放宽准入新增的误触发。

验收同时覆盖 16kHz／48kHz、provider／SmartTurn；对“喂、停、取消、嗯”、弱起音、词内低分和碰撞声分别检查实际上传内容、回合准备、取消、final、回复次数。需覆盖短窗接受后结束事件、迟到 final 和后继音频的归属。不能把合成高分测试通过写成真实短词已修复。
