# 网易云点歌插件

启用任务分析和用户插件通道、启动本插件后即可在聊天里点歌。明确点名或“挑一首”只播一曲。说“放点歌”时，角色根据当前聊天和记忆中的音乐偏好编排曲目；说“搜网易云的 dream pop 歌单”按原歌单顺序播放。精确匹配歌名和指定的歌手，没有匹配时不播放其他版本。

“把这首加到夜读”只收藏播放器确认的当前曲目，按歌曲 ID 去重；回执包含歌名、歌手和收藏后的总数。“把整张歌单保存为夜读”把当前整组曲目的网易云 ID、歌名、歌手保存在角色自己的本地收藏。“播放我保存的夜读”“下一首”“停止连播”可直接控制。自然结束或加载错误推进一次，关闭播放器终止连播。每首临播放时解析音源。

本地歌单使用保存时的完整名称。重播时未提供名称或找不到对应歌单，会列出当前角色已经保存的歌单，请选择其中一个；当前播放队列继续保留。名称本身含有“歌单”或“点歌台”时也会完整保留。明确要求使用点歌台或本地音频文件时，交给点歌台控制器。

## 路由补测

配置好 summary 模型后，在仓库根目录运行以下命令，可用真实模型检查本地歌单与点歌台的入口选择、参数和对话中的名称纠正。脚本只分析合成对话，不执行播放、收藏或桌面操作；模型调用会消耗 token。每次使用一个新的输出目录，结果包含模型、代码提交、提示词摘要和逐例判断。

```sh
uv run python scripts/probe_music_routing.py --pipeline --repeat 2 --output /tmp/neko-music-routing
```

这项补测固定提供网易云与点歌台两个插件，使用中文路由提示；不覆盖完整插件清单筛选、记忆服务、前端触发或音源播放验收。

## Cookie 配置

插件管理页内置 Hosted UI Cookie 配置面板，字段与内置网易云登录保持一致：`MUSIC_U` 必填，`NMTID` 可选。`MUSIC_U` 输入框既可粘贴单独值，也可粘贴包含 `MUSIC_U=...` 的完整 Cookie 字符串；完整字符串中的 `MUSIC_A`、`NMTID` 和 `__csrf` 也会一并保留，其余 Cookie 会被丢弃。

获取方式也直接写在插件面板中：登录 `music.163.com` 后打开浏览器开发者工具，在 Application（应用程序）→ Storage（存储）→ Cookies → `music.163.com` 中复制 `MUSIC_U` 和可选的 `NMTID` 的 Value。插件不会尝试读取浏览器 Cookie。

凭据只会加密保存在本插件的私有数据目录，面板只返回配置状态和保存字段数量，不会回显 Cookie。保存后无需重启，后续点歌会先将这些 Cookie 同步到插件创建的 pyncm 会话并尝试登录音源；凭据失效、请求异常或没有返回音源时，会自动降级到已验证的公开音源。清除后立即恢复匿名解析。

## 安全与隐私

- 搜索地址固定为网易云公开搜索接口，播放地址只能由验证过的十进制歌曲 ID 构造。
- 所有实际网络请求和最终播放地址均为 HTTPS；重定向的每一跳都会校验网易云域名。
- 插件不接受模型传入播放 URL，不读取 NEKO 全局凭据、浏览器或系统 Cookie，不继承环境代理；只使用用户在本插件 Hosted UI 中保存的网易云 Cookie 白名单字段。
- 插件日志、结果消息和错误中不输出完整音频 URL、签名查询串、Cookie 或响应体。
- 播放动作只发送给调用上下文中的 `lanlan_name`；缺少目标会话时直接拒绝，避免广播到其他角色。
