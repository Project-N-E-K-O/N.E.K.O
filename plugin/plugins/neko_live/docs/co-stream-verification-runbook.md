# 人猫同播验收 Runbook

> 用途：真机测试恢复时，按本文逐条验收人猫同播行为。
>
> 前提：本文覆盖的所有行为**只经过离线契约测试，未经真机验证**。本 runbook 存在的意义就是把它们验掉。
>
> 相关：问题台账 [`co-stream-correctness-issue-ledger-2026-07-26.md`](co-stream-correctness-issue-ledger-2026-07-26.md)、跟踪 issue [#2478](https://github.com/Project-N-E-K-O/N.E.K.O/issues/2478)。
>
> **当前产品边界（2026-07-30）**：
> [RFC #2491](https://github.com/Project-N-E-K-O/N.E.K.O/issues/2491)
> 已关闭，不再作为 Live 的生命周期/公共消息 ID/补偿队列方向。用户说话检测和
> 语音内部硬碰撞防护由 Core 自己处理，不向插件暴露 VAD、播放或 `audio_done`
> 状态。Live 只负责内容价值、上下文和表达引导，并继续使用既有主动/被动入口。
> 本文不得把插件收到请求、宿主接收请求或缺少重叠声误写成播放完成证明。

## 0. 开测前

| 项 | 要求 |
|---|---|
| 模式 | `live_mode = co_stream` |
| 输入 | 语音会话（`input_mode=audio`），主播实际开麦 |
| 日志 | 保留 `logs/plugin/N.E.K.O_Plugin_neko_live_*.log` 与 `logs/N.E.K.O_Main_*.log` |
| 观众 | 至少 2 名真实观众（多条判据要求 ≥2 名不同观众） |

**第一件要确认的事**：连接后插件日志里应出现 `live summary (connect): records=0 ...`。断开时应再出现一条 `live summary (disconnect): records=N ...`。

若整场 `records=0`，说明**没有任何弹幕进入插件**——这时不要继续验收后面的项，先查 ingest。这条正是过去无法区分「房间没人说话」和「事件被静默吞掉」的关键证据。

## 1. Core 语音安全边界（插件不可见）

插件不读取 VAD、播放或 floor 状态，也不据此删掉值得回应的内容。被筛中的内容
仍走既有主动/被动入口；用户或 AI 发声时的技术性碰撞由 Core 内部安全机制处理。
本节只验证最终听感和“同一输入不重复生成”，不为插件新增闸门、`brief_text`、
播放回流或公共生命周期。

| # | 操作 | 期望 | 证据 |
|---|---|---|---|
| 1.1 | 主播持续说话 30 秒，其间有主动弹幕 cue | 猫猫不与主播重叠发声；过期 cue 静默丢弃 | 宿主脱敏闸门原因 + 无生成证据 |
| 1.2 | 主播说完，队列中有未过期 cue | 猫猫可在开门后说正常完整短句，不要求 `brief_text` | 闸门解除后按 priority/FIFO 释放 |
| 1.3 | 主播停 10 秒以上 | 新的相关主动 cue 可正常发言 | 不存在额外 quiet window |
| 1.4 | 主播换气时有普通弹幕待回 | 只要宿主判定已停止发声且 cue 未过期，就可正常释放 | 不宣称 pause/brief 能力 |

**1.4 是关键**：窄闸门防止音频硬重叠，但不把所有主动接梗视为错误。若产品
未来需要真正的换气口短形式，应另开实验，不能把它塞回 #2491。

## 2. 打断与过期（不含补偿）

`compensate_once`、`delivery_key`、`compensation_*` 和播放完成回传均不在
#2491 范围。以下只验收“不复活旧 cue、不重复认领”，不得期待补说感谢。

| # | 场景 | 操作 | 期望 |
|---|---|---|---|
| 2.1 | A｜普通弹幕仍在排队时主播继续说话 | cue 等待至开门或 TTL 到期 | 过期后不得生成或补播 |
| 2.2 | B｜高价值礼物未生成前被占用话权 | 主播说完前保持等待 | 45 秒内开门可正常释放；超时静默丢弃 |
| 2.3 | C｜direct inject 与 hot-swap 同时竞争 | 制造并发认领窗口 | 同一队列项只能一个路径成功 |
| 2.4 | E｜误触 VAD / 播放状态抖动 | 制造短噪声或快速开关门 | 不得重复生成同一队列项 |
| 2.5 | F｜下播 | 队列有待播内容时直接下播 | 新会话**不得**播出上一场的感谢或弹幕 |

**2.3 / 2.4 的验收底线**：正确性来自宿主队列 ownership / 原子认领，不来自
插件 `delivery_key` 或供应商事件 ID。

## 3. 被动房间上下文

按维护者 owner decision，被动上下文**等下一次自然热切换**投递，不做中途推送。

| # | 检查 | 期望 |
|---|---|---|
| 3.1 | 观察热切换实际间隔 | 记录下来。历史实测 2–3 分钟 |
| 3.2 | 热切换后猫猫是否知道近期弹幕 | 应能答出「最新/上一条/上上条」，且固定按「位置｜昵称｜弹幕」配对，不得把昵称当正文或把正文当昵称 |
| 3.3 | 猫猫是否说出「N 秒前」这类时间描述 | **不应该**——快照已改为位置标签 |
| 3.4 | 猫猫是否声称「已经感谢过了」 | **不应该**——插件无权断言投送结果 |

3.3 / 3.4 若出现，说明快照的时间无关性被破坏。

## 4. 房间共识与梗（独播为主，同播顺带观察）

| 字段 | 位置 | 怎么读 |
|---|---|---|
| `room_verdict_delivery_unconfirmed_count` | `live_events.status()` | choice 问题已交给宿主，但因没有播放确认而安全压住的次数 |
| `room_verdict_ballots_opened` | 同上 | 有播放确认后真正开启的投票次数；当前宿主未回流确认时应为 0 |
| `room_verdict_announced_count` | 同上 | 其中几次真的宣布了结果 |
| `room_verdict_last_reason` | 同上 | 当前常见 `delivery_unconfirmed`；未来开票后才会出现 `too_few_voters` / `expired` |
| `ritual_callback_offers` / `_uses` | 同上 | 梗是否形成并被回收 |
| `ritual_last_skip_reason` | 同上 | 一直是 `unconfirmed` 表示还没形成梗 |

**判读要点**：当前若 `delivery_unconfirmed_count` 增长而
`ballots_opened=0`，表示插件正确拒绝把“宿主接收”冒充“观众听见”，不是投票故障。
只有未来接入播放确认后，才能用 opened / announced 的差值评价提问效果。

## 5. 不要用这份 runbook 做的判断

- **不要**因为测试全绿就认为效果好。本文验的是行为正确性，不是直播好不好看。
- **不要**把 `pushed` 当成「猫猫已经说了」。它只代表请求交给了宿主。
- **不要**只测一个 Provider。台账 CSL-010 明确要求覆盖 OpenAI 风格服务端 VAD、无服务端 VAD、Gemini Live，以及网页与 Electron 两种播放端。

## 6. 结果回填

测完请把以下内容回填到 issue [#2478](https://github.com/Project-N-E-K-O/N.E.K.O/issues/2478)：

1. 每项的通过 / 失败；
2. 实测热切换间隔；
3. 短形式感谢的听感评价（自然 / 突兀 / 像抢话）；
4. 是否出现重复感谢，若有只附 `provider_event_id_hash`；不得附加或记录原始 `provider_event_id`；
5. `live summary` 汇总行的原文（已脱敏，可直接贴）。
